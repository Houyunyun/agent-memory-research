## 详细解读

### 核心总结

这篇论文提出了 **ReasoningBank**，一个面向LLM智能体（Agent）的新型记忆框架。其核心思想是：当智能体在持续执行任务流时，不应该把每个任务当作孤立事件处理，而应该从过去的成功和失败经验中提炼出可泛化的推理策略，存储为结构化的记忆条目，供未来任务检索和复用。与以往只存储原始轨迹或仅从成功案例中提取工作流的方法不同，ReasoningBank 同时利用成功和失败经验，通过LLM自我判断（无需真实标签）来蒸馏高层次的推理模式。在此基础上，论文进一步提出了**记忆感知的测试时缩放（MaTTS）**，通过在每个任务上分配更多计算资源来生成多样化的探索经验，利用对比信号合成更高质量的记忆，形成记忆与测试时缩放之间的正反馈循环。在WebArena、Mind2Web和SWE-Bench-Verified等基准上，ReasoningBank在有效性（最高20%的相对提升）和效率（最多减少16%的交互步数）上均优于现有方法。

### 1. 研究动机与问题背景

#### 1.1 当前LLM Agent的核心局限

随着LLM Agent越来越多地被部署在持续运行的角色中（如网页浏览助手、软件工程助手），它们会不断遇到新任务。然而，当前的Agent存在一个关键缺陷：**它们无法从积累的交互历史中学习**。每个新任务都被孤立地处理，导致三个问题：

1. **重复过去的错误**：曾经犯过的错误会再次出现
2. **丢弃有价值的洞察**：从相关问题中获得的经验被浪费
3. **缺乏自我进化能力**：Agent系统无法随时间变得更强

#### 1.2 现有记忆方法的不足

已有的Agent记忆方法主要分两类，但都有根本性缺陷：

- **轨迹记忆（Trajectory Memory）**：如Synapse，直接存储过去的原始交互轨迹。问题是轨迹太长、太嘈杂，包含大量低层级的执行细节（如具体的点击操作ID），难以迁移到新任务。
- **工作流记忆（Workflow Memory）**：如AWM，从成功轨迹中抽象出可复用的操作流程。问题是它只关注成功经验，**完全忽略了失败经验中蕴含的宝贵教训**，而且抽象出的工作流仍然偏向于执行层面而非推理层面。  
  如Figure 1所示，轨迹记忆存储的是具体的点击操作序列，工作流记忆存储的是模板化的操作流程，而ReasoningBank存储的是高层次的推理策略（如"导航策略：检测分页模式、检查所有相关订单、使用回退机制"等）。

### 2. 问题形式化

#### 2.1 Agent配置

Agent的策略定义为 $\pi_{\mathcal{L}}(\cdot|\mathcal{M}, \mathcal{A})$，其中 $\mathcal{L}$ 是骨干LLM，$\mathcal{M}$ 是记忆模块（即ReasoningBank，初始为空），$\mathcal{A}$ 是动作空间。环境的转移函数为 $\mathcal{T}(s_{t+1}|s_t, a_t)$。对于每个任务，Agent生成一个轨迹 $(o_{0:t}, a_{0:t})$，其中 $o_t$ 是当前状态 $s_t$ 的观测。Agent需要通过以下方式生成下一步动作：  

$\displaystyle a_{t+1} = \pi_{\mathcal{L}}(o_{0:t}, a_{0:t}; \mathcal{M}, \mathcal{A})$

  
在实现中，记忆模块 $\mathcal{M}$ 将相关记忆作为额外的系统指令注入 $\pi_{\mathcal{L}}$。  
对于网页浏览任务，$\mathcal{A}$ 是网页导航操作集合，观测 $o_t$ 是网页的文本可访问性树（accessibility tree）；对于软件工程任务，$\mathcal{A}$ 是bash命令集合，观测是代码片段。

#### 2.2 测试时学习范式

论文采用**测试时学习（Test-Time Learning）**范式：任务查询序列 $Q = \{q_1, q_2, ..., q_N\}$ 以流式方式到达，每个查询按顺序揭示并必须依次完成，**测试时没有任何真实标签可用**。Agent必须仅依靠自己过去的轨迹和自我验证来持续进化。  
这个设定提出了两个核心挑战：

1. 如何从过去的轨迹中提取和保存有用的记忆
2. 如何有效利用这些记忆来指导未来的查询

### 3. ReasoningBank 方法详解

ReasoningBank的核心流程如Figure 2所示，包含三个步骤形成闭环：**记忆检索 → 记忆提取 → 记忆整合**。

#### 3.1 记忆模式（Memory Schema）

每个记忆条目是一个结构化的知识单元，包含三个组件：

1. **标题（Title）**：简洁地总结核心策略或推理模式，如"优先使用用户账户区域获取个人数据"
2. **描述（Description）**：一句话摘要
3. **内容（Content）**：蒸馏出的推理步骤、决策理由或操作洞察，如"系统地查找并点击相关链接，检测分页模式并检查所有相关项目..."  
   这种设计使得记忆条目既**人类可解读**又**机器可用**，抽象掉了低层级的执行细节，保留了可迁移的推理模式。

#### 3.2 记忆检索（Memory Retrieval）

当新任务 $q_i$ 到来时：

1. 使用embedding模型（gemini-embedding-001）对查询进行编码
2. 在记忆池中使用余弦距离进行相似性搜索
3. 检索与当前查询最相关的top-$k$个经验对应的记忆条目（默认$k=1$）
4. 将检索到的记忆条目拼接到Agent的系统提示中  
   注入的指令告诉Agent："以下是我从过去与环境交互中积累的一些记忆条目，可能对解决当前任务有帮助。你可以在觉得相关时使用它们。在每一步中，请先明确讨论是否要使用每个记忆条目，然后再采取行动。"

#### 3.3 记忆提取（Memory Extraction）

当任务完成后，进行记忆提取：  
**第一步：获取代理正确性信号。** 由于测试时没有真实标签，论文采用**LLM-as-a-Judge**方法：用同一个骨干LLM作为评判者，给定查询和轨迹，判断任务是"成功"还是"失败"。评判者不需要任何真实标签参考。  
**第二步：根据信号应用不同的提取策略。**

- **成功轨迹**：提示LLM分析"为什么这个轨迹成功了"，然后总结出可迁移的推理策略（如Figure 9左侧所示）
- **失败轨迹**：提示LLM"首先反思并思考为什么轨迹失败了"，然后总结出教训和预防策略（如Figure 9右侧所示）  
  每个轨迹最多提取3个记忆条目，要求不重复、不提及具体网站或查询字符串，而是聚焦于可泛化的洞察。

#### 3.4 记忆整合（Memory Consolidation）

新提取的记忆条目通过简单的追加操作加入记忆池。论文有意采用最简单的整合策略（不做修剪、合并或遗忘），以突出ReasoningBank记忆内容本身的贡献。

#### 3.5 与现有方法的关键区别

| 特性 | 轨迹记忆(Synapse) | 工作流记忆(AWM) | ReasoningBank |
| --- | --- | --- | --- |
| 存储内容 | 原始轨迹 | 抽象操作流程 | 高层推理策略 |
| 利用失败经验 | ✗ | ✗ | ✓ |
| 抽象层次 | 低（具体操作） | 中（操作模板） | 高（推理原则） |
| 可迁移性 | 低 | 中 | 高 |

### 4. MaTTS：记忆感知的测试时缩放

#### 4.1 动机

测试时缩放（Test-Time Scaling, TTS）是近年来提升LLM性能的有效策略，通过在推理时分配更多计算资源来提升表现。ReasoningBank作为一个强大的经验学习器，可以将"更多经验"转化为"更大改进"。  
一个朴素的组合方式（Vanilla TTS，如Figure 3(a)）是：对每个任务生成多条轨迹，每条轨迹独立地转化为记忆条目。但这种方式是次优的，因为它**没有利用同一问题上多次探索之间的对比信号**。

#### 4.2 并行缩放（Parallel Scaling）

如Figure 3(b)所示：

1. 在记忆指导下，对同一查询生成 $k$ 条轨迹
2. 通过**自对比（self-contrast）**跨不同轨迹进行比较
3. 识别一致的推理模式，过滤掉虚假的解决方案
4. 从多次试验中策划出更可靠的记忆  
   具体的提示如Figure 11左侧所示，要求模型："比较和对比这些轨迹，识别最有用和可泛化的策略...思考为什么有些轨迹成功而其他失败？"  
   对于最终答案的选择，使用Best-of-N（BoN）策略：用LLM从 $N$ 条轨迹中选择最佳答案（Figure 12展示了详细的评估标准，包括目标进展、效率、循环检测、错误严重性等）。

#### 4.3 顺序缩放（Sequential Scaling）

如Figure 3(c)所示：

1. 完成初始轨迹后，遵循**自精炼（self-refinement）**原则迭代优化
2. 自精炼过程中产生的中间笔记也作为记忆的有价值信号
3. 这些笔记捕获了推理尝试、纠正和洞察  
   具体的提示如Figure 11右侧所示，第一次检查要求"仔细重新检查之前的轨迹，特别注意是否使用了正确的页面元素"，后续检查则简单地要求"再检查一次"。

#### 4.4 记忆与缩放的协同效应

MaTTS建立了记忆与测试时缩放之间的**双向正反馈循环**：

- **高质量记忆 → 更有效的缩放**：好的记忆引导缩放探索朝向更有前景的路径
- **更多探索 → 更好的记忆**：丰富的经验提供了更多对比信号来锻造更强的记忆  
  这个正反馈循环将**记忆驱动的经验缩放**定位为Agent的一个新的缩放维度。

### 5. 实验设置

#### 5.1 数据集

- **WebArena**：通用网页导航，跨多个领域（购物187题、管理182题、Gitlab 180题、Reddit 106题、跨站29题，共684题）
- **Mind2Web**：测试Agent在多样操作和环境上的泛化能力（跨任务252题、跨网站177题、跨领域912题，共1341题）
- **SWE-Bench-Verified**：仓库级别的软件问题解决（500个人工验证的测试实例）

#### 5.2 基线方法

- **No Memory**：无记忆的骨干LLM Agent
- **Synapse**：基于轨迹的记忆，将过去轨迹作为上下文示例
- **AWM**：基于工作流的记忆，从轨迹中抽象出可复用的工作流

#### 5.3 骨干模型

- Gemini-2.5-Flash
- Gemini-2.5-Pro
- Claude-3.7-Sonnet  
  所有Agent使用ReAct风格，在BrowserGym环境中执行网页浏览任务。

#### 5.4 评估指标

- **有效性**：成功率（SR），$SR = \frac{1}{N}\sum_{i=1}^{N}\text{isSuccess}(q_i)$
- **效率**：平均步数（AS），$AS = \frac{1}{N}\sum_{i=1}^{N}\text{Steps}(q_i)$
- Mind2Web额外使用元素准确率（EA）、动作F1（AF1）、步骤成功率（SSR）和任务级成功率（SR）

### 6. 实验结果

#### 6.1 ReasoningBank的主要结果（Table 1, 2, 3）

**WebArena（Table 1）**：ReasoningBank在所有骨干LLM上一致优于基线：

- Gemini-2.5-flash：整体SR从40.5（No Memory）提升到48.8（+8.3）
- Gemini-2.5-pro：从46.7提升到53.9（+7.2）
- Claude-3.7-sonnet：从41.7提升到46.3（+4.6）  
  同时，平均步数也显著降低，如Gemini-2.5-flash从9.7步降到8.3步。

**跨域泛化能力**：在WebArena的Multi子集（需要跨多个网站迁移记忆）上，ReasoningBank平均SR比最强基线高+4.6。而AWM在这个设置下甚至性能下降（如Gemini-2.5-flash从10.3降到3.4）。在Mind2Web的跨领域设置中，ReasoningBank的优势尤为明显。  
**SWE-Bench-Verified（Table 2）**：ReasoningBank同样有效，Gemini-2.5-pro的解决率从54.0提升到57.4，平均步数从21.1降到19.8。

#### 6.2 MaTTS的结果（Figure 4）

在WebArena-Shopping子集上使用Gemini-2.5-flash进行详细分析：  
**并行缩放**：随着缩放因子 $k$ 增加，MaTTS的SR从49.7（$k=1$）稳步增长到55.1（$k=5$）。而没有记忆的MaTTS w/o memory在39.0到42.2之间波动，改进不稳定。  
**顺序缩放**：MaTTS的SR从49.7增长到54.5（$k=5$）。  
**MaTTS vs. Vanilla TTS**：在 $k=5$ 时，MaTTS并行缩放达到55.1，而Vanilla TTS只有52.4；顺序缩放分别为54.5 vs. 51.9。这说明记忆感知的协调和聚合至关重要。  
**并行vs.顺序的比较**：对于ReasoningBank，顺序缩放在小 $k$ 时有短期优势（因为自精炼能快速纠错），但在大 $k$ 时并行缩放占优（因为并行提供更多样化的rollout供对比学习）。

#### 6.3 记忆与测试时缩放的协同效应（Figure 5）

这是论文的一个核心发现，通过WebArena-Shopping子集、$k=5$的并行缩放快照来展示：  
**更好的记忆 → 更强的缩放效果**（看BoN指标）：

- No Memory：BoN从39.0只提升到42.2（+3.2）
- Synapse：提升到44.4
- AWM：提升到47.6
- ReasoningBank：从49.7提升到55.1（+5.4）

**缩放 → 更好的记忆策划**（看Pass@1指标，衡量记忆策划后轨迹的平均质量）：

- Synapse：从40.6微升到41.2
- AWM：从44.4微升到45.5
- ReasoningBank：从49.7大幅提升到53.0  
  这说明只有配合好的记忆机制，缩放才能贡献到更有效记忆的策划，形成良性循环。

### 7. 深入分析

#### 7.1 涌现行为（Figure 6）

论文发现ReasoningBank中的策略不是静态的，而是随时间**涌现式进化**，类似强化学习的学习动态：

1. **初始阶段**：执行导向的程序性策略（如"主动查找并点击'下一页'链接"）
2. **中期**：原子级自我反思（如"首先重新检查元素的当前标识符"）
3. **后期**：进化的自适应检查（如"在扫描前，总是利用可用的搜索或过滤功能，确保完整性"）
4. **成熟阶段**：泛化的复杂策略（如"定期将当前视图与任务需求交叉参照以防止错误...如果当前数据不符合预期，重新评估可用选项"）

#### 7.2 失败经验的价值（Figure 7）

在WebArena-Shopping上的消融实验显示：

- Synapse：仅成功→40.6，加入失败→41.7（微升）
- AWM：仅成功→44.4，加入失败→42.2（**下降**，因为AWM不具备从失败中学习的能力）
- ReasoningBank：仅成功→46.5，加入失败→49.7（**显著提升**）  
  这证明ReasoningBank能将失败转化为建设性信号而非噪声。

#### 7.3 对LLM-as-a-Judge的鲁棒性（Figure 8）

LLM-as-a-Judge的基线准确率为72.7%。论文模拟了不同准确率水平（50%-100%），发现在70%-90%的合理范围内，ReasoningBank的性能差异很小（SR在47.6-49.7之间），说明框架对验证噪声具有鲁棒性。

#### 7.4 效率增益的来源（Table 4）

将步数减少分解到成功和失败案例：

- 成功案例的步数减少更显著（Shopping从6.8降到4.7，减少2.1步，即26.9%）
- 失败案例的步数减少较小（Shopping从8.7降到7.3，减少1.4步）  
  这说明ReasoningBank主要通过**加强Agent沿有效推理路径前进的能力**来减少交互，而非简单地截断失败轨迹。

#### 7.5 检索经验数量的影响（Figure 13）

消融实验显示：检索1个经验时效果最好（SR=49.7），随着数量增加性能逐渐下降（2个→46.0，3个→45.5，4个→44.4）。这说明记忆的**相关性和质量**比数量更重要，过多经验可能引入冲突或噪声。

#### 7.6 推理成本分析（Table 5）

与No Memory相比，ReasoningBank的总token消耗仅增加约4.3%（53054.5 vs. 50847.4），但性能提升了20.5%。而Synapse和AWM的token消耗增加更多（58514.7和59372.8），性能提升却更少。

#### 7.7 小模型上的效果（Table 6）

在开源的Gemma-3-12B-Instruct上，ReasoningBank同样有效：SR从17.1%（No Memory）提升到24.1%，平均步数从13.7降到11.8，优于Synapse（16.0%）和AWM（21.4%）。

#### 7.8 Pass@k分析（Figure 14）

Pass@$k$分析揭示了两个效应：

1. Vanilla TTS已经使测试时学习类似于RL训练，通过引导探索来提高样本效率
2. MaTTS进一步推动性能，在$k=5$时Pass@5达到62.1，而MaTTS w/o memory仅52.4

### 8. 案例研究

论文提供了三个具体案例：  
**有效性案例（Figure 15）**：查询"我第一次购买的日期"。无记忆的Agent只查看"最近订单"表，错误地输出最近的购买日期。ReasoningBank的Agent回忆起过去的推理提示，导航到完整的订单历史并正确找到最早的订单。  
**效率案例（Figure 16）**：购买"男鞋"类别中评分最高的产品。无记忆的Agent花了29步，其中8步浪费在低效的导航搜索上。ReasoningBank的Agent利用存储的分类过滤推理，仅用10步完成任务。  
**从失败中学习的案例（Figure 17）**：搜索Sony蓝牙耳机时，原始轨迹因搜索查询不精确导致返回太多无关项目而失败。ReasoningBank能够诊断失败原因，提炼出"搜索查询优化"、"调整每页显示数量"、"使用可用过滤器"等策略。

### 9. 总结与局限性

**主要贡献**：

1. 提出ReasoningBank，从成功和失败经验中蒸馏可泛化的推理策略
2. 提出MaTTS，建立记忆与测试时缩放的双向协同
3. 在三个基准上验证了方法的有效性、效率和泛化能力

**局限性**：

- 聚焦于记忆内容，未与情景记忆、层次记忆等架构进行广泛比较
- 有意采用简单的检索和整合策略，更复杂的策略可能进一步提升性能
- 依赖LLM-as-a-Judge获取正确性信号，可能在模糊任务上引入噪声

## 原文摘要

With the growing adoption of large language model agents in persistent real-world roles, they naturally encounter continuous streams of tasks. A key limitation, however, is their failure to learn from the accumulated interaction history, forcing them to discard valuable insights and repeat past errors. We propose ReasoningBank, a novel memory framework that distills generalizable reasoning strategies from an agent's self-judged successful and failed experiences. At test time, an agent retrieves relevant memories from ReasoningBank to inform its interaction and then integrates new learnings back, enabling it to become more capable over time. Building on this powerful experience learner, we further introduce memory-aware test-time scaling (MaTTS), which accelerates and diversifies this learning process by scaling up the agent's interaction experience. By allocating more compute to each task, the agent generates abundant, diverse experiences that provide rich contrastive signals for synthesizing higher-quality memory. The better memory in turn guides more effective scaling, establishing a powerful synergy between memory and test-time scaling. Across web browsing and software engineering benchmarks, ReasoningBank consistently outperforms existing memory mechanisms that store raw trajectories or only successful task routines, improving both effectiveness and efficiency; MaTTS further amplifies these gains. These findings establish memory-driven experience scaling as a new scaling dimension, enabling agents to self-evolve with emergent behaviors naturally arise.
