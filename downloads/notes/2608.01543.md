# V-Mem: Modality-Routed Retrieval for Long-Term Multimodal Agentic Memory

Kang, Dingyi, Jiang, Dongming, Li, Yi, Li, Guanpeng, Li, Bingzhe · 2026

[论文原文](https://arxiv.org/abs/2608.01543)

## 核心机制

按查询与证据模态路由检索，并构造更接近目标的检索锚点

## 适用范围与局限

主要证据定位问题，不等于学习视觉技能

## 详细解读

### 核心总结

V-Mem是一个面向多模态长期对话记忆的智能体记忆系统。它针对现有基于相似度搜索的记忆检索方法在多模态场景下的两个根本性失败——**模态鸿沟**（跨模态查询时，查询总是更接近同模态内容而非真正的证据）和**相似度-相关性鸿沟**（最相似的内容往往不是最相关的证据，尤其当查询同时携带文本和图像时）——提出了一种**按模态路由检索**的方案。V-Mem根据查询本身推断出（查询模态，目标证据模态）的组合，据此决定激活哪些检索通道、用什么作为搜索锚点、返回什么内容。它通过"共享轮次匹配"跨越模态鸿沟（在同模态内匹配后返回同一轮次中另一模态的内容），通过LLM生成的搜索锚点（假设性描述或富化锚点）弥合相似度-相关性鸿沟。在Mem-Gallery和LoCoMo两个基准上，V-Mem显著超越现有基线，尤其在视觉相关问题上优势最为突出，且记忆构建阶段零LLM调用、仅需数秒完成。

### 一、研究动机与问题背景

#### 1.1 多模态对话记忆的需求

当前LLM智能体越来越多地处理多模态交互：用户在对话中交替发送文本、图片、语音消息，并且后续的提问可能针对其中任何一种模态。例如，用户拍了一张植物的照片发给助手，过了几天又问"那是什么品种？"；或者用户发了一张Google总部的照片并问"我们之前讨论过这个组织的什么内容？"  
然而，LLM的上下文窗口有限，早期的对话内容会被挤出窗口而无法被后续查询访问。即使扩大窗口，也存在"lost-in-the-middle"和"context decay"等问题——模型对长输入中远离查询位置的证据关注度很低。

#### 1.2 记忆增强生成（MAG）

为解决上述问题，**记忆增强生成（Memory-Augmented Generation, MAG）**将交互历史写入外部存储，在每次新查询时检索相关片段并注入生成过程。形式化地：  

$\displaystyle a_t = \text{LLM}\big(q_t,\, \mathcal{R}(q_t, \mathcal{M}_t)\big), \quad \mathcal{M}_{t+1} = \mathcal{U}(\mathcal{M}_t, x_t)$

  
其中$\mathcal{R}$从记忆$\mathcal{M}_t$中检索与查询$q_t$相关的证据，$\mathcal{U}$将新内容$x_t$写入记忆。  
几乎所有现有系统将$\mathcal{R}$实现为**相似度搜索**：  

$\displaystyle \mathcal{R}(q, \mathcal{M}) = \underset{u \in \mathcal{M}}{\text{top-}k}\; s\big(e(q),\, e(u)\big)$

  
其中$e(\cdot)$将查询或记忆项映射到表示空间，$s(\cdot, \cdot)$计算相似度，查询$q$本身作为搜索锚点。这种方法成功的前提是：**相关证据$u^\star$在索引空间中与锚点距离近，从而排在top-$k$之内**。

#### 1.3 多模态场景下相似度搜索的两个失败

论文指出，在多模态场景下，上述前提被两个"鸿沟"打破：  
**（1）模态鸿沟（Modality Gap）**  
当查询和证据处于不同模态时（如文本查询、图像证据），即使在CLIP、SigLIP等经过对比学习训练的联合嵌入空间中，查询仍然更接近同模态的记忆内容，而非真正的跨模态证据。这导致相似度搜索总是把同模态内容排在跨模态证据之前。  
**（2）相似度-相关性鸿沟（Similarity-Relevance Gap）**  
记忆中与查询最相似的内容，往往不是真正回答查询的相关证据。这在多模态场景中尤为严重：当查询同时携带文本和图像，而证据既不像文本部分也不像图像部分时，单独搜索任一模态都找不到它。  
论文用Figure 1中的三个案例具体说明：

- **Case 1**：用户附上一张植物照片问品种。相似度搜索找到了正确的图片，但证据实际上是图片旁边的文字对话（提到了品种名），而图片嵌入本身不包含品种信息。
- **Case 2**：用户问"对话中哪张图片是关于友谊的？"查询文本中只有"friends"这个词，而正确图片的描述中没有这个词，导致文本搜索找不到目标图片。
- **Case 3**：用户附上Google总部的照片问"我们讨论过这个组织的什么？"证据是"Google正在给学生免费提供一年Gemini Pro订阅"。这条证据既不像照片（一栋建筑），也不像查询文本（只说了"organization"没提"Google"），所以单独搜索任一模态都失败。

### 二、V-Mem系统设计

#### 2.1 整体架构概览

V-Mem的核心思想是**按模态路由检索**：根据查询本身推断出（查询模态，目标证据模态）的组合，然后针对不同组合采用不同的检索策略。  
系统分为三个阶段：

1. **记忆构建**：保持对话原样，组织成"轮次"（rounds），不做任何LLM摘要或提取
2. **路由检索**：识别模态组合，激活对应的检索通道，使用合适的搜索锚点
3. **按轮次重排与上下文组装**：按轮次评分，融合多通道结果，返回top轮次及其邻居

#### 2.2 轮次、单元和通道（Rounds, Units, Lanes）

**轮次（Round）**：V-Mem将对话历史表示为轮次序列$\mathcal{C} = (r_1, \ldots, r_T)$，每个轮次$r_t$是一次用户-助手交换。  
**记忆单元（Memory Unit）**：每个轮次中的每段文本和每张图片都是一个独立的记忆单元$u$，模态$m(u) \in \{\text{txt}, \text{img}\}$。同一轮次中的单元共同出现在一次交换中，因此很可能彼此相关——这是后续"共享轮次匹配"的基础。  
**通道（Lane）**：所有单元按模态分组：

- **文本通道**：存放文本单元
- **图像通道**：存放图像单元

**索引**：

- 文本索引包含两种互补信号：密集嵌入（来自编码器$\phi$，语义层面）和稀疏BM25索引（词汇层面），覆盖文本单元的内容和图像单元的描述文本（caption）
- 图像索引包含每张原始图像的视觉嵌入$\psi$  
  通过分离通道，V-Mem可以只搜索查询需要的通道，避免无关模态的干扰。

#### 2.3 路由检索（Routed Retrieval）

路由检索将公式(2)的简单相似度搜索推广为：  

$\displaystyle \mathcal{R}_{\text{V-Mem}}(q, \mathcal{M}) = \Pi_c\bigg(\underset{r}{\text{top-}k}\; \text{Fuse}_{\ell \in L_c}\; S_\ell\big(a_{c,\ell}(q),\, \mathcal{U}_{c,\ell}\big)\bigg)$

  
其中：

- $c = \text{Route}(q)$是查询的"案例"（case）
- $L_c$是该案例激活的通道集合
- $\mathcal{U}_{c,\ell}$是该案例在通道$\ell$中搜索的单元子集
- $a_{c,\ell}(q)$是搜索锚点（原始查询或LLM生成的锚点）
- $S_\ell$是通道内的评分函数
- $\text{Fuse}$将多通道排名融合
- $\Pi_c$将top-$k$轮次组装成返回给LLM的内容

##### 路由规则

V-Mem通过关键词规则从查询本身推断两个模态，**无需LLM调用**：

- **查询模态**：查询是否附带图片→纯文本 或 图像+文本
- **目标模态**：查询是否在问"哪张图片/照片"或"有多少张图片"→图像目标；否则→文本目标  
  这产生四种案例（2×2矩阵）：

  |  | 目标=文本 | 目标=图像 |
  | --- | --- | --- |
  | 查询=文本 | text→text | text→image |
  | 查询=图像+文本 | image+text→text | image+text→image |
- **同模态检索**（text→text, image+text→image）：直接在共享模态的通道内搜索
- **跨模态检索**（text→image, image+text→text）：同时面临模态鸿沟和相似度-相关性鸿沟，需要特殊处理

##### 机制一：共享轮次匹配（Matching Through Shared Rounds）

核心思想：**不做跨模态比较**。在查询自身模态的通道内找到最匹配的单元，然后返回该单元所在轮次中目标模态的内容。因为同一轮次的内容共同出现，所以很可能相关。  
具体操作：

- **Text→image**：在文本通道中搜索，但**限制在包含图片的轮次**的文本中搜索（因为不含图片的轮次无法返回图像）。找到匹配后，返回该轮次中的图片。
- **Image+text→text**：在图像通道中搜索，将查询图片与存储图片做视觉嵌入相似度比较。找到匹配后，返回该轮次中的文本。  
  这样，每次匹配都在同一模态内进行，轮次（而非共享嵌入空间）充当了连接两种模态的桥梁。

##### 机制二：LLM生成的搜索锚点（Searching with an LLM-Generated Anchor）

在跨模态场景中，原始查询往往不像目标证据，直接用它搜索会错过证据。V-Mem让LLM生成一个更接近目标证据的搜索锚点：

- **Text→image（假设性描述，hypo-caption）**：查询是纯文本，要找一张图片。V-Mem让LLM根据查询生成一个"目标图片可能具有的描述"，然后用这个假设性描述去匹配存储图片的描述。例如Case 2中，查询问"关于友谊的图片"，LLM生成"朋友们围坐在篝火旁烤棉花糖"的描述，这个描述与正确图片的caption更匹配。
  - 特殊情况：如果查询是在数图片（如"有多少张..."），则不生成hypo-caption，因为没有单一目标图片可以描述。
- **Image+text→text（富化锚点，enriched anchor）**：查询同时携带文本和图片，目标是文本证据。V-Mem让视觉LLM从查询图片中提取相关关键词，附加到查询文本上，形成富化锚点。例如Case 3中，从Tesla照片中提取"Tesla"等关键词，附加到"我们讨论过这个组织的什么"上，使得文本搜索能找到提到"Google"和"Tesla"的对话轮次。

##### 评分与融合

每个激活的通道可能有多种评分信号。文本通道有密集嵌入和BM25两种信号，图像通道有视觉嵌入（当查询带图时）或描述文本的密集/稀疏信号（当查询不带图时）。  
对于信号$j$，单元$u$的得分为：  

$\displaystyle s_j(u) = \cos\big(e_j(a_{c,\ell}),\, e_j(u)\big)$

  
（密集和视觉信号用余弦相似度，稀疏信号用BM25）  
评分按单元计算，但检索按轮次排名。每个轮次取其单元中的最高分：  

$\displaystyle S_j(r) = \max_{u \in r_\ell} s_j(u)$

  
由于不同信号的分数尺度不同（余弦有界 vs BM25无界），V-Mem使用**倒数排名融合（Reciprocal Rank Fusion, RRF）**：  

$\displaystyle \text{score}(r) = \sum_{j \in J_c} \frac{1}{\kappa + \text{rank}_j(r)}$

  
其中$\kappa$是平滑常数（取60），$\text{rank}_j(r)$是轮次$r$在信号$j$下的排名位置。

##### 上下文组装

对于大多数查询，V-Mem将每个top轮次与其前后各1个相邻轮次包装成一个时间有序的片段返回。相邻轮次往往延续同一话题，可以补充证据（类似于图记忆中实体间的链接）。  
对于**聚合类问题**（如"我们讨论过多少个不同的博物馆？"），证据分散在许多远距离的轮次中。此时V-Mem不添加邻居，而是返回更多轮次（从12个增加到30个）。聚合问题通过关键词规则识别，无需LLM调用。

#### 2.4 记忆构建

V-Mem的记忆构建**完全不调用LLM**，仅使用本地编码器：

- 保持对话原样，不做摘要、笔记或图提取
- 每个轮次生成一个文本单元/段和一个图像单元/张
- 每个单元被索引并存入对应通道
- 音频被转录为文本，作为文本单元存储  
  这种构建方式是**增量式**的：新轮次的单元直接追加，不影响已有记忆。构建在数秒内完成，token消耗为零。

### 三、实验

#### 3.1 实验设置

**基准数据集**：

- **Mem-Gallery**：多模态基准，20个多会话对话，1,711个问题，9个类别。其中3个是视觉类（VS视觉搜索、VR视觉推理、TTL测试时学习——查询提供新图片），6个是文本类（FR事实检索、TR时间推理、MR多实体推理、KR知识解析、CD冲突检测、AR拒答）。
- **LoCoMo**：10个对话，1,986个问题（评估非对抗类的1,540个），5个类别。图片仅以描述文本形式给出。

**基线系统**：

- **Omni（SimpleMem）**：基于图和摘要的记忆，用LLM提取记忆单元，图片仅通过描述索引
- **M2A**：多模态智能体记忆，保留图片的描述和嵌入，通过融合密集、稀疏和图像信号的迭代LLM管道检索
- **A-Mem**：纯文本智能体记忆，每轮用LLM构建和演化笔记抽象

**评估指标**：主要使用gpt-4o-mini的LLM-as-judge评分（0-1），所有系统使用相同的评判模型和提示。

#### 3.2 主要结果

**Mem-Gallery**（Table 1）：

- V-Mem在gpt-4o-mini骨干下达到0.825，远超Omni的0.561、A-Mem的0.460和M2A的0.314
- 在Qwen2.5-VL-32B骨干下达到0.829 vs Omni的0.628
- **视觉类别差距最大**：TTL上V-Mem达0.872，无基线超过0.472；VR上0.575 vs 最高0.273

**LoCoMo**（Table 2）：

- V-Mem达0.690 vs Omni的0.583
- 单跳问题上优势明显（0.818 vs 0.663），时间推理也领先
- 唯一不足是开放域问题，M2A领先

#### 3.3 消融实验

论文通过增量消融（Table 3）逐步构建V-Mem：

| 配置 | TTL | VR | VS | Overall |
| --- | --- | --- | --- | --- |
| Vanilla（所有通道，单元级） | 0.740 | 0.362 | 0.655 | 0.680 |
| + 路由 | 0.708 | 0.356 | 0.647 | 0.689 |
| + 共享轮次匹配 | 0.890 | 0.537 | 0.801 | 0.818 |
| + 生成锚点 | 0.872 | 0.575 | 0.833 | 0.825 |

关键发现：

- **路由**本身对整体提升不大（+0.009），但它为后续步骤奠定基础，且在文本类别上有稳定提升
- **共享轮次匹配**是最大的提升步骤（+0.129 overall），主要提升视觉类别
- **生成锚点**在其触发的类别上有效（VR +0.038, VS +0.032）

**路由的必要性**：Table 11的通道开关实验表明，同一个通道在一个案例中帮助+0.04，在另一个案例中损害-0.24。没有统一的融合策略能同时满足所有案例，这正是V-Mem按案例路由的原因。

#### 3.4 效率分析

**记忆构建**（Table 4）：

- V-Mem：0 token，120秒（Mem-Gallery）/ 18秒（LoCoMo）
- Omni：2.77M token，6.5小时
- A-Mem：6.92M token，5.2小时
- M2A：4.3B token，73小时  
  V-Mem的零token构建是其检索设计的直接结果——保持对话原样而非提取。

### **回答成本**：V-Mem在视觉问题上消耗更多token（因为需要调用视觉模型提取关键词），但这正是产生视觉QA优势的机制。

### 四、关键设计细节

#### 4.1 图像轮次过滤

当目标是图像时，V-Mem丢弃任何不包含图片（自身或±1邻居内）的排名轮次。因为这样的轮次无法返回图像，只会占据返回名额。

#### 4.2 描述折叠（Caption Folding）

V-Mem将图片的描述文本不仅附加到图片单元上，还写入该图片所在轮次的文本中，使其可以通过文本通道被搜索到。消融实验显示这带来了+0.020的提升。

#### 4.3 图像编码器选择

论文比较了SigLIP（对比学习，图文对齐）和DINOv2（纯图像自监督）作为图像编码器。结果几乎相同（整体差异仅-0.003），因为DINOv2在实例识别上略好，SigLIP在从描述找图上略好，两者抵消。

### 五、局限性

1. **仅评估了图文对话记忆**：音频被当作文本处理，但基准中不包含音频数据，音频/视频作为独立可检索模态未被测试
2. **依赖骨干模型能力**：V-Mem通过返回匹配轮次及其邻居来提供证据，需要骨干模型从中提取答案。在较弱的7B骨干上，V-Mem反而不如Omni（0.509 vs 0.534），因为额外上下文成为噪声
3. **生成锚点有成本**：hypo-caption和enriched anchor在回答时消耗额外token和延迟，enriched anchor还需要视觉模型

---

### 六、核心贡献总结

1. 识别了多模态记忆检索中相似度搜索失败的两个根本原因（模态鸿沟和相似度-相关性鸿沟）
2. 提出按（查询模态，目标模态）组合路由检索的框架
3. 设计了两个互补机制：共享轮次匹配（跨越模态鸿沟）和LLM生成搜索锚点（弥合相似度-相关性鸿沟）
4. 实现了零LLM调用的记忆构建，在两个基准上显著超越现有基线

| 研究方法 | 提出V-Mem系统，通过模态路由检索机制解决问题：(1) 将对话组织为轮次(rounds)，通过共享轮次匹配跨越模态间隙，避免跨模态比较；(2) 利用LLM生成搜索锚点（假设性描述caption或富化搜索锚点）缩小相似性-相关性间隙；(3) 基于关键词规则从查询中识别(查询, 目标)模态对，按需激活对应检索通道。在Mem-Gallery和LoCoMo两个基准上进行评估。 |
| 主要发现 | 在Mem-Gallery上，V-Mem的LLM评判分数达到0.825，远超第二名Omni的0.561，在携带图像的查询上优势最大（0.872 vs. 基线最高0.472）；在LoCoMo上得分0.690 vs. 0.583。V-Mem的记忆构建零LLM调用，仅需数秒完成，而基线系统需数小时和数百万token。 |
| 创新点 | (1) 识别并形式化了多模态记忆检索中的模态间隙和相似性-相关性间隙两大问题；(2) 提出基于(查询, 目标)模态对的路由检索框架，按需激活不同检索通道和策略；(3) 通过共享轮次匹配跨越模态间隙，无需学习跨模态对齐；(4) 通过LLM生成假设性描述和富化搜索锚点缩小相似性-相关性间隙；(5) 记忆构建零LLM token开销，保留原始对话不做摘要或重写。 |
| 局限性 | (1) 评估仅限于图文对话记忆，音频和视频作为独立可检索模态尚未测试；(2) 依赖骨干模型能力，较弱的模型（如7B）反而不如基线；(3) 生成锚点在回答时增加token和延迟开销，尤其是携带图像的查询需要视觉模型调用；(4) 剩余的图像相关错误源于回答模型而非检索失败。 |
| 与本研究的关联 | 该论文针对多模态长期对话记忆的检索问题提出了模态路由方案，对研究LLM智能体的外部记忆系统、多模态检索增强生成（RAG）、以及跨模态信息检索具有重要参考价值，特别是其对模态间隙和相似性-相关性间隙的分析框架可为相关记忆系统设计提供理论指导。 |

## 原文摘要

Interaction between users and LLM agents is increasingly multimodal: conversations interleave text with images, and a later question may target either. Yet most agent memories are designed around text, and even the few that support multimodal conversations still fail on vision-related questions. We trace this failure to an assumption behind the similarity search they rely on: in the index space, a query lies close to the relevant evidence that answers it. In multimodal settings, two gaps break it. By the modality gap, a query lies closer to memory content of its own modality than to evidence in another, even in a trained joint embedding space. By the similarity-relevance gap, the content most similar to a query is often not the evidence that answers it, most acutely when a query carries both text and image and its evidence resembles neither part alone. We present V-Mem, a multimodal agentic memory system that routes retrieval by the modality of the query and that of the target evidence, both recognized from the query alone. To cross the modality gap, V-Mem organizes the conversation into rounds and returns the target-modality content from the same round as the match, without comparing across modalities. To close the similarity-relevance gap, it searches with an LLM-generated anchor that sits closer to the relevant evidence than the query does: a hypothetical caption for a text-only query seeking an image, and an enriched search anchor, the query text plus relevant keywords extracted from the query image, when the evidence is reachable only by combining the two. On Mem-Gallery, V-Mem reaches an LLM-judge score of 0.82 versus 0.56 for the second best, with the largest margin on questions carrying an image (0.87, no baseline above 0.47); on LoCoMo it scores 0.69 versus 0.58.
