# EvoMemBench: Benchmarking Agent Memory from a Self-Evolving Perspective

Wang, Yuyao, Zhang, Zhongjian, Chi, Mo, Yu, Kaichi, Li, Yuhan, Peng, Miao, Tong, Bing, Zhang, Chen, Zhou, Yan, Li, Jia · 2026

[论文原文](https://arxiv.org/abs/2605.18421)

## 核心机制

episode 内/跨 episode 与知识/执行两轴，比较多种记忆

## 适用范围与局限

强长上下文有竞争力；部分简单任务记忆负收益

## 详细解读

### EvoMemBench 论文详解

#### 核心内容概述

这篇论文提出了 **EvoMemBench**，一个专门用于评估大语言模型（LLM）智能体"记忆能力"的基准测试框架。作者从"自演化记忆"的视角出发，将记忆评估组织在两个维度上：**记忆范围**（单轮内 vs. 跨轮次）和**记忆内容**（知识导向 vs. 执行导向），形成四个评测子任务，并对 15 种代表性记忆方法进行了系统比较。核心结论是：当前所有记忆方法都远未达到"通用解决方案"的水平——强大的长上下文基线模型依然极具竞争力，记忆机制只在特定场景（上下文不足、任务困难、经验与任务结构匹配）下才能带来明显提升，且没有任何单一记忆形式能在所有场景下都表现最优。

---

### 一、研究背景与动机

#### 1.1 LLM 智能体的无状态问题

现代 LLM 本质上是**无状态**的：它们只能处理当前输入上下文中的信息，无法跨交互维护或更新持久状态。常见的应对方式是把历史交互、环境观测和工具输出都拼接到 prompt 里，但这种做法有明显局限——随着历史增长，内容很快就会超出有限的上下文窗口（context window）。

因此，真正有效的智能体记忆需要具备**持续更新、组织和复用**信息的能力，而不仅仅是存储过去的信息。

#### 1.2 现有评测基准的不足

作者梳理了已有的记忆评测工作，发现它们各有侧重但存在明显盲区：

| 基准 | 单轮内知识演化 | 单轮内执行演化 | 跨轮次知识演化 | 跨轮次执行演化 | 开源 |
| --- | --- | --- | --- | --- | --- |
| LoCoMo | ✓ | ✗ | ✗ | ✗ | ✓ |
| LongMemEval | ✓ | ✗ | ✗ | ✗ | ✓ |
| MemoryAgentBench | ✓ | ✗ | ✗ | ✗ | ✓ |
| StuLife | ✗ | ✓ | ✓ | ✓ | ✓ |
| MemoryBench | ✓ | ✗ | ✓ | ✗ | ✗ |
| Evo-Memory | ✗ | ✗ | ✓ | ✓ | ✗ |
| MemoryArena | ✓ | ✓ | ✗ | ✗ | ✓ |
| **EvoMemBench（本文）** | ✓ | ✓ | ✓ | ✓ | ✓ |

没有任何已有基准同时覆盖全部四个维度，且部分基准不开源，可复现性差。

### 二、核心概念框架

#### 2.1 形式化定义

论文将智能体的记忆机制形式化为：在 episode $e$ 的第 $t$ 步，智能体接收观测 $o_t^e$，持有历史 $h_{t-1}^e = (o_1^e, a_1^e, \ldots, o_{t-1}^e, a_{t-1}^e)$，然后基于当前上下文和记忆状态 $m_t^e$ 做出决策：

$$a_t^e \sim \pi(\cdot \mid h_{t-1}^e, o_t^e, m_t^e)$$

收到反馈 $y_t^e$ 之后，记忆状态被更新：

$$m_{t+1}^e = U(m_t^e, o_t^e, a_t^e, y_t^e)$$

其中 $U$ 是记忆更新函数。

#### 2.2 两个评估维度

**维度一：记忆范围（Scope）**

- **单轮内记忆（In-Episode）**：记忆仅在一个任务 episode 内维护。episode 开始时初始化，期间在线更新，episode 结束后清空。作用是在同一任务内为后续决策提供压缩的任务级状态。
- **跨轮次记忆（Cross-Episode）**：记忆在不同 episode 之间积累和复用。作用是将过去任务的经验提炼为经验级状态，供未来任务决策参考，同时需要避免直接复用不再相关的 episode 细节。

**维度二：记忆内容（Content）**

- **知识演化（Knowledge Evolution）**：存储支持后续推理和回答的信息，包括事实、约束、偏好、领域规则或任务模式。关键挑战是在新信息到来时，既要保留有效的旧信息，又要更新或替换与新证据相冲突的旧信息。
- **执行演化（Execution Evolution）**：存储支持动作选择和任务推进的信息，包括任务进度、中间结果、工具输出、未解决的子目标、行动套路和解题流程。关键挑战是帮助智能体追踪"做了什么、还剩什么、下一步最优行动是什么"。

### 三、基准构建：六个数据集

四个维度对应六个数据集，选取原则是：任务需为显式记忆留下改进空间、具有清晰的记忆依赖和可验证结果、覆盖多样化领域。

#### 3.1 INEP-KNOW（单轮内知识演化）

来源：MemoryAgentBench 的两个子集：

- **Accurate Retrieval**（2000 样本）：测试记忆保留（retention）——对话中提到的信息，后续能否正确检索。
- **Selective Forgetting**（800 样本）：测试记忆修订（revision）——对话中出现信息矛盾时，智能体能否正确更新记忆（例如"我说我爱梨？抱歉，我是爱豌豆"）。

#### 3.2 INEP-EXEC（单轮内执行演化）

来源：BFCL-Multiturn-LongContext，涵盖 Gorilla File System、Vehicle Control、Trading Bots、Travel Booking 四个领域，各 200 样本。

论文对原始数据做了两步重构以增强记忆导向性：

1. 将实体名、参数值等显式引用替换为隐式引用（"你刚创建的那个目录"而非具体名称），迫使智能体从记忆中恢复。
2. 将包含多个依赖动作的单轮拆分为多个子轮，使后续子轮必须依赖前轮结果。

#### 3.3 CROSSEP-KNOW（跨轮次知识演化）

来源：CL-Bench，覆盖四类知识形式：

- 领域事实（Domain Knowledge Reasoning，294 样本）
- 规则系统（Rule System Application，257 样本）
- 操作流程（Procedural Task Execution，306 样本）
- 经验规律（Empirical Discovery & Simulation，27 样本）

构建方式：将样本按共享背景分组，保留至少含 5 个样本的上下文（共 120 个上下文，884 个样本），按 DeepSeek-V3.2 基线得分三等分为 Easy/Medium/Hard。episode 按序处理，每个 episode 结束后更新记忆供同一上下文的后续 episode 使用。

#### 3.4 CROSSEP-TOOL（跨轮次工具使用执行演化）

来源：BFCL-Multiturn-Base，同样覆盖四个领域各 200 样本，采用与 INEP-EXEC 相同的重构流程。测试智能体能否学习可复用的工具调用模式、API 约束和参数填充流程。

#### 3.5 CROSSEP-WEB（跨轮次网页搜索执行演化）

来源：xbench-DeepSearch（100 样本）+ WebWalkerQA（170 样本）。测试智能体能否复用之前的搜索策略和信息验证经验。

#### 3.6 CROSSEP-EMB（跨轮次具身交互执行演化）

来源：ALFWorld 测试集，覆盖六类任务：Examine in Light（19）、Pick & Place（46）、Clean & Place（37）、Cool & Place（28）、Heat & Place（25）、Pick Two & Place（45）。测试智能体能否积累行动套路和环境信息用于后续具身任务。

### 四、评估指标

#### 4.1 答案准确率（Answer Accuracy）

用于 INEP-KNOW 和 CROSSEP-KNOW（知识导向任务）：

$$\text{Acc} = \frac{1}{N}\sum_{i=1}^{N} \text{Correct}(i)$$

其中 $\text{Correct}(i) \in \{0,1\}$ 表示第 $i$ 个实例是否答对。

#### 4.2 成功率（Success Rate）

用于 INEP-EXEC、CROSSEP-TOOL、CROSSEP-WEB、CROSSEP-EMB（执行导向任务）：

$$\text{SR} = \frac{1}{N}\sum_{i=1}^{N} \text{Success}(i)$$

衡量智能体能否完成最终目标，是端到端执行质量的严格度量。

#### 4.3 进度分（Progress Score）

用于 INEP-EXEC 和 CROSSEP-TOOL，衡量部分完成情况：

$$\text{PS}_i = \frac{1}{T_i}\sum_{t=1}^{T_i} \text{Pass}(i, t)$$

$$\text{PS} = \frac{1}{N}\sum_{i=1}^{N} \text{PS}_i$$

比成功率更细粒度，即使最终失败也能反映智能体走了多远。

#### 4.4 平均步数与 Token 用量

- **平均步数**（Average Steps）：$\text{AS} = \frac{1}{N}\sum_{i=1}^N \text{Steps}(i)$，反映交互效率，越低越好。
- **Token 用量**（Token Usage）：$\text{TU}_i = \sum_{c \in C_i} (\text{Tok}^{\text{in}}(c) + \text{Tok}^{\text{out}}(c))$，衡量不同记忆机制引入的计算开销。

### 五、实验设置

#### 5.1 对比方法

**无记忆基线（长上下文 LLM）：**

- **Gemini-3-Flash**：Google 的长上下文模型，支持超长上下文高效推理。
- **GPT-5-mini**：OpenAI 的轻量长上下文模型。
- **DeepSeek-V3.2**：混合专家（MoE）架构，作为所有记忆增强方法的统一骨干模型。

**记忆增强方法（均以 DeepSeek-V3.2 为骨干）：**

| 类别 | 方法 | 核心思路 |
| --- | --- | --- |
| 检索增强记忆 | BM25 | 基于词频/逆文档频率的稀疏检索 |
|  | Qwen3-Emb-4B | 4B 参数稠密向量检索 |
|  | GraphRAG | 构建知识图谱后分层摘要查询 |
| 短期记忆 | MemAgent | 固定大小记忆缓冲区，RL 训练的覆写式更新 |
|  | MemoBrain | 持续压缩近期交互历史的执行型记忆 |
| 通用长期记忆 | Mem0 | ADD/UPDATE/DELETE/NOOP 四操作增量提取 |
|  | A-MEM | 语义互联的记忆笔记网络 |
|  | MemOS | 操作系统风格的分层存储管理 |
|  | MemoryOS | STM/MTM/LPM 三层记忆层次 |
| 程序性长期记忆 | AWM | 从轨迹归纳可复用工作流 |
|  | SkillWeaver | 自主发现和精炼可执行 API 技能 |
|  | AgentKB | 跨框架知识共享基础设施 |
| ACE |  | 积累可执行经验模板 |
|  | ReasoningBank | 存储结构化推理轨迹的推理记忆库 |
| 元演化记忆 | MemEvolve | 通过迭代自优化持续演化记忆结构 |

注：程序性记忆不用于单轮内知识演化；短期记忆不用于跨轮次场景。

#### 5.2 实现细节

- 每个方法统一封装为 `utilize`（利用记忆）和 `update`（更新记忆）两个接口。
- INEP-EXEC 评估四种上下文预算：16K、32K、64K、128K token；当 prompt 超出预算时，保留当前任务输入和记忆，截断早期历史。
- 默认使用 DashScope 的 text-embedding-v4 作为嵌入后端；知识导向任务检索 top-k=10，执行导向任务 top-k=3。

### 六、主要实验结果与发现

#### 6.1 单轮内知识演化（INEP-KNOW）

**发现 1：强大的长上下文基线极具竞争力。**

Gemini-3-Flash 在记忆保留和记忆修订上均排名第一。这说明当上下文预算充足时，直接保留原始证据往往比依赖外部记忆抽象更可靠。从 Figure 2 的精度-开销图来看，很多记忆方法消耗了更多 token，但准确率并不更高。

**发现 2：现有记忆方法在"保留"上优于"修订"。**

BM25、Mem0、A-MEM 在保留类任务上能超过弱基线，但在 FactConsolidation（事实修订）任务上——尤其是多跳推理子集——性能急剧下降。这揭示了记忆修订的核心难点：**不是检索相关证据，而是判断哪些存储信息应当被更新、压制或替换**。

#### 6.2 单轮内执行演化（INEP-EXEC）

**发现 3：上下文预算受限时，记忆帮助更大。**

与 DeepSeek-V3.2 无记忆基线相比，最优记忆方法在各上下文预算下的整体成功率提升：

- 16K：+14.5 个百分点
- 32K：+14.0 个百分点
- 64K：+7.8 个百分点
- 128K：+8.5 个百分点

16K 和 32K 下提升最大，因为原始交互历史更容易被截断。但随着上下文增大，记忆的边际收益递减；在 128K 下，部分记忆方法甚至低于无记忆基线，说明追加的记忆内容可能引入噪声或占用有用上下文空间。

**发现 4：执行任务受益于程序性引导，但压缩有风险。**

ReasoningBank 在 16K（43.0）、32K（49.5）、128K（48.0）三个预算下均取得最优整体成绩；AWM 在 64K（53.1）下最优。这说明工具使用任务受益于可复用的执行指导（行动套路、失败感知策略、参数填充流程）。

但短期压缩方法（MemAgent 和 MemoBrain）在 16K 下整体成功率仅为 26.0 和 25.0，均低于无记忆基线 28.5。执行状态追踪需要**精细粒度的细节**（精确的工具调用参数、实体引用、中间结果），粗粒度压缩会造成信息损失。

#### 6.3 跨轮次知识演化（CROSSEP-KNOW）

**发现 5：记忆对难任务帮助更大，但会损害简单任务。**

- Easy 分割：无记忆基线 DeepSeek-V3.2 得 52.1，最优记忆方法 Qwen3-Emb-4B 仅 50.0，通用长期记忆更低（43.8–46.8）。
- Hard 分割：DeepSeek-V3.2 得 0.0，而 ACE 达到 13.0，BM25 达到 10.1，MemoryOS 达到 9.0。

结论：当当前上下文对基础模型已经足够时，额外记忆可能引入不相关证据、不匹配的历史信息或不必要的 prompt 偏差，反而有害。

**发现 6：瓶颈在于形成可复用知识，而非简单堆叠更多信息。**

ACE 在 Medium 和 Hard 任务上综合表现最优（16.5 和 13.0），在规则系统应用子任务上更是在 Easy/Medium/Hard 三个难度上都超越所有其他记忆方法（74.9 / 24.0 / 7.8）。这表明有效记忆应当支持**知识的应用方式**，而非仅仅存储更多知识内容。

#### 6.4 跨轮次执行演化（CROSSEP-TOOL/WEB/EMB）

**发现 7：不同执行域偏好不同记忆形式。**

| 执行域 | 最优记忆类别 | 平均排名 | 原因分析 |
| --- | --- | --- | --- |
| 工具使用 | 检索增强记忆 | 5.43 | 相似 API 调用和参数模式反复出现，适合基于案例的检索复用 |
| 网页搜索 | 通用长期记忆 | 5.38 | 需要持续积累证据和验证习惯，适合长期信息维护 |
| 具身 AI | 程序性长期记忆 | 5.60 | 行动套路和环境可供性（affordance）重要，适合技能/工作流存储 |

**发现 8：跨环境迁移取决于记忆与目标决策过程的匹配程度。**

- **CROSSEP-TOOL**（图 3）：工具使用任务跨环境迁移更稳定，因为不同工具使用环境通常共享相似的决策步骤（检查中间状态→选择下一次调用→验证最终状态）。
- **CROSSEP-EMB**（图 4）：ALFWorld 跨环境迁移更不稳定，更容易出现中性或负迁移。ALFWorld 各子环境在任务需求和执行条件上差异更大，一个具身环境积累的经验未必适用于另一个。

### 七、综合结论

论文最终得出三条一致性规律：

1. **记忆可以提升性能，但不均匀**：强长上下文基线依然极具竞争力，显式记忆只在部分场景下提供明显增益。
2. **记忆在以下情况最有帮助，在以下情况可能有害**：

   - 有帮助：上下文不足、任务更难、存储经验与目标决策过程匹配。
   - 有害：引入不相关证据、通过压缩移除细粒度执行细节、跨环境迁移程序不匹配。
3. **没有单一记忆形式能在所有场景普遍有效**：检索增强是知识导向需求的强选择；程序性和长期记忆在执行导向问题上更有效——前提是存储形式与任务的可复用结构对齐。

总体而言，当前方法仍未能提供自演化智能体记忆的通用解决方案，EvoMemBench 旨在为这一方向的未来研究提供统一测试平台。

## 原文摘要

Recent benchmarks for Large Language Model (LLM) agents mainly evaluate reasoning, planning, and execution. However, memory is also essential for agents, as it enables them to store, update, and retrieve information over time. This ability remains under-evaluated, largely because existing benchmarks do not provide a systematic way to assess memory mechanisms. In this paper, we study agent memory from a self-evolving perspective and introduce EvoMemBench, a unified benchmark organized along two axes: memory scope (in-episode vs. cross-episode) and memory content (knowledge-oriented vs. execution-oriented). We compare 15 representative memory methods with strong long-context baselines under a standardized protocol. Results show that current memory systems are still far from a general solution: long-context baselines remain highly competitive, memory helps most when the current context is insufficient or tasks are difficult, and no single memory form works consistently across all settings. Retrieval-based methods remain strong for knowledge-intensive settings, whereas procedural and long-term memory methods are more effective for execution-oriented tasks when their stored experience matches the task structure. We hope EvoMemBench facilitates future research on more effective memory systems for LLM-based agents. Our code is available at  this https URL .
