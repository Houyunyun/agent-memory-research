# Proteus: A Self-Evolving Red Team for Agent Skill Ecosystems

Zhou, Zhaojiacheng · 2026

[论文原文](https://arxiv.org/abs/2605.11891)

## 核心机制

反馈驱动地迭代评估技能审查及运行风险

## 适用范围与局限

主要技能生态审查，与记忆自写入攻击权限不同

## 详细解读

> 阅读边界：攻击成功是审计通过与沙箱目标副作用同时成立，限于论文的种子、预算、审计器和运行环境；文中的“致命”指规则 oracle 记录的目标副作用，不是人身伤害。仅审计的单向迁移不等于换环境后重新执行成功；小样本消融、累计成功率斜率也不是普遍因果保证。

Proteus 是一种针对智能体技能生态系统的“自进化红队”框架，用于测量一种此前未被充分量化的部署风险——自适应泄漏（adaptive leakage）。其核心思想是：攻击者不再只是一次性提交恶意技能，而是可以在预算内根据审计器返回的结构化发现和沙箱运行时反馈，反复修改技能文档、代码、拓扑和侧信道，直到该技能既通过安全审计，又在目标智能体上造成可由预言器验证的运行时危害。论文将成功的攻击定义为 $b_t \land l_t = 1$，即“审计不拦截”和“沙箱预言器确认致命”同时成立。Proteus 通过一个统一的审计—沙箱—预言器轮次合约和五轴技能攻击空间（目标 $o$、拓扑 $\tau$、代码 $c$、侧信道 $\kappa$、文档 $d$）实现这一测量。在两个公开技能审计器上，Proteus 在 5 轮预算内的攻击成功率（ASR@5）达到 40%–90%，并在扩展阶段生成 438 个同时绕过审计且经预言器验证为致命的变体；其中最强的公开审计器 AI-Infra-Guard 仍被多个配置以最高 41.3% 的联合成功率绕过，且 87.7% 针对该审计器演化的成功技能无需任何新变异即可通过另一审计器 SkillVetter 的审计。结果表明，当前的技能审查在被反馈驱动的自适应攻击者评估时，显著低估了残余风险。

### 1. 研究背景与问题定位

#### 1.1 智能体技能生态系统

论文研究的是“智能体技能”（agent skills）：为 LLM 智能体提供的可重用指令、工具接口和可执行代码。这些技能通常来自市场、代码仓库或社区渠道，以第三方包的形式安装。一个技能包含：

- YAML frontmatter（元数据）
- Markdown 文档（说明用途、用法、权限）
- 捆绑脚本（可执行代码）
- 声明的工具白名单

这种封装同时暴露两个攻击面：**执行面**（代码在智能体运行时中运行）和**上下文面**（文档被加载到智能体的上下文中，影响宿主模型对后续任务的解读）。因此，安全审计器只是位于第三方技能和部署智能体之间安全链中的一层，还需要运行时白名单、沙箱约束和宿主模型自身的拒绝行为来共同防护。

#### 1.2 现有工作的不足

已有关于智能体技能安全的研究主要基于**静态攻击制品**：手工构造或模板驱动的恶意技能、静态扫描数据集、针对特定加载机制的单轮攻击等。这些研究衡量的是审计器在一次快照中能发现什么，而没有衡量当攻击者利用审计反馈和运行时反馈反复修改同一个技能后，审计器还能挡住多少。

开源技能审计器公开了其审计代码和规则集，因此任何技能作者都可以在本地复现其提交将获得的结构化发现——这是一个灰盒通道。但以往的单轮评估没有利用这一点。邻近领域的自动化红队（如提示词越狱、网页智能体注入、记忆投毒）虽然提供了反馈循环，但它们搜索的是提示、网页注入、记忆条目或智能体间消息，而非技能包。技能包中代码、文档、侧信道和拓扑共同决定危害，因此技能审查的残余泄漏很可能被低估。

论文由此提出“自适应泄漏”这一测量对象：**预算受限的攻击者是否能通过多轮修改使技能既通过审计又造成经验证的运行时危害**。

### 2. 问题形式化

#### 2.1 技能、威胁模型与防御者

技能制品被建模为三元组：YAML frontmatter、Markdown 正文、捆绑脚本，并带有声明的工具白名单；托管仓库提供公开上下文。攻击者向市场提交任意技能；防御者运行离线静态+LLM 判断审计，并在沙箱中执行。两个公开审计器被实例化：SkillVetter（ClawHub 生态使用的开源审计器）和 AI-Infra-Guard（腾讯的审计器）。沙箱使用 OpenClaw 2026.3.24 版本。

攻击者能力是**灰盒**：在轮次之间可以看到审计器的结构化发现和沙箱运行时轨迹，而不是依赖审计模型内部状态。审计器代码和规则公开，使技能作者有机会在本地复现发现；这不等于所有部署都提供相同反馈。

#### 2.2 五轴分解和三种搜索模式

技能变体被分解为五元组：

$$s = (o, \tau, c, \kappa, d)$$

其中：

- $o$：攻击目标，七个预言器类别之一——数据外泄（data exfiltration）、持久化（persistence）、权限提升（privilege escalation）、清理中毒（cleanup-poisoning）、引导注入（guidance injection）、供应链滥用（supply-chain abuse）、跨技能链式（cross-skill chaining）。
- $\tau$：拓扑，单个技能或 $k$ 链。
- $c$：代码制品。
- $\kappa$：侧信道（side-effect channel）。
- $d$：文档层面的呈现。

三个嵌套搜索模式在不同阶段激活：

- **S1 第一阶段的自由发现**：固定 $(o, \tau)$，自由搜索 $(c, \kappa, d)$，直到第一次出现 $b \land l$。
- **S2 路径扩展**（离线预算）：固定 $(o, \tau)$，但要求替代的 $(c, \kappa)$。
- **S3 表面扩展**（离线预算）：释放 $(o, \tau)$，但施加 SharedMotif ≥ 2 轴结构基元门控。

#### 2.3 自适应泄漏的数学定义

每一轮，红队应用两阶段 Reason→Mutate 算子；审计器、运行时和预言器返回一个反馈四元组：

$$\langle b_t, l_t, F_t, R_t \rangle$$

其中 $b_t=1$ 表示审计器返回非阻塞判定；$l_t=1$ 表示沙箱预言器观察到目标副作用（如金丝雀令牌外泄、受保护哨兵删除、SUID 提权）；$F_t$ 是结构化发现列表（原因代码、严重度、证据指针）；$R_t$ 是运行时轨迹。一个技能在第 $t$ 轮成功当且仅当 $b_t \land l_t = 1$。

自适应泄漏（Adaptive Leakage，AL）定义为部署风险的度量：

$$\mathrm{ALB}(\text{Blue}, M, \theta) = \mathbb{E}_{s_0 \sim D_{\mathrm{seed}}} P_{\theta_r} \left[ \exists t \le T : b_t \land l_t \mid s_0, M, \text{Blue} \right]$$

即在预算 $B = (T, B_{\mathrm{tool}})$ 下，从种子分布采样一个种子，攻击者轨迹中至少一轮达到 $b \land l$ 的概率。实验中用 $T=5$、$n=20$ 层化种子的每格 $\star$ 率作为经验估计。

### 3. Proteus 方法

#### 3.1 总体框架

图 1 展示了 Proteus 的一轮流程。红队变异器（左侧）持三种信号源：本次运行的攻击日志、目标仓库的公开上下文、良性技能样本；并消费上一轮的结构化审计发现 $F_{t-1}$ 和沙箱运行时建议 $R_{t-1}$ 作为上下文侧信息，输出变异后的技能变体。该变体经过防御者无关的审计→沙箱→预言器轮次合约：审计器给出每技能判定 $b_t$ 和发现列表 $F_t$；沙箱对目标骨干执行变体并记录运行时轨迹；每目标预言器根据沙箱可观测物判断致命性 $l_t$。四元组 $\langle b_t, l_t, F_t, R_t \rangle$ 关闭循环进入下一轮。

#### 3.2 图引导链组合

拓扑轴 $\tau$ 的实现不是一个自由 LLM 想象，而是一个对市场组合图的**结构化搜索**。具体做法：

- 抓取 ClawHub 形成约 47k 节点的技能图。
- 使用 16 条类型化的 source→sink 风险规则（如 credentials → network_egress 对应数据外泄）识别哪些端点配对在操作上有意义。
- 当代理选择链拓扑（$|\tau| > 1$）时，变异算子 `thematic-chain-insert` 会从图中检索一个声明主题与源→汇数据流一致的良性外观技能作为桥接。例如在凭据读取技能和不相关的网络汇之间插入一个凭据同步风格的桥接技能。
- 桥接技能的选择受审计侧相同的主题相似度约束（cos ≥ 0.30），因此合成链在构造上看起来像审计器自己会枚举的链。

这一机制与审计侧的枚举有三个不对称性：粒度不同（审计消费整条路径，攻击者消费单个节点作为可组合构建块）；机制不同（代理通过主题一致的桥接插入，而非直接输出路径）；复用不同（同一指纹表可用于表面扩展的跨目标构思）。

#### 3.3 红队：自进化 Agent

红队是一个闭环灰盒变异器，实现为 Reason→Mutate 两阶段算子：

$$h_t = \text{Reason}_\theta(H_{<t}, F_{<t}), \quad s_t = \text{Mutate}_\theta(s_{t-1}, a_t, S_k)$$

其中 $H_{<t}$ 是历史攻击日志，$F_{<t}$ 是过去的审计发现集，$a_t$ 是结构化的工具调用序列，$S_k$ 是当前搜索子空间。

Agent 有六个工具函数：

- `read_skill`：读取良性技能作为写作风格演示。
- `list_skills`：浏览类别中的技能以找风格参考。
- `read_repo_context`：目标仓库 README/文件树/主题摘要。
- `read_attack_log`：用 BM25 检索当前运行的攻击日志。
- `get_binary`：代码卸载原语，当上一轮 $R_t$ 显示运行时层阻止了 exec 类别原语时，可转向写类别的二进制投放原语。
- `submit_mutation`：提交变异后的技能变体。

这些工具暴露三个信号源：良性技能样本作为写作风格的演示、本次运行的历史攻击日志、目标仓库的公开上下文。灰盒反馈通道——结构化发现作为上下文条件，防御者状态跨轮保留——是跨轮学习的关键。

#### 3.4 三层进化

- **第 1 层：第一阶段自由发现（free discovery）**。核心变异循环在 S1 中运行：代理分析审计器发现和运行时建议 $R_t$，然后提交文档重写、代码/脚本编辑、信道添加、链替换的任意组合。首次 $b \land l$ 成功通常需要在多个轴上组合动作。
- **第 2 层：路径扩展（path expansion）**。一旦成功，代理进入不占用主轮预算的水平扩展阶段。给定成功变异，代理使用 `list_skills`、`read_skill`、`read_attack_log` 发现实现同一攻击目标的替代实现（如持久化通过 cron 成功后，发现 systemd 定时器或 launchd plist 等机制）。
- **第 3 层：表面扩展（surface expansion）**。测试代理能否将成功漏洞利用转移到不同攻击类型。采用开放式构思+自选测试协议：提示代理列出 $k$ 个候选扩展，每个包含新目标 $o'$、共享基元（SharedMotif）和可行性理由；代理选择 $k' \le k$ 个目标与 $o$ 不同的候选并提交新变异，每个新变异由对应的 $o'$ 预言器验证。SharedMotif 约束在提交变体后事后计算，不作为提示的一部分，这减少直接按该门槛写提示的机会，但不保证发现信号不能被操纵。

#### 3.5 灰盒轮次合约

每个被评估的审计器（AIG, SkillVetter）被包裹在一个统一的 BluePort 适配器后面，将其原生输出标准化为共享发现模式 $\{layer, reason\_code, category, severity, evidence, explanation\}$。审计找到的 $F_t$ 和运行时建议 $R_t$ 通过同一 `<FINDING>` 通道进入下一轮提示，因此两者都统一地作为侧信息而非标量奖励。

沙箱运行时建议 $R_t$ 的合成有两种触发模式：

1. **目标执行了某些动作但未触发金丝雀**：合成器枚举哪些预言器传感器保持沉默，以及哪些路径本应触发它们（如 `.env` 在 `` $HOME/.openclaw/workspace/.env` 而非 `$HOME/.env ``）。
2. **尽管审计通过但零执行动作**：表面化两种候选失败模式——运行时白名单拒绝原语，或目标对齐在 LLM 层拒绝——并附上目标的字面回复，让变异器自行消歧。

#### 3.6 三条自我进化度量

- **ASR@5**：5 轮预算后的攻击成功率。对 $n=20$ 种子跑 $T=5$ 轮，ASR@t 是前 $t$ 轮内至少产生一个 $\star = b \land l$ 变体的种子比例。累计轨迹 $\{\mathrm{ASR@t}\}_{t=1}^{5}$ 是 AL 的经验估计。
- **学习曲线斜率（LCS）**：对 ASR@t 做 OLS 拟合的斜率 $\alpha$。由于 ASR@t 单调不减且在 [0,1] 内，5 轮时的几何上限约 0.30；$\alpha > 0.10$ 已表明强跨轮学习。
- **策略多样性增长（SDG）**：每轮变异理由声明使用的变异算子集合，SDG 是不同集合跨轮累计计数；正增长斜率表明探索策略日益多样，而非收敛到单一方法。

### 4. 实验设置

#### 4.1 种子、仓库与模型

- 20 个恶意种子技能通过图引导链组合从 ClawHub 语料库中选出，层化覆盖七类攻击。
- 与 10 个目标仓库配对，领域多样（交易、DevOps、数据科学、RAG、CI/CD）。
- 红队变异器：DeepSeek-V4-Pro 或 Kimi-2.6。
- 目标智能体骨干：GPT-5.4-mini 或 GLM-5。
- 审计器：SkillVetter 或 AI-Infra-Guard。
- 沙箱使用未加固的 OpenClaw 镜像；审计通过和报告致命性之间的唯一门是沙箱观测和每目标预言器。

#### 4.2 基线

- **Random**：每轮均匀随机组合 $(c,\kappa,d)$ 编辑，不消费反馈。
- **Zero-shot**：一次性要求 LLM 写一个能绕过“通用审计器”的恶意技能，无轮结构。
- **Blackbox**：LLM 仅根据标量审计判定 $b_t$ 迭代重写提示，无结构化发现或运行时建议。
- **PyRIT**：微软的公开红队框架，用于外部对比，采用默认叙述重写模式只变异文档通道 $d$。

### 5. 实验结果

#### 5.1 多轮迭代绕过（Phase-1）

表 1 给出 8 个（变异器，目标，防御者）单元的 ASR@5：

| 防御者 | 变异器 | 目标 | $\star / n$ | $\star(\%)$ |
| --- | --- | --- | --- | --- |
| SV | DeepSeek-V4-Pro | GLM-5 | 16/20 | 80.0 |
| SV | DeepSeek-V4-Pro | GPT-5.4-mini | 17/20 | 85.0 |
| SV | Kimi-2.6 | GLM-5 | 18/20 | 90.0 |
| SV | Kimi-2.6 | GPT-5.4-mini | 11/20 | 55.0 |
| AIG | DeepSeek-V4-Pro | GLM-5 | 16/20 | 80.0 |
| AIG | DeepSeek-V4-Pro | GPT-5.4-mini | 10/20 | 50.0 |
| AIG | Kimi-2.6 | GLM-5 | 14/20 | 70.0 |
| AIG | Kimi-2.6 | GPT-5.4-mini | 8/20 | 40.0 |

两个稳健趋势：AIG 的静态分析地板使 $\star$ 率相对 SkillVetter 降低 10–30 个百分点；更对齐的目标 GPT-5.4-mini 比 GLM-5 难 5–30 个百分点。

表 2 对比 SV+GPT-5.4mini+DeepSeek 单元上的基线：

| 红队 | LCS |
| --- | --- |
| Random | +0.014 |
| Zero-shot | 0.000 |
| Blackbox | +0.014 |
| Ours | +0.160 |

Ours 的 LCS 为 0.160，而所有基线 ≤ 0.014（几何上限约 0.30），约 11 倍斜率差距。Blackbox 在第二轮就饱和在 42.9%，即使扩展到 T=10 也无增益；这表明将 $F_{<t}$ 折叠为标量奖励会导致学习率下降一个数量级。

图 3 的累计曲线显示：SkillVetter 上四个单元中有三个在 r=3 就饱和；而 AIG 上每个单元在 T=5 时仍在增长——审计地板越严格，预算越不充分。

图 4 的首次 $\star$ 直方图显示：AIG 下首次成功集中在第 3–5 轮，说明需要反馈驱动的枢转突破静态分析地板；SkillVetter 下超过半数首次成功出现在第 1–2 轮，说明 LLM 判断审计可被单次闭环迭代绕过。

**与 PyRIT 的对比**（图 2）：在 AIG + DeepSeek-V4-Pro + GLM-5 单元，PyRIT 默认叙述重写模式只变异文档通道 $d$，得到 5/100 联合 $\star$ 轮和 5/20 $\star$ 种子；Ours 得到 57/138 和 16/20。该配置中的差距支持联合变异的价值；两种方法的搜索空间和预算构成不同，不能由这一对比单独识别各轴的因果贡献。

#### 5.2 阶段 2 扩展：路径与表面

一旦某个种子达到第一阶段 $\star$，离线预算的路径扩展（S2）和表面扩展（S3）将单个成功变体扩展为一个家族。汇总全 8 单元矩阵（表 3）：

- 总共生成 438 个 $\star$ 变体。
- SkillVetter 在每个单元中被绕过率 ≥ 93%。
- AIG 每个（变异器，目标）对产生 25–41% 的 $\star$ 率；最强配置 DeepSeek-V4-Pro + GLM-5 + AIG 达到 41.3%。

图 5 将阶段 2 产出按攻击类别和扩展阶段切割：S3 表面扩展产生的 $\star$ 跨越多个攻击类别，证明存在超越父种子目标的真正表面发现，而不只是类内脆弱性。

#### 5.3 跨审计器迁移

为了测试 Proteus 的收益是否泛化到审计器之外，将 DeepSeek+GLM-5+AIG 单元的 57 个阶段-2 $\star$ 变体重新通过 SkillVetter（仅审计；沙箱/预言器输出不变，因此致命性按技能字节身份保持）。结果：50/57（87.7%，95% CI [76.8%, 93.9%]）也通过 SV 审计，给出跨审计器联合 $b \land l$ 率 87.7%。该结果是单向的（从较强的 AIG → 较弱的 SV），表明针对较强审计器学到的绕过也能清除较弱审计器，但不证明对任意审计器完全无关。这一结果提示风险可能迁移，但不建立面向任意其他审计器或执行环境的统一风险下界。

#### 5.4 消融实验与关键结论

附录 A.10 的消融（AIG + GLM-5 + Kimi 单元，N=5，T=5）显示：

| 配置 | $\star$ 率 |
| --- | --- |
| Full（Ours） | 4/5 = 80% |
| 仅标量 $b_t$（无结构化发现） | 3/5 = 60% |
| 强制 $\tau =$ 单技能（无配对/链） | 0/5 = 0% |
| 无工具（Random） | 0/5 = 0% |

两个主导性下降是拓扑因子化与 LLM 作为变异器的价值：限制为单技能使攻击面不足以通过 AIG 审计并交付预言器接受的证据；移除全部反馈消费通道使成功率为零。

### 6. 结论与局限

**结论**：Proteus 展示了一个闭环自进化红队框架，能够在两个公开审计器上产生大量同时绕过审计且被预言器验证为致命的技能变体。它不仅绕过审计，还通过路径扩展和表面扩展发现原种子目标之外的新攻击类型；针对 AIG 演化的成功技能中有 87.7% 不需重新变异就绕过 SkillVetter，证明自适应泄漏可跨审计器边界转移。作者认为这是生态系统层面的风险信号，并呼吁审计器维护者在自适应攻击下重新评估残余风险。

**局限**（附录 C.1 列出了 8 条）：

1. 威胁模型假设攻击者可以在轮间读取结构化审计发现；完全封闭、不输出解释的商业审计器会弱化这一侧信道。
2. 攻击预言器基于规则，可能未涵盖所有复杂攻击目标。
3. 只使用了两个目标模型（GPT-5.4-mini, GLM-5）。
4. 表面扩展受变异器模型能力的限制。
5. SharedMotif 门使用固定的 ≥2 轴阈值，未消融该阈值。
6. 审计器被建模为静态，不考虑审计器学习和军备竞赛。
7. 两个变异器来自同一前沿模型生态。
8. 种子选择与变异器侧使用同一图引导链组合方法，存在潜在耦合，尚未正式反驳。

论文最后说明将发布轮次合约、图构建器、变异算子目录、沙箱运行器和测量指标等以支持其他审计器的复测，但暂不公开具体绕过模板和完整变异提示，以平衡可复现性和滥用风险。

## 原文摘要

Agent skills extend LLM agents with reusable instructions, tool interfaces, and executable code, and users increasingly install third-party skills from marketplaces, repositories, and community channels. Because a skill exposes both executable behavior and context-setting documentation, its deployment risk cannot be measured by single-shot audits or prompt-level red teams alone: a realistic attacker can use audit and runtime feedback to repeatedly rewrite the skill. We frame this risk as \emph{adaptive leakage} -- whether a budgeted attacker can iteratively revise a skill until it passes audit and produces verified runtime harm -- and present \ours{}, a grey-box self-evolving red-team framework for measuring it. Proteus searches a formalized five-axis skill-attack space. Each candidate is evaluated through a unified audit-sandbox-oracle pipeline that returns structured audit findings and runtime evidence to guide cross-round mutation. Beyond initial evasion, Proteus performs path expansion, which finds alternative implementations of successful attacks, and surface expansion, which transfers learned implementation patterns to new attack objectives beyond the original seed catalogue. Across eight phase-1 cells, Proteus reaches 40--90\% Attack Success Rate at $5$ rounds (ASR@5) with positive learning-curve slopes on both evaluated auditors. Phase-2 path/surface expansion produces 438 jointly bypassing and lethal variants, with SkillVetter bypassed at $\geq 93\%$ in every cell and AI-Infra-Guard, the strongest public auditor we evaluate, still admitting up to 41.3\% joint-success. These results show that current skill vetting substantially underestimates residual risk when evaluated against adaptive, feedback-driven attackers.
