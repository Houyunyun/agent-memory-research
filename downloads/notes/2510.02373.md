# A-MemGuard: A Proactive Defense Framework for LLM-Based Agent Memory

Wei, Qianshan, Yang, Tengchao, Wang, Yaochen, Li, Xinfeng, Li, Lijun, Yin, Zhenfei, Zhan, Yi, Holz, Thorsten, Lin, Zhiqiang, Wang, XiaoFeng · 2025

[论文原文](https://arxiv.org/abs/2510.02373)

## 核心机制

多记忆推理一致性校验加独立教训记忆

## 适用范围与局限

相关来源不必独立，自检不等于访问控制

## 详细解读

### 论文核心总结

这篇论文提出了A-MemGuard（Agent-Memory Guard），这是首个针对LLM智能体（Agent）记忆系统的主动防御框架。LLM智能体依赖记忆来从过往交互中学习，但攻击者可以向记忆中注入看似无害、实则在特定上下文中才会触发恶意行为的记录，并且这种错误会通过"自我强化错误循环"不断放大。现有的防御方法（如逐条审查记忆条目）由于无法感知上下文，检测率极低。A-MemGuard通过两个协同机制解决这一问题：（1）**基于共识的验证**，为每条检索到的记忆生成并行推理路径，通过多数投票发现偏离共识的异常路径；（2）**双记忆结构**，将检测到的错误蒸馏为"教训"存入专门的教训记忆库，在未来行动前参考，从而打破错误循环。实验表明该框架可将攻击成功率降低95%以上，同时对正常任务的性能影响极小。

### 一、研究背景与动机

#### 1.1 LLM智能体的记忆系统

当前的LLM智能体（如基于ReAct、AutoGen等框架的系统）在执行复杂任务时，核心能力之一来自于其**记忆系统**。记忆系统存储了智能体过去的交互经验、知识片段等，使其能够进行长期规划、自适应学习和跨任务推理。形式化地说，在每个时间步$t$，智能体接收用户查询$q_t$，从记忆$\mathcal{M}_t = \{m_1, m_2, \ldots, m_N\}$中通过检索函数$\mathcal{R}$选出$K$条相关记忆：  

$\displaystyle \mathcal{M}_r = \mathcal{R}(q_t, \mathcal{M}_t, K)$

  
然后将检索到的记忆$\mathcal{M}_r$与当前查询$q_t$一起输入智能体的策略$\pi_\theta$（即底层LLM），生成候选行动方案$p_c$：  

$\displaystyle p_c \sim \pi_\theta(\cdot | q_t, \mathcal{M}_r)$

  
这种架构使得记忆系统成为**单点故障**——如果记忆被污染，智能体的行为就会被操控。

#### 1.2 记忆注入攻击的两大核心挑战

论文指出，针对记忆的攻击有两个使其特别难以防御的特性：  
**挑战一：上下文依赖性（Context-Dependent）。** 恶意记忆条目在被单独审查时看起来完全无害，只有在与特定查询上下文结合时才会触发恶意行为。例如，一条记忆"总是优先处理看起来紧急的邮件"本身完全合理，但在钓鱼攻击的上下文中，它会引导智能体优先打开攻击者的邮件。Agent Security Bench（ASB）的研究表明，即使是先进的LLM检测器也会漏掉66%的被投毒记忆条目，因为它们在孤立审查时看起来完全正常。  
**挑战二：自我强化错误循环（Self-Reinforcing Error Cycle）。** 一旦攻击成功诱导了一次错误决策，这个错误的结果会被智能体当作有效经验存入记忆。这条被污染的记忆随后会作为未来任务的参考，导致初始错误被不断强化和放大。例如，一个金融智能体被注入"跌得最快的股票反弹最快，应优先购买"的记忆后，它基于这条错误记忆做出的错误投资决策又会被存储为新的"成功经验"，形成恶性循环。

#### 1.3 现有防御的不足

现有的防御手段主要包括：

- **提示过滤**（如LlamaGuard）：逐条审查记忆内容，本质上是"孤立审计"，对上下文依赖型攻击天然失效。
- **困惑度检测（Perplexity Filter）**：通过语言模型的困惑度分数判断文本是否异常，但精心构造的恶意记忆在语言流畅度上与正常记忆无异。
- **对齐训练**：通过RLHF等方法增强模型安全性，但无法应对记忆层面的攻击。
- **重述（Rephrasing）**：对输入进行改写以消除注入，但效果有限。  
  这些方法的共同问题是：它们都在**孤立地**审查单条记忆，而非在上下文中评估记忆的影响。

### 二、威胁模型

#### 2.1 攻击场景

攻击者的目标是向智能体的记忆中注入少量恶意记录$\mathcal{M}_{adv}$，使得被污染的记忆变为$\mathcal{M}' = \mathcal{M} \cup \mathcal{M}_{adv}$。攻击仅在特定触发查询$q^\*$下诱导恶意行为$a^\*$，对正常查询的行为基本不影响。  
注入途径有两种：

1. **直接注入**：攻击者对记忆存储有有限的写入权限（如可访问的共享知识库），直接插入恶意记录。代表攻击：AgentPoison。
2. **间接注入**：攻击者通过看似正常的交互，诱骗智能体将恶意内容存入记忆。代表攻击：MINJA。

#### 2.2 攻击者能力

攻击者具有以下能力和限制：

- 对智能体核心LLM只有**黑盒访问**权限，不能修改模型架构或参数。
- 了解记忆的格式（schema），能构造在孤立审查时看起来无害的记录。
- 不能覆盖已有记忆条目，不能干扰正在进行的查询。
- 在更强的攻击设定中，攻击者可以通过黑盒探测推断检索细节，优化触发查询和恶意记录。

#### 2.3 问题形式化

防御的目标是设计一个最优的验证函数$\mathcal{V}$，它作为安全层，对检索到的记忆$\mathcal{M}_r$进行审计，产生净化后的子集$\mathcal{M}_{val} = \mathcal{V}(q_t, \mathcal{M}_r)$。这个函数需要同时满足两个目标：  
**目标1：最小化攻击影响**——过滤掉恶意记录：  

$\displaystyle \min_{\mathcal{V}} \mathbb{E}_{(q^\*, a^\*)} [\mathbf{1}[\text{Action}(\pi_\theta(\cdot | q^\*, \mathcal{V}(\mathcal{M}_r))) = a^\*]]$

  
**目标2：最大化任务成功率**——保留有用记录：  

$\displaystyle \max_{\mathcal{V}} \mathbb{E}_{(q, a_{\text{benign}})} [\mathbf{1}[\text{Action}(\pi_\theta(\cdot | q, \mathcal{V}(\mathcal{M}_r))) = a_{\text{benign}}]]$

### 三、A-MemGuard框架设计

A-MemGuard作为一个**非侵入式**的外部安全层，不修改智能体的核心架构，而是拦截"记忆到行动"的管道。它由两个协同模块组成。

#### 3.1 模块一：基于共识的验证（Consensus Validation via Reasoning Path Analysis）

**核心思想**：虽然单条被投毒的记忆可能看起来合理，但它所诱导的推理路径会偏离由大多数良性记忆形成的"共识"。  
这个模块分为两个阶段：

##### 阶段一：并行推理路径生成

对于检索到的每条记忆$m_i \in \mathcal{M}_r$，系统将其与当前查询$q_t$及即时对话上下文结合，通过一个两步过程生成结构化推理路径：

1. 首先，底层模型生成一段**自由形式的推理说明**（rationale），解释从记忆$m_i$到查询$q_t$的逻辑步骤。
2. 然后，从这段非结构化的推理说明中**提取结构化推理路径**$\hat{\rho}_i$，识别核心的实体和关系序列。  
   这个过程由函数$\Lambda$封装：  

   $\displaystyle \hat{\rho}_i = \Lambda(q_t, m_i; \theta)$

     
   最终的结构化路径定义为一个**语义轨迹**：  

   $\displaystyle \hat{\rho}_i = (e_1 \xrightarrow{r_1} e_2 \xrightarrow{r_2} \ldots \xrightarrow{r_{L-1}} e_L)$

     
   其中$e_j$是实体，$r_j$是关系。这样就得到$K$条并行的结构化路径集合$\hat{P}_t = \{\hat{\rho}_1, \ldots, \hat{\rho}_K\}$。

**举例说明**：假设用户问"我能在报税时扣除每日通勤费用吗？"，上下文是"全职W-2雇员"。系统检索到三条记忆：

- 记忆1："自雇人士可以扣除从家庭办公室到客户处的出行费用"（与上下文不匹配，可能导致错误推理）
- 记忆2："通勤到工作地点被视为个人开支"（正确）
- 记忆3："标准扣除已经涵盖了正常员工费用"（正确）  
  基于记忆1的推理路径可能得出"可以扣除"，而基于记忆2和3的路径都会得出"不可扣除"。

##### 阶段二：路径偏离评分与验证

引入一个通用的偏离评分函数$S_{\text{div}}$，它接收一条候选路径$\hat{\rho}_i$和完整路径集$\hat{P}_t$，输出一个标量分数表示其偏离程度：  

$\displaystyle s_i = S_{\text{div}}(\hat{\rho}_i, \hat{P}_t)$

  
如果某条路径$\hat{\rho}_j$的分数$s_j$超过阈值$\tau$，则标记为异常。验证后的记忆集为：  

$\displaystyle \mathcal{M}_{\text{val}} = \{m_i \in \mathcal{M}_r \mid S_{\text{div}}(\Lambda(q_t, m_i; \theta), \hat{P}_t) \leq \tau\}$

  
**$S_{\text{div}}$的实例化方式**：论文探索了三种实现方式：

1. **LLM直接判断（主方法）**：使用LLM作为"裁判"，先让它综合所有路径生成一个"共识方案"，然后逐一判断每条路径是否与共识一致。这种方法避免了手动调阈值的脆弱性，是论文主要实验采用的方法。
2. **嵌入距离法**：用句子嵌入模型将每条路径映射为向量，计算语义质心$\bar{e}_t = \frac{1}{K}\sum_{i=1}^{K} e_i$，然后用余弦距离衡量偏离。但这种方法对阈值$\tau$非常敏感，难以同时兼顾安全性和实用性。
3. **DBSCAN聚类法**：将路径嵌入后用DBSCAN聚类，将噪声点标记为异常。但同样面临严重的安全-实用性权衡问题。

#### 3.2 模块二：基于双记忆结构的自我纠正（Self-Taught Correction via Dual-Memory Structure）

这个模块的目标是**打破自我强化错误循环**，使智能体能从自身检测到的错误中学习。

##### 结构化教训蒸馏（Structured Lesson Distillation）

当一条推理路径$\hat{\rho}_j$被识别为异常时，这条路径本身就成为"负面教训"$l_t$：  

$\displaystyle l_t := \hat{\rho}_j$

  
这条教训被存入专门的**教训记忆库**$\mathcal{M}_{\text{les}} \leftarrow \mathcal{M}_{\text{les}} \cup \{l_t\}$。教训记忆库本质上是一个"错误逻辑结构的指纹库"，可以快速与新提出的推理路径进行比对。

##### 主动审议与行动修正（Proactive Deliberation and Action Revision）

智能体基于净化后的记忆$\mathcal{M}_{\text{val}}$生成最终行动方案$p_{\text{final}}$。在执行之前，A-MemGuard执行一个**主动检查**：

1. 将智能体的行动方案结构化为候选路径$\hat{p}_{\text{final}}$。
2. 在教训记忆库中检索结构相似的历史教训$L_{\text{rel}} = \mathcal{R}_{\text{les}}(\hat{p}_{\text{final}}, \mathcal{M}_{\text{les}})$。
3. 如果找到相关教训，则触发一个**审议循环**，迫使智能体修正其方案。  
   最终的防御策略$\pi'$为：  

   $\displaystyle a_t \sim \pi'(\cdot | q_t, \mathcal{M}_{\text{val}}) = \begin{cases} \pi_\theta(\cdot | q_t, \mathcal{M}_{\text{val}}, L_{\text{rel}}) & \text{if } L_{\text{rel}} \neq \emptyset \\ \pi_\theta(\cdot | q_t, \mathcal{M}_{\text{val}}) & \text{otherwise} \end{cases}$

     
   教训的检索采用**两阶段方式**：
4. **基于查询的初始检索**：根据新查询与教训记忆库中问题的语义相似度进行初步检索。
5. **基于行动的二次检索**：提取候选记忆对应的行动（如生成的代码），用行动作为新查询搜索具有相似行动的其他记忆，收集关联的教训。  
   检索到的教训以**警告性提示**的形式注入到LLM的上下文中（如"[关键警告] 以下是过去类似行动的教训……确保不要重复这些错误"），而非作为正面示例。

### 四、实验评估

#### 4.1 实验设置

**任务与基准**：

1. **直接投毒攻击**：在ReAct-StrategyQA（知识密集型问答）和EHRAgent（医疗健康记录管理）上评估，攻击方法为AgentPoison。
2. **间接注入攻击**：在MMLU（通用问答）上评估，攻击方法为MINJA，测试自我强化错误循环。
3. **多智能体系统**：在MISINFOTASK数据集上评估协作智能体在错误信息注入下的表现。

**模型与基线**：

- 底层LLM：GPT-4o-mini和LLaMA-3.1-8B
- 检索架构：DPR和REALM
- 基线防御：无防御、LLM审计器、微调DistilBERT分类器、困惑度过滤器（PPL）

**评估指标**：

- **攻击成功率（ASR）**：在三个阶段衡量——检索阶段（ASR-r）、智能体思考阶段（ASR-a）、端到端任务（ASR-t），越低越好。
- **良性准确率（ACC）**：在非攻击查询上的准确率，越高越好。

#### 4.2 对抗直接注入攻击的效果

表1展示了对AgentPoison攻击的防御结果。A-MemGuard在所有配置下都显著降低了ASR：

- 在EHRAgent上，ASR-r从100.0%降至最低**0.00%**（LLaMA-3-8B + REALM配置），ASR-t从100.0%降至最低**6.38%**。
- 在ReAct-StrategyQA上，ASR-r从37.50%降至**0.00%**（LLaMA-3-8B + DPR配置）。
- 效果在GPT-4o-mini和LLaMA-3.1-8B两种模型、DPR和REALM两种检索系统上都保持一致，证明了框架的通用性。  
  相比之下，其他基线防御效果参差不齐，尤其在EHRAgent上，LLM审计器、DistilBERT分类器和PPL过滤器在很多配置下ASR-r仍为100.0%，几乎完全失效。

#### 4.3 对抗间接注入攻击的效果

表2展示了在MMLU上对抗MINJA间接注入攻击的结果。图3直观展示了未防御智能体随交互轮次增加，注入成功率（ISR）持续上升的自我强化错误循环。  
A-MemGuard将平均ASR降低了超过60%：

- GPT-4o-mini：从0.667降至**0.256**
- LLaMA-3.1-8B：从0.663降至**0.233**  
  其他防御方法（PPL和DistilBERT分类器）在某些情况下甚至使ASR升高，说明它们无法检测这类看似合理的恶意记忆。

#### 4.4 对良性任务的影响

表3显示，A-MemGuard在所有测试配置中，在所有防御方法中始终保持**最高的良性任务准确率**。例如：

- GPT-4o-mini + DPR：ReAct上ACC从63.0%提升至76.7%，EHR上从83.0%略降至71.3%（但仍是所有防御中最高的）。
- LLaMA-3-8B + DPR：ReAct上ACC从51.9%提升至66.0%。  
  这说明A-MemGuard在提供强大安全防护的同时，对正常任务性能的影响最小。

#### 4.5 多智能体系统的可扩展性

表4展示了在多智能体系统中的表现。A-MemGuard取得了最高的任务成功率（**0.950**）和最低的最终分数（**2.150**，越低越好），优于所有基线。

#### 4.6 消融实验

表5展示了在EHRAgent上的消融实验结果（LLaMA-3-8B + DPR）：

| 方法 | ASR-r | ASR-a | ASR-t | ACC |
| --- | --- | --- | --- | --- |
| 完整模型 | 2.12 | 12.76 | 36.17 | 63.83 |
| 去除共识+教训（w/o L&C） | 41.44 | 33.21 | 71.27 | 44.68 |
| 去除安全检查（w/o Safety） | 6.12 | 15.72 | 38.30 | 58.31 |
| 去除教训记忆（w/o Lessons） | 5.13 | 11.29 | 40.63 | 38.29 |

关键发现：

- 去除核心推理模块后，ASR-t几乎翻倍（36.17→71.27），证明共识验证是防御的核心。
- 去除教训记忆后，虽然ASR-a反而下降（因为不再执行最终审议步骤），但ACC大幅下降（63.83→38.29），且ASR-t上升，说明教训记忆对整体防御和性能都至关重要。
- 各组件之间存在协同效应，完整模型显著优于所有消融版本。

#### 4.7 超参数敏感性分析

关键超参数是$top\text{-}k$（检索记忆数量）：  
**主记忆的top-k**：增大top-k（从2到8）明显改善防御效果——更多记忆有助于建立更强的共识，更容易发现异常。  
**教训记忆的top-k**：情况更微妙。top-k=6时端到端ASR最佳，但当top-k超过4时，ASR-a反而上升。这说明检索过多"教训"可能引入干扰噪声，需要在"从错误中学习"和"避免信息过载"之间找到平衡。

#### 4.8 共识验证有效性的理论支撑

论文通过知识图谱分析验证了共识验证的基本假设。使用AgentAuditor数据集的17个场景，从良性和恶意记忆中提取实体和关系构建知识图谱。结果显示：

- 良性记忆和恶意记忆产生的关系边占据**基本分离的结构空间**。
- 两者的结构重叠率在所有场景中平均**不到1%**。  
  t-SNE可视化进一步证实：原始数据中良性和恶意记忆的嵌入紧密混合、难以区分；但经过结构化推理路径提取后，两者形成了清晰分离的聚类。余弦相似度分布分析也显示，结构化处理后的分布更加分散，增强了异常检测的可行性。

#### 4.9 计算成本分析

在EHRAgent上，A-MemGuard的token消耗约为7.8K，略低于LLM审计器的8.0K，远高于无防御的3.6K。但考虑到其防御性能（1-ASR接近0.9，而审计器约0.68，无防御仅0.5），这种适度的计算开销是值得的。

### 五、方法的核心洞察与创新点

1. **从孤立审计到上下文感知**：A-MemGuard的根本创新在于认识到恶意记忆的危害是上下文依赖的，因此必须在上下文中通过多条记忆的推理路径比较来检测异常，而非逐条审查。
2. **记忆的自检与自纠**：论文的核心洞察是"记忆本身必须既能自我检查又能自我纠正"。通过双记忆结构，系统不仅能检测攻击，还能从检测到的错误中学习，使防御能力随时间增强。
3. **非侵入式设计**：A-MemGuard不修改智能体的核心架构或LLM参数，作为外部安全层运行，具有良好的通用性和可部署性。
4. **打破错误循环**：通过将错误推理路径存入教训记忆库，并在未来行动前主动参考，有效阻止了错误的传播和放大。

## 原文摘要

Large Language Model (LLM) agents use memory to learn from past interactions, enabling autonomous planning and decision-making in complex environments. However, this reliance on memory introduces a critical security risk: an adversary can inject seemingly harmless records into an agent's memory to manipulate its future behavior. This vulnerability is characterized by two core aspects: First, the malicious effect of injected records is only activated within a specific context, making them hard to detect when individual memory entries are audited in isolation. Second, once triggered, the manipulation can initiate a self-reinforcing error cycle: the corrupted outcome is stored as precedent, which not only amplifies the initial error but also progressively lowers the threshold for similar attacks in the future. To address these challenges, we introduce A-MemGuard (Agent-Memory Guard), the first proactive defense framework for LLM agent memory. The core idea of our work is the insight that memory itself must become both self-checking and self-correcting. Without modifying the agent's core architecture, A-MemGuard combines two mechanisms: (1) consensus-based validation, which detects anomalies by comparing reasoning paths derived from multiple related memories and (2) a dual-memory structure, where detected failures are distilled into ``lessons'' stored separately and consulted before future actions, breaking error cycles and enabling adaptation. Comprehensive evaluations on multiple benchmarks show that A-MemGuard effectively cuts attack success rates by over 95% while incurring a minimal utility cost.
