### 论文核心总结

这篇论文提出了 **HaluMem**（Hallucination in Memory Benchmark），这是一个针对AI Agent记忆系统的**操作级（operation-level）幻觉评估基准**。当前的记忆系统（如Mem0、MemOS、Zep等）在存储和检索用户信息时会产生"记忆幻觉"——即捏造、错误、冲突或遗漏信息——但单靠端到端的问答评测，难以定位幻觉究竟出现在记忆系统的哪个操作阶段。HaluMem将评估分解为**记忆抽取、记忆更新、记忆问答**三个阶段，并构建了两个以用户为中心的多轮人机对话数据集（HaluMem-Medium和HaluMem-Long），包含约15k记忆点和3.5k评测问题，上下文长度可达百万token级别。实验表明，现有记忆系统在抽取和更新阶段就会产生并累积幻觉，这些上游幻觉会进一步传播并放大到下游问答阶段，所有系统的问答准确率均未超过70%。

### 一、研究背景与动机

#### 1.1 为什么需要记忆系统？

每次用户与LLM交互时，对话中可能包含用户的个性化信息（如偏好、经历、社交关系等）。但对话结束后，这些信息通常就被"遗忘"了，LLM无法在后续交互中持续理解用户、适应用户变化或生成个性化回复。

为解决这个问题，**记忆系统（Memory System）**应运而生。它作为AI系统的基础设施，负责从多轮对话中**抽取、结构化、持续更新**关键信息，并在需要时检索这些信息注入到模型中，从而支持个性化和长期一致性。

论文介绍了几个代表性的记忆系统：

- **MemOS**：将记忆抽象为系统级资源，统一管理参数记忆、激活记忆和显式文本记忆
- **Mem0**：使用带元数据的纯文本存储，支持创建/更新/删除/扩展操作，有冲突检测和记忆合并机制
- **Zep**：引入时序感知的图结构（Graphiti），整合Agent记忆与Graph RAG
- **Supermemory**：结合文档检索和用户特定记忆，使用上下文图捕捉时间、关系和个人信息
- **Memobase**：聚焦用户级长期记忆，以纯文本结构记录偏好和交互历史

#### 1.2 记忆幻觉问题

尽管这些系统显著提升了记忆的组织性和可控性，但它们普遍受到**记忆幻觉（Memory Hallucination）**的影响。记忆幻觉的表现形式包括：

- **捏造（Fabrication）**：系统凭空生成从未出现在对话中的信息
- **错误（Error）**：抽取的记忆与原始对话内容不一致
- **冲突（Conflict）**：新旧记忆之间存在矛盾未被解决
- **遗漏（Omission）**：应该被记住的重要信息被遗漏

论文图1给出了四个非常直观的例子：

1. **抽取幻觉（来自用户发言）**：用户说"最近我被鹦鹉深深吸引了，让我重新考虑了之前对它们的不喜欢"，系统却抽取为"不喜欢鹦鹉"（正确应该是"喜欢鹦鹉"）
2. **抽取幻觉（来自助手发言）**：助手提到"你的朋友Linda和Mark支持你"，用户纠正为"Linda和Joseph"，但系统记忆了错误的"Mark"
3. **更新幻觉**：助手说"你的健康状况从'低于正常'改善到了'良好'"，用户纠正说"实际上恶化到了'较差'"，但系统仍将更新记为"改善到良好"
4. **问答幻觉**：用户说"我最近被提升为Senior Researcher"，但记忆系统回答时却说"Lead Research Scientist"

#### 1.3 现有评估的局限

现有的记忆系统评估方法（如LoCoMo、LongMemEval、PrefEval、PersonaMem等）都采用**端到端的问答评测范式**：给系统一系列对话和问题，只看最终答案是否正确。这种方式的根本问题在于——当答案错误时，**无法判断幻觉是在哪个操作阶段产生的**：是抽取阶段引入了错误记忆？是更新阶段没有正确修改旧信息？还是问答阶段在正确记忆的基础上生成了虚构内容？

### 二、问题定义

论文用形式化语言定义了记忆系统的操作流程。设记忆系统 $S$ 赋予AI系统 $A$ 长期记忆能力。系统接收用户和助手的多轮对话序列：

$$D = (u_1, a_1), (u_2, a_2), \ldots, (u_N, a_N)$$
其中 $u_i$ 和 $a_i$ 分别是第 $i$ 轮用户和AI的发言。每个记忆点 $m$ 存储为带元数据的纯文本条目。

记忆系统涉及四种操作：

1. **记忆抽取（$E$）**：从对话 $D$ 中提取新的记忆点
2. **记忆更新（$U$）**：修改或删除已有记忆
3. **记忆检索（$R$）**：根据当前查询召回相关记忆
4. **记忆问答（$Q$）**：构建提示并调用AI生成回答

现有的端到端评估可以抽象为：

$$\hat{M} = U(E(D)), \quad \hat{R}_j = R(\hat{M}, q_j), \quad \hat{y}_j = A(\hat{R}_j, q_j)$$
端到端准确率为：

$$\text{Acc}_{\text{e2e}} = \frac{1}{J}\sum_{j=1}^{J} \mathbb{I}[\hat{y}_j = y_j^*]$$
当 $\hat{y}_j \neq y_j^\*$ 时，这个指标**无法定位**错误来源——不知道是 $E$（抽取引入了错误记忆）、$U$（更新时旧记忆被错误修改）还是 $Q$（问答生成了不受支持的内容）。

为实现**可定位的诊断性评估**，HaluMem为每个阶段构建了精细标注和黄金标准：

1. **抽取黄金标准**：$G^{\text{ext}} = \{m_i\}_{i=1}^K$，表示对话中应该被新增的记忆点集合
2. **更新黄金标准**：$G^{\text{upd}} = \{m^{\text{old}} \rightarrow m^{\text{new}}\}$，表示更新前后的记忆点对
3. **问答数据集**：每个查询 $q_j$ 配有黄金答案 $y_j^\*$

### 三、HaluMem数据集构建方法

为了系统地评估记忆系统在真实场景下的表现，论文设计了一个**以用户为中心的六阶段渐进式构建流程**。

#### Stage 1：人设构建（Persona Construction）

为每个虚拟用户创建完整的人设档案，包含三部分：

- **核心档案信息（Core Profile）**：姓名、性别、年龄、出生日期、居住地、教育背景、MBTI性格类型、人生目标、家庭状况等**稳定**的背景特征
- **动态状态信息（Dynamic State）**：职业状态（就业状况、行业、收入、存款）、健康状况（身体/心理健康）、社交关系（朋友、同事等），这些会随时间**演变**
- **偏好信息（Preference）**：每个用户被随机分配6-8个领域的偏好（食物、音乐、电影、宠物、运动等），包括喜欢和不喜欢的具体项目及原因

用户种子从Persona Hub（一个包含10亿多样化人设的数据库）中随机采样，通过规则生成结构化人设草案后由GPT-4o进行验证和精炼。

#### Stage 2：人生骨架（Life Skeleton）

为每个用户定义**演化轨迹**：

- 围绕人生目标设定若干核心**职业事件**，作为动态信息演化的锚点
- 社会地位变化、职业转型、健康状况变化通常与这些职业事件关联
- **偏好信息**则通过概率性修改或删除**独立演化**，不依赖职业事件

人生骨架捕捉用户的潜在未来状态，作为后续记忆增删改的结构化脚本。

#### Stage 3：事件流（Event Flow）

将Stage 2的抽象"人生骨架"转化为**结构化、叙事性的事件流**。包含三类事件：

- **Init Events（初始化事件）**：从用户的初始档案生成，涵盖核心/动态/偏好信息，模拟用户的首次自我介绍
- **Career Events（职业事件）**：从人生骨架中推导，代表用户发展的主线故事，每个职业事件被分为子阶段并填充动态细节（如晋升、生病）
- **Daily Events（日常事件）**：从用户偏好的演变中生成，独立于职业发展。每个偏好变化被转化为具体的生活场景，记录变化前后的状态及原因

三类事件通过时间线整合对齐，形成连贯完整的事件序列，功能类似用户的**记忆事务日志**。

#### Stage 4：会话摘要和记忆点（Session Summaries and Memory Points）

将Stage 3的事件流转化为**真实的会话摘要和详细的记忆点**：

- 为每个事件创建人机对话场景
- 系统可以访问当前人设档案及所有历史事件和记忆点，确保逻辑和因果一致性
- 每个记忆点包括：内容、类型（persona/event/relationship）、重要性、是否为更新、被替换的旧记忆（便于溯源）

#### Stage 5：会话生成（Session Generation）

将结构化信息转化为**完整的多轮对话**。这个阶段有三个关键步骤：

1. **对抗性内容注入**：添加**干扰记忆（distractor memories）**——这是AI在对话中自然提到但用户未确认的虚假但相似的信息，模拟真实场景中的信息污染
2. **多轮对话生成**：生成上下文丰富、目标驱动的完整对话
3. **记忆自验证**：检查并精炼每个记忆点与生成对话的一致性

#### Stage 6：问题生成（Question Generation）

基于前面生成的会话和记忆点，构建**记忆相关的问答对**。预定义六类问题：

1. **基本事实回忆（Basic Fact Recall）**：直接问对话中明确出现的单一事实
2. **多跳推理（Multi-hop Inference）**：需要综合多个信息片段才能得出答案
3. **动态更新（Dynamic Update）**：测试追踪信息随时间变化的能力
4. **记忆边界（Memory Boundary）**：问对话中未提及的信息，测试系统是否会编造答案
5. **泛化与应用（Generalization & Application）**：基于已知偏好推断新场景中的合理建议
6. **记忆冲突（Memory Conflict）**：问题中故意包含与已知记忆点矛盾的错误信息，测试系统能否识别并纠正

每个问答对标注了难度级别和可追溯的证据（指向支持答案的记忆点）。

#### 数据质量验证

对HaluMem-Medium进行了人工标注验证，覆盖700个会话（超50%），8位标注员从正确性、相关性和一致性三个维度评分。结果：正确率95.70%，平均相关性9.58/10，平均一致性9.45/10，为这一抽样范围内的数据质量提供了支持；不能将该验证视为所有样本和自动标签均无误的保证。

#### 最终数据集规模

| 指标 | HaluMem-Medium | HaluMem-Long |
| --- | --- | --- |
| 用户数 | 20 | 20 |
| 总对话轮次 | 30,073 | 53,516 |
| 平均上下文长度/用户 | ~160k tokens | ~1M tokens |
| 总记忆点 | 14,948 | 14,948 |
| 问答对总数 | 3,467 | 3,467 |

HaluMem-Long是在HaluMem-Medium的基础上，通过在会话内和会话间**插入无关对话**（来自ELI5数据集的事实问答、数学推理问答、GPT-4o生成的八领域事实问答）来将上下文扩展到百万token级别，用于测试超长上下文下的鲁棒性。

### 四、评估框架

#### 评估流程

对于每个用户，按时间顺序将对话会话 $D^1, D^2, \ldots, D^S$ 依次输入记忆系统 $S$。如果当前会话包含参考记忆点或QA任务，在系统处理完该会话后**立即触发**对应的评估（抽取/更新/问答）并记录结果。处理完所有会话后，汇总三类任务的指标。

评估要求记忆系统提供三种API接口：

1. **Add Dialogue API**：输入对话并自动执行记忆抽取
2. **Get Dialogue Memory API**：检索系统从指定会话中抽取的记忆点
3. **Retrieve Memory API**：根据查询检索用户最相关的记忆内容

#### 4.1 记忆抽取评估

评估系统能否正确识别和存储对话中的关键信息，同时避免捏造或无关记忆。

**记忆完整性（抗遗忘）**：

$$\text{Memory Recall} = \frac{N_{\text{correct}}}{N_{\text{should}}}$$
$$\text{Weighted Memory Recall} = \frac{\sum_{i=1}^{N_{\text{should}}} w_i \cdot s_i}{\sum_{i=1}^{N_{\text{should}}} w_i}$$
其中 $N_{\text{should}} = |G_s^{\text{ext}}|$ 是应该被抽取的记忆数量，$w_i$ 是第 $i$ 个记忆的重要性权重，$s_i \in \{1, 0.5, 0\}$ 表示抽取得分（完全抽取/部分抽取/遗漏）。

**记忆准确性（抗幻觉）**：

$$\text{Memory Accuracy} = \frac{\sum_{j=1}^{N_{\text{extract}}} s_j}{N_{\text{extract}}}$$
$$\text{Target Memory Precision} = \frac{\sum_{j \in M_T} s_j}{|M_T|}$$
其中 $N_{\text{extract}}$ 是系统实际抽取的记忆总数，$M_T$ 是与参考记忆匹配的目标记忆子集。

**虚假记忆抵抗率（FMR）**：

$$\text{FMR} = \frac{N_{\text{miss}}}{N_D}$$
其中 $N_D$ 是干扰记忆总数，$N_{\text{miss}}$ 是系统成功忽略的干扰数量，越高越好。

**记忆抽取F1**：

$$\text{F1}_{\text{mem}} = \frac{2 \cdot R_{\text{mem}} \cdot P_{\text{tgt}}}{R_{\text{mem}} + P_{\text{tgt}}}$$
#### 4.2 记忆更新评估

评估系统在新对话中能否正确修改、合并或替换已有记忆，典型的更新幻觉包括：错误修改旧信息、遗漏新信息、版本冲突。

$$\text{Updating Accuracy} = \frac{N_{\text{correct-upd}}}{N_{\text{target-upd}}}$$
$$\text{Updating Hallucination Rate} = \frac{N_{\text{wrong-upd}}}{N_{\text{target-upd}}}$$
$$\text{Updating Omission Rate} = \frac{N_{\text{missed-upd}}}{N_{\text{target-upd}}}$$
#### 4.3 记忆问答评估

评估端到端性能，系统用Retrieve Memory API获取相关记忆，与问题一起传入AI系统生成答案，与参考答案比较：

$$\text{QA Accuracy} = \frac{N_{\text{correct-qa}}}{N_{\text{total-qa}}}$$
$$\text{QA Hallucination Rate} = \frac{N_{\text{wrong-qa}}}{N_{\text{total-qa}}}$$
$$\text{QA Omission Rate} = \frac{N_{\text{missed-qa}}}{N_{\text{total-qa}}}$$
所有评估中的一致性判断和打分均由**GPT-4o**自动完成，论文设计了详细的prompt模板。

### 五、实验结果

#### 5.1 总体评估

论文评估了六个记忆系统：Mem0、Mem0-Graph、Memobase、MemOS、Supermemory、Zep（Zep因不提供Get Dialogue Memory API，无法评估抽取任务）。

**关键发现（记忆抽取）**：

- 除MemOS外，所有系统的**Recall都低于60%**，意味着大量应被记住的信息被遗漏
- **Weighted Recall高于普通Recall**，说明系统能优先抽取重要的记忆点
- 所有系统的**Accuracy低于62%**，反映了幻觉比例很高
- MemOS和Supermemory的**FMR最差**，因为它们倾向于抽取大量信息却不能有效过滤干扰内容
- 在HaluMem-Long上，Mem0系列和Memobase的抽取记忆数量**大幅下降**，而MemOS和Supermemory则相反

**关键发现（记忆更新）**：

- 大多数系统表现很差，**遗漏率超过50%**
- 主要原因是**上游抽取覆盖不足**：当更新前的旧记忆没有被抽取时，相关的更新自然无法被正确处理
- 所有系统的幻觉率低于2%，但这并不意味着幻觉抑制能力强——因为很少有样本真正进入更新阶段

**关键发现（记忆问答）**：

- 最好的系统也是在记忆完整性和更新方面表现较好的系统，进一步印证了**记忆抽取是关键瓶颈**
- 所有系统的问答准确率均**低于70%**，幻觉率和遗漏率都很高
- 在HaluMem-Long上性能进一步下降

#### 5.2 不同记忆类型的表现

三种记忆类型（事件、人设、关系）中，**人设记忆的准确率略高**，因为静态个人特征更容易捕捉，而事件动态和关系变化仍然很具挑战性。MemOS在所有类型上表现最好。在长上下文场景下，Mem0系列和Memobase出现明显下降。

#### 5.3 不同问题类型的表现

所有记忆系统在**记忆边界和记忆冲突**问题上表现相对较好，说明它们有一定识别未知或误导信息的能力。但在**多跳推理、动态更新、泛化与应用**问题上表现明显更差，表明当前系统在复杂推理和偏好追踪方面仍有很大不足。

#### 5.4 效率分析

- **对话添加（写入）阶段是主要的计算瓶颈**，耗时远超记忆检索
- 在HaluMem-Medium上，Supermemory在对话添加和总运行时间上表现最好，MemOS检索效率最高
- Mem0和Mem0-Graph的对话添加时间超过2700分钟，处理效率很低
- 在HaluMem-Long上，Mem0系列和Memobase的时间反而减少，主要因为它们处理的记忆点数量减少了（而非性能提升）

### 六、核心贡献与结论

#### 核心贡献

1. 提出**操作级别的记忆幻觉评估基准HaluMem**，克服了端到端评估方法的局限，能够系统性地揭示记忆抽取、更新和问答三个维度的幻觉现象
2. 构建了大规模多轮人机交互评估数据集（HaluMem-Medium和HaluMem-Long），支持不同上下文规模和任务复杂度下的幻觉评估
3. 通过分阶段评估，揭示了幻觉在记忆抽取→更新→问答各阶段的**累积和放大效应**

#### 主要结论

- 现有记忆系统在**抽取和更新阶段就会产生和累积幻觉**，这些上游幻觉随后**传播并放大**到问答阶段
- 抽取阶段是整个系统的关键瓶颈——抽取的覆盖率和准确率直接决定了更新和问答的上限
- 未来研究应聚焦于开发**可解释和约束性的记忆操作机制**，系统性地抑制幻觉、提高记忆可靠性
- 需要在记忆覆盖率、抽取准确率、抗干扰能力之间取得平衡
- 提升记忆抽取和更新的**效率**对改善交互性能至关重要

## 原文摘要

Memory systems are key components that enable AI systems such as LLMs and AI agents to achieve long-term learning and sustained interaction. However, during memory storage and retrieval, these systems frequently exhibit memory hallucinations, including fabrication, errors, conflicts, and omissions. Existing evaluations of memory hallucinations are primarily end-to-end question answering, which makes it difficult to localize the operational stage within the memory system where hallucinations arise. To address this, we introduce the Hallucination in Memory Benchmark (HaluMem), the first operation level hallucination evaluation benchmark tailored to memory systems. HaluMem defines three evaluation tasks (memory extraction, memory updating, and memory question answering) to comprehensively reveal hallucination behaviors across different operational stages of interaction. To support evaluation, we construct user-centric, multi-turn human-AI interaction datasets, HaluMem-Medium and HaluMem-Long. Both include about 15k memory points and 3.5k multi-type questions. The average dialogue length per user reaches 1.5k and 2.6k turns, with context lengths exceeding 1M tokens, enabling evaluation of hallucinations across different context scales and task complexities. Empirical studies based on HaluMem show that existing memory systems tend to generate and accumulate hallucinations during the extraction and updating stages, which subsequently propagate errors to the question answering stage. Future research should focus on developing interpretable and constrained memory operation mechanisms that systematically suppress hallucinations and improve memory reliability.
