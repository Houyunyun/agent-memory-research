# Evo-Memory: Benchmarking LLM Agent Test-time Learning with Self-Evolving Memory

Wei, Tianxin, Sachdeva, Noveen, Coleman, Benjamin, He, Zhankui, Bei, Yuanchen, Ning, Xuying, Ai, Mengting, Li, Yunzhe, He, Jingrui, Chi, Ed H., Wang, Chi, Chen, Shuo, Pereira, Fernando, Kang, Wang-Cheng, Cheng, Derek Zhiyuan · 2025

## 核心机制

流式任务中的经验检索、更新与复用，含 ExpRAG/ReMem

## 详细解读

这篇论文提出了**Evo-Memory**，一个用于评估LLM智能体（agent）在部署阶段（test-time）通过"自演化记忆"（self-evolving memory）进行持续学习的综合性流式基准测试和框架。核心思想是：现有的LLM记忆系统大多是静态的，只能被动地从对话历史中检索事实来回答问题（即"对话回忆"），但无法从过去的交互经验中抽象出可复用的推理策略来改进未来的决策（即"经验复用"）。Evo-Memory将传统静态数据集重构为顺序任务流，要求LLM在每次交互后检索、整合和更新记忆，并统一实现了十余种代表性记忆模块，在10个多样化的数据集上进行评估。论文还提出了两个方法：ExpRAG（一个简单的经验检索聚合基线）和ReMem（一个将推理、行动和记忆精炼紧密结合的action–think–memory refine流水线），用于实现持续改进。

### 一、问题动机与核心区分

#### 1.1 对话回忆 vs. 经验复用

论文开篇就做了一个关键区分（Figure 1a）：

- **对话回忆（Conversational Recall）**：记住"说了什么"。比如你之前问过 $2x^2 + 3x - 1 = 0$ 的解是什么，记忆系统能回忆起答案是 $x = -2, 0.5$。这是一种"What"层面的记忆。
- **经验复用（Experience Reuse）**：记住"怎么做的"。比如记住解二次方程应该用求根公式 $\frac{-b \pm \sqrt{b^2 - 4ac}}{2a}$，这样遇到新的二次方程时可以直接复用这个策略。这是"How"层面的记忆。  
  现有的LLM记忆评估基本都停留在对话回忆层面，而忽略了经验复用这个更重要的能力。

#### 1.2 现有工作的不足

论文指出几个已有基准的局限：

- **StreamBench**：评估顺序学习，但主要测量事实保留，不涉及推理或轨迹复用。
- **LifelongBench**：研究终身学习，但关注的是保留能力而非记忆结构或更新机制。
- 其他工作评估长期对话一致性，但不测试agent如何在部署过程中演化其记忆。  
  总之，缺乏一个统一框架来评估不同记忆方法如何在真实流式场景中检索、整合和演化历史策略。

### 二、问题形式化

#### 2.1 记忆增强智能体的抽象

论文将一个通用的记忆增强智能体形式化为一个四元组 $(\mathrm{F}, \mathrm{U}, \mathrm{R}, \mathrm{C})$：

- $\mathrm{F}$：基础LLM
- $\mathrm{U}$：记忆更新管道
- $\mathrm{R}$：检索模块
- $\mathrm{C}$：上下文构造机制（将检索到的内容转化为最终的工作上下文）  
  智能体处理一个输入序列 $\{x_1, x_2, \ldots, x_T\}$，记忆状态 $M_t$ 随历史演化。在时间步 $t$，智能体接收输入 $x_t$，维护演化记忆 $M_t$，检索相关元素 $\mathrm{R}(M_t, x_t)$，构造上下文化的提示：  

  $\displaystyle C_t = \mathrm{C}(x_t, \mathrm{R}(M_t, x_t))$

    
  然后产生输出：  

  $\displaystyle \hat{y}_t = \mathrm{F}(C_t)$

#### 2.2 搜索-合成-演化循环

这个抽象统一了从RAG到动态/层次化/工作流记忆的各种机制，核心是三个步骤的迭代循环：  
**搜索（Search）**：给定当前输入 $x_t$，检索相关记忆条目：  

$\displaystyle R_t = \mathrm{R}(M_t, x_t)$

  
其中 $\mathrm{R}$ 可以是相似性搜索、索引查找或对存储嵌入的注意力机制。  
**合成（Synthesis）**：将检索到的信息 $R_t$ 重组为适合当前输入的工作上下文。可能涉及构建结构化提示、选择关键记忆项或将检索内容合并为摘要：  

$\displaystyle \tilde{C}_t = \mathrm{C}(x_t, R_t), \quad \hat{y}_t = \mathrm{F}(\tilde{C}_t)$

  
**演化（Evolve）**：获得 $\hat{y}_t$ 后，构造新的记忆条目 $m_t = h(x_t, \hat{y}_t, f_t)$，其中 $f_t$ 是反馈信号（如任务是否完成），然后更新记忆：  

$\displaystyle M_{t+1} = \mathrm{U}(M_t, m_t)$

  
不同算法以不同方式实例化 $\mathrm{U}$：直接追加（检索型记忆）、摘要/压缩（长期存储）、替换（有限容量存储）等。

#### 2.3 数据集准备

Evo-Memory将传统静态数据集重构为**流式任务序列**。每个数据集被转化为序列 $\tau = \{(x_1, y_1), \ldots, (x_T, y_T)\}$，形成一个ground-truth轨迹，其中早期任务为后续任务提供关键信息或策略。在每一步 $t$，智能体处理输入 $x_t$，检索和合成记忆，产生预测 $\hat{y}_t$，并更新记忆状态 $M_t$，得到预测轨迹：  

$\displaystyle (x_1, \hat{y}_1, M_1) \rightarrow (x_2, \hat{y}_2, M_2) \rightarrow \cdots \rightarrow (x_T, \hat{y}_T, M_T)$

### 三、提出的方法

#### 3.1 ExpRAG：经验检索与聚合

ExpRAG是一个简单的任务级检索增强基线。每个记忆条目 $m_i = S(x_i, \hat{y}_i, f_i)$ 用模板 $S$ 编码为结构化经验文本。在步骤 $t$，智能体根据检索分数 $\phi$ 从记忆中检索 $k$ 个最相似的经验：  

$\displaystyle R_t = \text{Top-}k_{m_i \in M_t} \phi(x_t, m_i)$

  
模型基于这些检索到的示例进行上下文学习（in-context learning）：  

$\displaystyle \hat{y}_t = \mathrm{F}(x_t, R_t)$

  
然后将新经验追加到记忆：  

$\displaystyle M_{t+1} = M_t \cup \{(x_t, \hat{y}_t, f_t)\}$

  
ExpRAG的特点是**一次性经验复用**——通过检索和聚合实现，但缺乏迭代推理或自适应精炼。它本质上是in-context learning的记忆扩展版本。

#### 3.2 ReMem：推理、行动与记忆的协同

ReMem是论文提出的核心方法，一个将推理（reasoning）、行动（action）和记忆精炼（memory refinement）统一在单一决策循环中的框架。与传统的ReAct风格方法将记忆视为静态上下文不同，ReMem引入了第三个维度——**记忆推理（memory reasoning）**，允许智能体在问题求解过程中主动评估、重组和演化自己的记忆。  
在每一步 $t$，给定当前输入 $x_t$、记忆状态 $M_t$ 和之前的推理轨迹 $o_t^{1:n-1}$，智能体选择以下操作之一：  

$\displaystyle a_t^n \in \{\text{Think}, \text{Act}, \text{Refine}\}$

  
然后执行操作并转移：  

$\displaystyle o_t^n = \text{Agent}(x_t, M_t, a_t^n)$

  
三种操作的含义：

- **Think**：产生内部推理轨迹，帮助分解任务并指导后续行动。
- **Act**：在环境中执行操作或输出用户可见的响应。
- **Refine**：对记忆进行元推理——利用有用经验、修剪噪声、重组 $M_t$，以更好地支持未来的推理和行动。  
  在每一步内，智能体可以执行多轮Think和Refine，一旦选择Act操作，该步骤终止。这诱导了一个**马尔可夫决策过程**，其中步骤 $t$ 经过 $n$ 次操作后的状态为：  

  $\displaystyle s_t^n = (x_t, M_t, o_t^{1:n-1})$

    
  动作空间为 $\{\text{Think}, \text{Act}, \text{Refine}\}$，转移动态由Agent算子和环境响应给出。  
  ReMem的关键创新在于扩展了ReAct风格智能体的动作空间，引入了显式的记忆推理机制。通过这种扩展，记忆成为一个与推理实时交互的自适应组件，而不是被动的上下文。

### 四、实验设置

#### 4.1 数据集

Evo-Memory在涵盖多种能力的10个数据集上进行评估：  
**单轮推理和QA任务**：

- **MMLU-Pro**：多学科推理（工程、经济、哲学等子领域）
- **GPQA-Diamond**：研究生级别的科学推理
- **AIME-24/25**：奥林匹克数学竞赛题
- **ToolBench**：工具使用和API调用

**多轮目标导向任务**：

- **AlfWorld**：文本化的家庭任务环境
- **BabyAI**：网格导航和物体操作
- **ScienceWorld**：交互式科学实验
- **PDDL**：符号规划任务  
  所有方法在相同的搜索-预测-演化循环下评估：  

  $\displaystyle (x_t, M_t) \xrightarrow{\text{search}} R_t \xrightarrow{\text{synthesis}} \hat{y}_t \xrightarrow{\text{evolve}} M_{t+1}$

#### 4.2 对比方法

论文将评估的方法分为四类：

1. **无过程记忆的Agent管道**：ReAct、Amem
2. **自适应Agent记忆方法**：SelfRAG、MemOS、Mem0、LangMem
3. **基于过程知识的记忆Agent**：Dynamic Cheatsheet（DC-Cu和DC-RS两个变体）、Agent Workflow Memory（AWM）
4. **提出的演化记忆框架**：ExpRecent、ExpRAG、ReMem  
   所有方法在两个强LLM骨干上实例化：**Gemini-2.5系列**（Flash、Flash-Lite、Pro）和**Claude系列**（3.5-Haiku、3.7-Sonnet）。

#### 4.3 评估维度

- **答案准确率**：LLM是否产生正确输出
- **成功率（S）**：Agent是否成功完成任务目标
- **进度率（P）**：任务完成的进度
- **步骤效率**：完成目标所需的步数
- **序列鲁棒性**：在不同任务顺序下是否保持一致性能

### 五、实验结果

#### 5.1 RQ1：整体性能

**单轮任务**（Table 1a）：演化记忆方法显示出一致的改进。ReMem在Gemini-2.5 Flash上达到0.65的平均精确匹配和0.85/0.71的API准确率。ExpRAG作为简单基线，表现出色，超越了多个更复杂的设计。单轮场景下的改进幅度相对温和。  
**多轮任务**（Table 1b）：ReMem和ExpRAG在两个骨干上都取得了强劲且稳定的性能。特别值得注意的是，在Claude 3.7 Sonnet上，ReMem在AlfWorld达到0.92/0.96（成功率/进度率），在PDDL达到0.83/0.95，在ScienceWorld达到0.62/0.89。多轮场景下的性能提升**明显大于**单轮场景，说明随着任务视野的延长，持续适应变得越来越有价值。

#### 5.2 RQ2：记忆改进的影响因素

**任务相似性的影响**（Figure 3）：ReMem的改进与数据集内任务相似性强相关（Gemini 2.5 Flash上Pearson $r = 0.717$，Claude 3.7 Sonnet上 $r = 0.563$）。任务相似性通过计算每个任务嵌入与其数据集聚类中心的平均余弦距离来衡量。PDDL和AlfWorld等具有较高嵌入聚类比率的任务产生更大的增益，说明重复出现的任务结构有助于记忆复用和泛化。而AIME-25或GPQA等多样性较高的数据集增益较小。  
**步骤效率**（Figure 4）：演化记忆方法一致地需要更少的步骤。ReMem实现了最大且最稳定的减少（如在AlfWorld上从22.6步降到11.5步）。

#### 5.3 RQ3：任务序列难度的影响

Table 2比较了Easy→Hard和Hard→Easy两种任务排列方向下的性能。基线方法在不同序列下表现差异大，鲁棒性有限。而ReMem在两个方向上都保持强劲一致的性能，在Hard→Easy设置下达到0.94/0.97。有趣的是，Hard→Easy方向的性能更好，这暗示**从更难任务中获得的成功经验更具可迁移性**。

#### 5.4 RQ4：反馈类型的影响

Table 3评估了当成功和失败经验都存入记忆时的表现。基线方法在未过滤失败经验下性能明显下降，说明朴素的记忆积累会引入噪声并妨碍检索。而ReMem通过主动精炼存储的经验保持鲁棒，在两个骨干上都取得最佳的成功率和进度率。这突显了选择性利用和记忆精炼对稳定测试时适应的重要性。

### 六、附加分析

#### 6.1 记忆修剪率

Figure 5展示了不同数据集上的记忆修剪率。领域覆盖范围更广的数据集（如GPQA，涵盖工程、物理等多领域）表现出更高的修剪率（36.8%），说明更多记忆在异构任务间被认为是冗余的。而问题类型更集中的数据集（如AIME）修剪率更低（17.5%和10.8%），因为更高的任务相似性使记忆保持相关性。

#### 6.2 累积准确率曲线

Figure 6和7展示了随任务序列推进的累积准确率曲线。在所有环境中，ReMem表现出更快的适应和更稳定的保持。在初始的"冷启动"阶段，History基线表现相当，但随着更多任务被处理，ReMem迅速超越，体现了持续任务级适应的累积优势。

#### 6.3 跨模型泛化

附录中的Table 4和5展示了在更多模型（Gemini-2.5-Flash-Lite、Gemini-2.5-Pro、Claude-3.5-Haiku）上的结果。性能趋势在所有设置下保持一致，确认了演化记忆架构的优势是**模型无关的**。值得注意的是，**较小的模型从中受益最大**，说明测试时精炼也是增强轻量级LLM的有效方式。

### 七、总结与启示

论文的核心发现包括：

1. **自演化记忆能持续提升性能**，但在稳定性和过程知识复用方面仍然脆弱。
2. **多轮任务的改进远大于单轮任务**，说明持续适应在长视野任务中价值更大。
3. **记忆改进与任务相似性正相关**——结构重复的任务更容易从记忆复用中获益。
4. **简单的经验检索（ExpRAG）已经是非常有效的基线**，超越了许多更复杂的设计，说明显式的任务级经验利用是一个有前景但尚未充分探索的方向。
5. **ReMem通过将记忆推理引入决策循环**，实现了最佳的整体性能，特别是在多轮交互环境中。
6. **失败经验的处理很重要**——朴素积累会引入噪声，需要选择性利用和主动精炼。

## 原文摘要

Statefulness is essential for large language model (LLM) agents to perform long-term planning and problem-solving. This makes memory a critical component, yet its management and evolution remain largely underexplored. Existing evaluations mostly focus on static conversational settings, where memory is passively retrieved from dialogue to answer queries, overlooking the dynamic ability to accumulate and reuse experience across evolving task streams. In real-world environments such as interactive problem assistants or embodied agents, LLMs are required to handle continuous task streams, yet often fail to learn from accumulated interactions, losing valuable contextual insights, a limitation that calls for test-time evolution, where LLMs retrieve, integrate, and update memory continuously during deployment. To bridge this gap, we introduce Evo-Memory, a comprehensive streaming benchmark and framework for evaluating self-evolving memory in LLM agents. Evo-Memory structures datasets into sequential task streams, requiring LLMs to search, adapt, and evolve memory after each interaction. We unify and implement over ten representative memory modules and evaluate them across 10 diverse multi-turn goal-oriented and single-turn reasoning and QA datasets. To better benchmark experience reuse, we provide a baseline method, ExpRAG, for retrieving and utilizing prior experience, and further propose ReMem, an action-think-memory refine pipeline that tightly integrates reasoning, task actions, and memory updates to achieve continual improvement.
