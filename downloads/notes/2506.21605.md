# MemBench: Towards More Comprehensive Evaluation on the Memory of LLM-based Agents

Tan, Haoran, Zhang, Zeyu, Ma, Chen, Chen, Xu, Dai, Quanyu, Dong, Zhenhua · 2025

[论文原文](https://arxiv.org/abs/2506.21605)

## 核心机制

事实/反思记忆、参与/观察场景与多维指标

## 适用范围与局限

能力维度丰富不代表覆盖全部 Agent 行动场景

## 详细解读

### 论文核心总结

这篇论文提出了一个名为**MemBench**的综合性基准测试，用于评估基于大语言模型（LLM）的智能体（Agent）的记忆能力。作者指出，现有的记忆评估工作存在三个主要不足：（1）只关注事实记忆（factual memory），忽略了反思记忆（reflective memory）；（2）只考虑参与场景（participation scenario），忽略了观察场景（observation scenario）；（3）评估指标单一，仅关注记忆的有效性，而忽略了效率和容量。为此，论文构建了一个多场景、多层次的数据集，并设计了包含准确率、召回率、容量和时间效率在内的多维度评估体系，在此基础上对七种主流记忆机制进行了系统性评测。

### 一、研究背景与动机

#### 1.1 LLM-based Agent 的记忆模块

大语言模型虽然在自然语言处理方面表现出色，但原始的LLM通常在静态场景下工作，无法与外部环境交互。为了弥补这一不足，研究者们为LLM增加了额外模块（如规划模块、工具使用模块等），构建了所谓的"LLM-based Agent"。其中，**记忆模块**是核心组件之一，它负责保存关键信息、积累经验，使智能体能够在动态任务中持续进化。

#### 1.2 现有评估方法的不足

论文总结了现有记忆评估的三个主要局限：  
**第一，记忆层次单一。** 现有工作主要评估**事实记忆**（Factual Memory），即对话中明确提到的信息，例如"我喜欢《星球大战》这部电影"。但忽略了**反思记忆**（Reflective Memory），即需要从多个低层事实中归纳总结出的高层信息，例如从用户提到的多个具体菜品中推断出用户偏好"甜咸口味"。  
**第二，交互场景单一。** 现有数据集几乎都只考虑**参与场景**（Participation Scenario），即智能体以第一人称与用户对话交互。但在实际使用中，还存在**观察场景**（Observation Scenario），即智能体作为旁观者被动接收用户的消息流，不进行交互。这两种场景对记忆机制的要求不同——参与场景中智能体需要同时记住用户的话和自己的回复，而观察场景中只需记住用户的消息。  
**第三，评估指标单一。** 现有工作通常只关注记忆的准确性（effectiveness），而忽略了效率（efficiency，即读写记忆的时间开销）和容量（capacity，即记忆内容增长到什么程度时性能会急剧下降）。  
Table 1 对比了MemBench与已有数据集（PerLTQA、LoCoMo、LongMemEval）的差异：MemBench是唯一同时支持参与和观察两种场景、同时包含事实记忆和反思记忆、并且包含用户画像（profiles）的数据集。

### 二、数据集构建

#### 2.1 数据生成流程

数据集的构建受到MemSim框架的启发，整体流程如Figure 1所示，分为以下几个步骤：

##### 用户关系图采样（User's Relation Graph Sampling）

首先为每个用户构建一个**关系图**（如Figure 2所示），包含：

- 用户自身的画像（姓名、年龄、生日、职业、爱好等）
- 关联实体：包括**个人关系**（兄弟、姐妹、老板、同事等）、**事件**（工作活动、社区活动等）、**物品**（拥有的商品）、**地点**（去过的地方）  
  对于反思记忆所需的**高层偏好属性**，作者利用了三个推荐系统数据集（MovieLens、Food、Goodreads）中的用户-物品交互数据。具体做法是：找出每个用户正面评价最多的物品类别，提取其高层偏好（如电影类型偏好"喜剧"、口味偏好"甜咸"等）。如果数据集中没有类别信息，则用GPT-4o-mini来总结。然后通过随机匹配或基于相同属性的匹配，将高层偏好属性分配给构建的虚拟用户。  
  同时，作者构建了三个**一对多映射字典**，将高层偏好映射到多个低层事实属性。例如，"Action"类型的电影偏好映射到一系列具体的动作片名称（如Star Wars、Godfather等）。

##### 记忆数据集构建（Memory Dataset Construction）

基于用户关系图，生成对话数据的过程如下：

1. **生成证据对话（Evidence Dialogues）**：从用户关系图中采样属性，生成包含关键信息的对话片段。例如，选取事件"Build Start 2024"的时间属性"next week Mon 7:00 PM"，生成用户提到这个事件的对话。
2. **生成填充对话**：为了让对话更自然流畅，在关键证据对话之间插入基于其他属性生成的多轮对话。
3. **组装完整会话（Session）**：将证据对话嵌入到由其他属性生成的多轮对话中，形成完整的会话。
4. **时间戳分配**：采用基于时间的会话划分方法。同一会话内的对话轮次之间时间间隔很短（如一分钟），不同会话之间的时间间隔较长（如一天）。这使得时间推理类问题成为可能——例如用户说"下周一"，系统需要根据对话发生的时间戳推算出具体日期。
5. **生成问答对**：基于采样的属性和生成的对话，创建问题和标准答案。

#### 2.2 多场景记忆

**参与记忆场景（Participation Memory Scenario）**：数据形式为用户与智能体之间的多轮对话。智能体不仅需要记住用户说的话，还需要记住自己的回复（例如智能体推荐了什么电影）。为了消除智能体其他模块（如推理模块）对记忆评估的干扰，作者预定义了智能体的回复内容。数据由多个会话（session）组成，每个会话包含多轮对话（turns）。  
**观察记忆场景（Observation Memory Scenario）**：数据形式为用户单方面输入的消息流。智能体被动接收这些消息，不进行交互。这个场景聚焦于智能体作为观察者的角色，只需要记住用户表达的信息。数据由消息列表组成。  
两种场景的关键区别在于：参与场景中智能体的其他模块（如推理模块）会影响记忆模块，而观察场景中不会。

#### 2.3 多层次记忆

##### 事实记忆（Factual Memory）

事实记忆指的是用户或其关联实体的具体事实属性，如亲属的年龄、职业、事件的时间细节等。论文设计了多种问题类型来测试不同的事实记忆能力（如Table 6和Figure 3所示）：

- **Single-hop（单跳）**：依赖单条消息直接回答。例如"我侄女的公司叫什么？"
- **Multi-hop（多跳）**：需要联合多条消息回答。例如需要先知道"我姐姐叫Amelia Brooks"，再知道"我姐姐的生日是12月11日"，才能回答"Amelia Brooks的生日是什么？"
- **Comparative（比较）**：比较两个实体在某个共同属性上的差异。例如"Clara Jennings和Landon Pierce谁更大？"
- **Aggregative（聚合）**：聚合多个实体在某个共同属性上的信息。例如"有多少人住在Philadelphia, PA？"需要遍历所有提到的人物的家乡。
- **Post-processing（后处理）**：需要额外的推理步骤。例如给出邮箱地址，问这个邮箱对应的人的爱好是什么——需要先找到邮箱对应的人，再找到这个人的爱好。
- **Knowledge-updating（知识更新）**：同一属性在不同时间被更新。例如用户先说"Policing Forum持续四天"，后来又更正为"只持续一天"。
- **Single-session-assistant（单会话助手）**：需要记住智能体在单个会话中的回复。
- **Multi-session-assistant（多会话助手）**：需要记住智能体在多个会话中的回复。

##### 反思记忆（Reflective Memory）

反思记忆指的是从用户对低层偏好的多次表达中提取和总结出的高层偏好。例如，用户在多次对话中提到喜欢"Prosciutto and Melon"、"Salted Maple Ice Cream"、"Pecan Praline"、"Salted Butter Toffee"等菜品，智能体需要从这些具体菜品中归纳出用户偏好"Sweet and Salty"口味。  
反思记忆包含两个子类型（Table 7）：

- **Preference（偏好）**：依赖多条消息中用户主动表达的低层偏好来推断高层偏好。
- **Emotion（情绪）**：依赖特定时间段内的多条连续消息来推断用户的情绪状态。  
  为了增强答案的可信度，反思记忆的内容通过用户多次表达不同的具体偏好来强化。

#### 2.4 多指标评估

论文提出四个评估指标：  
**Memory Accuracy（记忆准确率）**：为避免智能体灵活表达导致的误判，所有问题设计为选择题。智能体完成记忆过程后，将问题和选项提交给智能体，通过比较其选择与正确答案来计算准确率。  
**Memory Recall（记忆召回率）**：针对基于检索的记忆机制，衡量检索的准确性。由于在数据生成过程中已经标记了回答问题所需的关键证据对话，因此可以计算检索的召回率（Recall@10）。  
**Memory Capacity（记忆容量）**：探索记忆机制是否存在容量上限——即当记忆内容达到某个量级时，准确率是否会急剧下降。这个临界阈值代表了记忆的容量。  
**Memory Efficiency（记忆效率）**：衡量记忆机制在读取和写入每轮消息时的时间开销。某些记忆机制可能导致过高的处理时间，在实际应用中不可接受。

#### 2.5 数据集统计

数据集包含：

- 500个用户关系图
- 多组用户-助手对话、用户消息和对应的问题  
  Table 2展示了详细统计：
- PS-RM（参与场景-反思记忆）：3.5k会话，3.5k问题，平均每条轨迹2,195 tokens
- PS-FM（参与场景-事实记忆）：51k会话，39k问题，平均每条轨迹10,285 tokens
- OS-RM（观察场景-反思记忆）：2k会话，2k问题，平均每条轨迹745 tokens
- OS-FM（观察场景-事实记忆）：8.5k会话，8.5k问题，平均每条轨迹617 tokens  
  Figure 4(c)显示，关键证据对话在会话中的位置分布近似均匀，模拟了真实世界中答案信息可能出现在对话任何位置的情况。

### 三、基准测试（Benchmark）

#### 3.1 实验设置

为了更贴合智能体在真实场景中的记忆过程，论文模拟了用户与智能体的交互流程：在时间$t$，输入用户第$t$轮的发言，而之前$t-1$轮及更早的内容只能通过记忆机制来回忆。  
**难度控制**：使用News数据集生成大量与问题无关的噪声对话/消息，随机插入到相邻会话之间。通过控制噪声比例，创建不同难度的测试集。论文构建了两个子数据集：

- **Sub-dataset 1（普通规模）**：每个测试约10K tokens（参与场景）或1K tokens（观察场景）
- **Sub-dataset 2（100k规模）**：每个测试约100K tokens（参与场景）或10K tokens（观察场景）

**测试的记忆机制**：基于MemEngine框架，使用Qwen2.5-7B作为基础模型，实现了七种记忆机制：

1. **FullMemory**：将所有历史信息放入上下文窗口
2. **RetrievalMemory**：基于检索的记忆，使用向量检索找到相关记忆
3. **RecentMemory**：只保留最近的记忆（滑动窗口）
4. **GenerativeAgent**：来自Stanford的生成式智能体，会对记忆进行反思和总结
5. **MemoryBank**：带有遗忘机制的长期记忆
6. **MemGPT**：将LLM类比为操作系统，实现分层记忆管理
7. **SCMemory（Self-Controlled Memory）**：自控记忆框架  
   所有涉及检索的方法使用multilingual-e5-small作为检索模型。

#### 3.2 事实记忆评估结果

Table 3展示了事实记忆的测试结果：  
**在Sub-dataset 1（10k）上**：

- FullMemory、RetrievalMemory和RecentMemory表现较好
- 参与场景中，RetrievalMemory达到0.692，FullMemory为0.647
- 观察场景中，RetrievalMemory达到0.883，RecentMemory为0.8

**在Sub-dataset 2（100k）上**：

- FullMemory和RecentMemory出现明显下降（因为目标信息可能超出上下文窗口）
- RecentMemory下降更严重（窗口更小）
- RetrievalMemory表现最稳定，在参与场景达到0.833，观察场景达到0.933
- 其他设计的记忆机制（GenerativeAgent、MemoryBank、MemGPT、SCMemory）在两个数据集上都没有表现出明显优势

**效率方面**：

- FullMemory和RecentMemory的读写时间几乎可以忽略
- MemGPT的读取时间最长（参与场景4.549秒/操作）
- MemoryBank的写入时间最长（参与场景8.047秒/操作，观察场景18.243秒/操作）

**召回率**：RetrievalMemory在10k数据上参与场景Recall@10为0.776，100k数据上为0.749；观察场景分别为0.847和0.769。

#### 3.3 反思记忆评估结果

Table 4展示了反思记忆的测试结果：  
**在Sub-dataset 1上**：

- GenerativeAgent、MemGPT和MemoryBank表现很好（参与场景分别为0.742、0.733、0.692）
- 观察场景中，MemoryBank甚至达到0.900

**在Sub-dataset 2（100k）上**：

- 几乎所有方法性能都急剧下降
- 只有RetrievalMemory保持了较好的结果（参与场景0.833，观察场景0.933）
- 其他方法（GenerativeAgent 0.333、MemGPT 0.367、MemoryBank 0.400等）下降严重  
  这说明：精心设计的记忆机制确实能有效捕捉反思记忆，但在长时间交互后如何维持这种能力是一个具有挑战性的研究问题。下降的原因可能是模型上下文窗口有限，或者遗忘机制导致了重要记忆的丢失。

#### 3.4 记忆容量评估

Figure 5展示了四种记忆机制（SCMemory、MemGPT、GenerativeAgent、RecentMemory）在观察场景100k数据集上，随着记忆token数量增加，准确率的变化趋势。  
结果显示，这些记忆机制都出现了**准确率的急剧下降**。这可能反映了在Qwen2.5-7B-Instruct模型上，这些记忆机制的性能保持能力存在上限。

#### 3.5 不同推理模型的比较

Table 5比较了四种不同基础模型（Qwen2.5-7B-Instruct、GPT-4o-mini、Meta-Llama-3.1-8B-Instruct、glm-4-9b-chat）在Sub-dataset 1上的表现：

- **GPT-4o-mini**在大多数情况下表现最好（事实记忆参与场景FullMemory达0.736，观察场景0.864）
- **Meta-Llama-3.1-8B-Instruct**的事实记忆能力明显弱于其他模型，但反思记忆能力仍然相对不错
- 有趣的是，使用GPT-4o-mini作为GenerativeAgent的基础模型时，时间消耗显著高于其他模型
- 基础模型的选择对智能体的记忆性能有显著影响

#### 3.6 各问题类型的详细结果

Table 11（事实记忆-参与场景）的细分结果显示：

- **Single-hop和Multi-hop**类型相对简单，大多数方法准确率在0.6-0.9之间
- **Comparative和Aggregative**类型较难，准确率普遍较低（0.05-0.55和0.225-0.45）
- **Knowledge-updating**类型准确率中等（0.475-0.75）
- **Assistant相关类型**（ssa和msa）对基于检索的方法挑战较大，因为需要记住智能体自己的回复  
  Table 10（反思记忆细分）显示：
- **Preference类型**普遍比**Emotion类型**表现更好
- Emotion类型最高准确率仅0.676（GenerativeAgent在观察场景），说明情绪记忆是一个更具挑战性的任务

### 四、总结与局限

#### 主要贡献

1. 构建了首个同时包含多场景（参与+观察）和多层次记忆（事实+反思）的评估数据集
2. 提出了包含准确率、召回率、容量和时间效率的多维度评估框架
3. 系统评测了七种主流记忆机制，揭示了现有方法在不同维度上的优劣

#### 主要发现

- RetrievalMemory在大规模数据上表现最稳定，是目前最可靠的记忆机制
- 精心设计的记忆机制能有效捕捉反思记忆，但在长时间交互后难以维持
- 现有记忆机制普遍存在容量瓶颈，随着记忆量增加性能急剧下降
- 某些记忆机制（如MemoryBank、MemGPT）的时间开销过大，在实际应用中可能不可接受
- 基础模型的选择对记忆性能有显著影响

#### 局限性

- 评估方法局限于结构化数据的记忆评估
- 反思记忆还有很多方面值得探索，如用户的情绪记忆
- 数据集基于用户画像和关联实体的图结构，对非结构化记忆的评估能力有限

## 原文摘要

Recent works have highlighted the significance of memory mechanisms in LLM-based agents, which enable them to store observed information and adapt to dynamic environments. However, evaluating their memory capabilities still remains challenges. Previous evaluations are commonly limited by the diversity of memory levels and interactive scenarios. They also lack comprehensive metrics to reflect the memory capabilities from multiple aspects. To address these problems, in this paper, we construct a more comprehensive dataset and benchmark to evaluate the memory capability of LLM-based agents. Our dataset incorporates factual memory and reflective memory as different levels, and proposes participation and observation as various interactive scenarios. Based on our dataset, we present a benchmark, named MemBench, to evaluate the memory capability of LLM-based agents from multiple aspects, including their effectiveness, efficiency, and capacity.
