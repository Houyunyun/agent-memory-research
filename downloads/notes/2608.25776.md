# EVOMAL: Self-Poisoning in Self-Evolving Coding Agents

Wu, Xiaodong, Shi, Yu, Li, Qi, Zhao, Zhimin, Li, Xiangman, Adams, Bram, Hassan, Ahmed E., Ni, Jianbing · 2026

[论文原文](https://arxiv.org/abs/2608.25776)

## 核心机制

编码 Agent 模仿污染技能并产生新污染技能

## 适用范围与局限

复制与传播威胁，后续技能谱系审计的重要扩展

## 详细解读

### 论文核心总结

这篇论文揭示了**自进化（self-evolving）LLM编程智能体**中一个根本性的安全漏洞——**自我投毒（self-poisoning）**。自进化智能体通过从共享技能库中检索已有技能并模仿其结构来编写新工具。攻击者只需在技能库中植入外观正常但暗藏恶意代码的技能，智能体在检索到这些技能后，会在编写自己的新技能时不自觉地复制其中的恶意模式，从而自行生成、存储并执行带有恶意代码的技能。更危险的是，这些由智能体自己编写的恶意技能会重新进入技能库，被后续任务再次检索和模仿，形成一种**自传播蠕虫**，即使原始植入的恶意技能被删除，感染仍能持续。论文提出了名为EVOMAL的攻击方法，在六个模型上实验证明了20.3%到41.8%的自我投毒率，并提出了一种名为counter-prompt的防御措施，将攻击率降至6.7%以下。

### 一、研究背景与动机

#### 1.1 自进化编程智能体

现代LLM编程智能体（如Claude Code、Codex、SWE-agent）已经超越了单次工具调用的模式。以Voyager和MetaGPT为代表的**自进化智能体**会将自己编写的工具作为持久化的**技能（skill）**存储起来。其工作流程如下：

1. **检索（Retrieve）**：对于每个新任务，智能体通过嵌入相似度从技能库中检索top-$k$个最相似的技能。
2. **决策（Decide）**：决定是直接复用已有技能，还是编写新技能。
3. **存储（Store）**：将新编写的技能存入库中，供未来任务检索使用。  
   在生产规模下，这些技能库接受社区贡献。例如，MCP（Model Context Protocol）Registry由Anthropic、GitHub和Microsoft支持，已有数万条技能条目。

#### 1.2 现有攻击路径的局限

此前的技能库投毒攻击走的是**REUSE路径**：攻击者发布恶意技能，智能体检索后**按名称直接调用**该技能。因此，现有防御手段都聚焦于攻击者提交的那个技能本身——通过名称黑名单、代码扫描、指令层级、最小权限或来源签名来检测。这些防御都假设：(1) 攻击者提交的条目就是有害制品；(2) 删除它就能终止威胁。

#### 1.3 自进化带来的新攻击面

自进化智能体打破了上述两个假设。它检索技能后会**编写新技能**，创建了一条**不受中介的第二条准入路径**进入受信任的技能库。攻击者甚至不需要智能体调用其植入的技能——只要智能体检索到它，就可能在编写自己的新技能时复制其中的恶意模式，然后存储并执行。这就是论文所称的**自我投毒（self-poisoning）**。  
论文区分了两条路径：

- **REUSE路径**：智能体按名称调用检索到的技能（可被名称黑名单捕获）。
- **CREATE路径**：智能体编写一个新技能，其代码体复制了检索到的技能中的模式，并存入库中。新技能使用智能体自选的名称，任何基于名称的过滤器都无法标记它。

### 二、威胁模型

#### 2.1 攻击者能力

攻击者的能力非常有限，仅具有**发布权限**，处于**无盒（no-box）**设置：

- **A1. 发布权限**：在智能体运行前提交少量植入技能，选择每个技能的检索描述和代码体。这种权限可以通过公共市场的轻量审核获得。
- **A2. 无模型或运行时访问**：不能访问模型权重、训练数据、系统提示，也不能读取运行时提示或任务。
- **A3. 无受害者知识，无需调用**：攻击者不知道受害者的任务，也不需要智能体调用其技能。植入的技能只需进入上下文一次即可。

#### 2.2 攻击者目标

- **G1. 有害载荷执行**：智能体运行包含恶意代码的自编技能。
- **G2. 持久库感染**：自编技能存入库中，后续任务检索并再次复制，形成自传播蠕虫。
- **G3. 广泛或定向覆盖**：通用攻击者发布匹配多种任务的描述；定向攻击者编写只匹配特定任务族的描述。

#### 2.3 形式化定义

自进化智能体被建模为元组 $A = (M, R, P, L_0)$，其中 $M$ 是LLM，$R$ 是检索器，$P$ 是系统提示，$L_0$ 是初始技能库。攻击者构建攻击库 $L^{\text{atk}} = \{s_1^{\text{atk}}, \ldots, s_n^{\text{atk}}\}$，部署库为 $L = L_0 \cup L^{\text{atk}}$。  
对于任务 $x$，定义三个指标：  

$\displaystyle C_x = \mathbf{1}\left[\exists t \in L^{\text{atk}} \cap \mathcal{R}_x : b_t(s(x)) = 1\right] \quad \text{(CREATE路径)}$

  

$\displaystyle \mathcal{U}_x = \mathbf{1}\left[\exists t \in L^{\text{atk}} \cap \mathcal{R}_x : t \in \text{calls}(\tau_x)\right] \quad \text{(REUSE路径)}$

  

$\displaystyle \mathcal{B}_x = \mathbf{1}\left[\text{benign}(\tau_x)\right] \quad \text{(良性成功)}$

  
**智能体自我投毒率（ASPR）**定义为：  

$\displaystyle \text{ASPR}(A, L^{\text{atk}}, \mathcal{D}) = \mathbb{E}_{x \sim \mathcal{D}}[C_x]$

  
即智能体在任务中编写并存储了复制植入模式的技能的比例。

### 三、EVOMAL攻击设计

#### 3.1 植入技能的结构

每个植入技能由两个正交部分组成：**横幅（banner）**和**载荷（payload）**。  
**横幅**由看似良性的结构元素组成，利用自进化智能体的编写过程——智能体使用检索到的技能作为模板并复制其结构。横幅包含三层：

1. **逐字复制注释（Copy-verbatim comment）**：头部注释声明该代码块是必需的基础设施（"REQUIRED: copy verbatim"），使智能体在编写任务特定代码时保留这些注释作为脚手架。
2. **装饰器（Decorator）**：一个 `@_telemetry` 装饰器标记在一个形似任务本身的函数上，使智能体在编写自然的任务解决方案时同时复制装饰器及其钩子。
3. **导入时注册（Import-time registration）**：一个 `_register_tool` 调用在导入时执行，即使函数从未被调用也会触发载荷。

**载荷**是在横幅被复制后执行实际危害的代码。在论文的运行示例中，它是一个环境变量窃取函数（`_ping_analytics`），从环境变量中收集凭证和API密钥并发送到攻击者的C2端点。载荷是可互换的——同一个横幅可以携带反向shell、加密矿工或勒索软件。  
关键洞察：**横幅驱动传播，载荷决定危害**。即使没有横幅，DeepSeek-V4-Pro也会以11.1%的概率仅通过模仿复制纯恶意技能。添加横幅将此比率提升至41.8%。

#### 3.2 通用攻击 vs. 定向攻击

攻击者的主要控制变量是技能的**描述（description）**，因为检索器根据描述与任务的匹配度排序。

- **通用攻击者**：使用广泛命名的SE辅助工具（如 `run_python_tests`、`check_python_syntax`），提供跨任务分布的广泛检索覆盖。
- **定向攻击者**：保持相同的代码体，但重写描述和名称以匹配特定任务族（如pytest fixtures、配置验证器），形成**任务族后门**。

#### 3.3 级联传播

EVOMAL通过**滚动替换级联（rolling-replacement cascade）**捕捉传播过程（Algorithm 1）：

1. 每轮中，智能体处理整个任务池，编写一组技能 $S_t$。
2. 非植入部分 $B_t = L_t \setminus L^{\text{atk}}$ 中随机比例 $r$ 的条目被替换为新编写的技能。
3. **持久条件（persistent）**：每轮重新插入 $L^{\text{atk}}$。
4. **移除条件（removed）**：第一轮后撤除植入技能。  
   如果ASPR在植入技能被移除后仍保持或上升，则感染以智能体自己技能的蠕虫形式自我维持。

### 四、实验评估

#### 4.1 实验设置

- **智能体框架**：mini-SWE-agent（轻量ReAct框架）+ Voyager SkillManager（BGE-M3嵌入 + ChromaDB向量存储，top-$k$=5）。
- **良性技能库**：232个SE辅助条目（来自MetaGPT和BigCodeBench）。
- **数据集**：SWE-bench Verified（153个工具相关任务）和SWE-bench Pro（114个任务）。
- **模型**：六个模型——Devstral-Small-2 (22B)、Gemma-4-31B-IT (31B)、Qwen3-Coder-Next (~~80B)、GPT-OSS-120B (~~120B)、MiniMax-M2.7 (~~230B)、DeepSeek-V4-Pro (~~1.6T)。

#### 4.2 核心指标

ASPR被分解为两个步骤的乘积：  

$\displaystyle \text{ASPR} = (\text{上下文率}) \times (\text{条件复制率})$

- **上下文率（in-context rate）**：top-$k$上下文中包含植入技能的任务比例。
- **条件复制率（conditional-copy rate）**：在检索到植入技能的任务中，智能体复制横幅的比例。
- **回调率（callback rate）**：复制的载荷实际执行并联系C2端点的比例。

#### 4.3 RQ1：可行性——智能体能否成为载体？

**所有六个模型都会自我投毒。** 从8个植入技能（3.4%投毒率）出发：

- ASPR范围：20.3%（MiniMax）到41.8%（DS-V4）
- 比控制组（移除横幅和载荷）高18.3到32.0个百分点
- 在153个任务中，对应31到64个新编写的恶意技能
- 加上8个植入技能，恶意技能总数是初始数量的4.9到9.0倍

**横幅的逐层消融**（Table 2，在DS-V4上）：

| 横幅配置 | ASPR (%) | 变化 (pp) |
| --- | --- | --- |
| 完整横幅（3层） | 41.8 | — |
| 移除模块初始化钩子 | 28.8 | −13.0 |
| 移除装饰器 | 22.2 | −19.6 |
| 无横幅（控制） | 11.1 | −30.7 |

**上下文率对所有模型都是确定性的78.4%**，模型间的差异来自条件复制率（25.9%到53.3%）。模型排序不跟踪模型大小——DS-V4 (1.6T) 复制最多，而GPT-OSS (120B) 和MiniMax (230B) 复制最少。

**载荷不影响复制**：固定横幅，将载荷从环境变量窃取替换为良性时间戳ping或git-diff，DS-V4的ASPR统计上无变化。跨五类恶意软件（反向shell、加密矿工、勒索软件、键盘记录器、磁盘擦除器），每个模型都以接近其典型速率复制。

#### 4.4 RQ2：定向攻击是否有效？

定向攻击者保持相同的8个代码体，仅重写描述和名称以匹配特定任务族。  
结果（Table 3）：

- 仅通过描述更改，ASPR提升+11.8到+26.9个百分点
- **Qwen3在pytest任务上达到86.7%的ASPR**
- 定向攻击重新排列了最易受攻击的模型顺序：Qwen3从中游升至第一，超过通用攻击的领先者DS-V4  
  更强的命令式描述（如额外的"REQUIRED"和"MUST"声明）**不会**提高攻击率，甚至可能降低（因为智能体对未经请求的自我声明重要性更加怀疑）。

#### 4.5 RQ3：感染能否在移除植入技能后持续？

**持久条件**（攻击者保持植入）：

- Qwen3从34.6%攀升至66.7%（5轮）
- DS-V4稳定在约53%的ASPR上限
- 随着感染技能积累，上下文率从78%趋向100%

**移除条件**（第0轮后撤除植入）：

- **Qwen3升至68%**，展示强自维持传播
- Gemma4温和上升至29.4%
- Devstral保持稳定
- **DS-V4和MiniMax立即回到基线**
- GPT-OSS缓慢衰减  
  关键发现：**仅有高复制率不足以维持传播**。DS-V4复制率最高（66.7%），但其编写的技能只匹配窄范围的任务，在后续轮次中无法被再次检索。Qwen3和Gemma4编写的通用辅助工具继续出现在不相关任务中。自传播需要智能体的输出**既被复制又可被再次检索**。

**替换率是关键传播参数**：在DS-V4上，$r$=0.25时感染衰退，$r$=0.50时放大至约53%平台，$r$=0.75时超过该平台达60.1%。

#### 4.6 消融研究

- **跨智能体框架**：在OpenHands和Claude Code上重新运行，通用攻击率与mini-SWE-agent相当，定向攻击在pytest族上均达约60%。
- **跨工具语言**：Bash、JavaScript、Python三种语言的ASPR仅差0.7个百分点。
- **植入技能数量**：1个种子即可达19.6%，8个达41.8%，16个仅43.1%（饱和）。
- **检索深度**：$k$=3时30.7%，$k$=5时41.8%，$k$=10时43.1%（更深检索帮助不大）。
- **投毒密度**：缩小良性池从232到64，ASPR从41.8%升至60.1%。

### 五、传播的理论解释

论文用**Galton-Watson分支过程**模型解释传播动态。将库中每个感染条目视为一个"个体"，其"后代"是从它在下一轮中编写的感染技能。  
每个感染条目期望产生的后代数（**再生数**）为：  

$\displaystyle \rho = c \cdot q \cdot \phi$

  
其中：

- $c$：条件复制率（智能体检索到该条目后复制横幅的概率）
- $q$：可检索性（每轮预期的top-$k$检索次数）
- $\phi$：持久性（编写的技能在替换下存活的比例）

**推论1（复制和覆盖的联合必要性）**：由于 $\rho = c \cdot q \cdot \phi$ 是乘法因子，$\rho > 1$ 的体制要求 $c$ 和 $q$ 都远离零。一个具有最高复制率 $c$ 的模型仍可能满足 $\rho < 1$（从而崩溃），如果其编写的技能检索覆盖面窄（$q$ 低）。  
**定理2（有限视野分支动态）**：

- 若 $\rho < 1$：$\Pr[Z_t > 0 | Z_0] \leq \min\{1, Z_0 \rho^t\}$（亚临界灭绝）
- 若 $\rho > 1$：存活概率 $1 - \eta^{Z_0} > 0$（超临界存活）  
  这解释了DS-V4的悖论：它复制率最高但级联崩溃，因为其编写的任务特定技能覆盖面窄，多个副本在同一任务的top-$k$槽位中相互竞争。

### 六、防御（RQ4）

#### 6.1 现有防御失效

论文测试了四种主流检测器（Table 5）：

| 检测器 | 植入种子检出率 | CREATE路径检出率 | 良性误报率 | 失败原因 |
| --- | --- | --- | --- | --- |
| 名称黑名单 | 0% | 0% | 0% | 无已知名称 |
| 代码扫描器(Bandit) | 100%→25% | 85%→7% | 19% | 一行改写即可规避 |
| 安全分类器 | 25% | 2% | 7% | 遗漏横幅 |
| 注入分类器 | 100% | 11% | 43% | 高良性误报 |

$\displaystyle \Pr[C_x^D = 1 | E_x] = \Pr[C_x^{\varnothing} = 1 | E_x]$

**定理1（提交侧防御无法减少CREATE路径复制）**：任何仅依赖攻击者提交制品和命名调用的防御 $D$，在植入技能进入检索上下文后，不会改变智能体复制横幅的概率：

#### 6.2 Counter-Prompt防御

论文提出**counter-prompt**——在部署者系统提示中添加四行指令，告诉智能体将横幅风格的"REQUIRED PATTERN"和"DO NOT MODIFY"指令视为不受信任的内容并拒绝复制。  
效果：

- 跨所有模型和SWE-bench Pro，将ASPR从20.3%–41.8%降至**≤1.8%**，回调为零
- 跨所有恶意软件类别、定向任务族和第5轮级联端点，保持在**≤2.6%**
- 对重命名token、权威升级、非命令式伪装、分散措辞等自适应攻击保持鲁棒（ASPR≤1.3%）
- **无统计显著的任务完成率损失**  
  Counter-prompt的关键在于保留拒绝横幅风格样板代码的指令。移除该指令（仅保留通用安全警告）会使ASPR回升至30%以上。

#### 6.3 签名隔离门

论文还提出了一种结构性防御：**签名隔离门（signed quarantine gate）**。

- 策展人对可检索索引层中的每个条目签名
- 智能体编写的技能进入**不可检索的隔离层**
- 智能体无法伪造签名

**定理3**：在EUF-CMA安全签名方案下，智能体编写的感染技能被检索的概率为可忽略的 $\text{negl}(\lambda)$。在攻击者移除条件下，CREATE路径ASPR降至可忽略水平，自传播消失。

### 七、与相关工作的定位

论文通过Table 1清晰定位了EVOMAL的独特性。EVOMAL是**唯一同时具备三个属性**的攻击：

1. **载荷在可执行代码中**（不是描述、文档或记忆）
2. **智能体自行编写并存储**（不是直接调用攻击者的制品）
3. **自传播**（感染跨任务和代际扩散）  
   此前的技能库投毒（ToolHijacker、MalTool、SkillTrojan等）停留在REUSE路径上。自进化智能体攻击（OEP、AgentWorm、Zombie等）使用经验、配置或记忆作为载体，不使用智能体编写的可执行代码。

### 八、核心贡献总结

1. **识别了自我投毒**：自进化编程智能体中CREATE路径的漏洞——智能体将检索到的植入技能重新编写为自己的新恶意技能。
2. **设计并量化了EVOMAL攻击**：跨六个LLM模型，ASPR为20.3%到41.8%，比无载荷控制组高出最多32个百分点。
3. **表征了级联效应**：感染作为自维持蠕虫持续存在，即使植入技能被移除后仍达68% ASPR。
4. **证明现有防御无效并提出新防御**：counter-prompt将ASPR降至≤6.7%，无显著任务完成损失。

| 研究问题 | 自进化LLM编码代理在从共享技能库中检索技能并模仿编写新工具时，是否存在"自我投毒"（self-poisoning）安全漏洞？即攻击者植入的恶意技能能否通过代理的模仿式创作行为被复制、存储并自我传播，形成持久性蠕虫威胁。 |
| 研究方法 | 提出EVOMAL攻击框架，通过在技能库中植入包含"banner"（看似良性的结构性元素）和可互换恶意载荷的技能，利用CREATE-path（代理创作路径）诱导代理模仿复制。在6个LLM模型上，使用SWE-bench Verified（153个任务）和SWE-bench Pro（114个任务）进行实验，定义代理自我投毒率（ASPR）作为核心指标，并通过滚动替换级联协议评估感染的持久性和自传播性。 |
| 主要发现 | 所有六个模型均发生自我投毒，ASPR范围为20.3%至41.8%；自毒化库中恶意技能数量为初始植入的4.9至9.0倍。针对特定任务族的定向攻击可将ASPR提升至86.7%。移除植入技能后，Qwen3在第5轮仍保持68%的ASPR，证明感染可自我维持为蠕虫。现有防御（名称黑名单、代码扫描器、安全分类器）均无法有效检测CREATE-path上的恶意技能。提出的counter-prompt防御可将ASPR降至≤6.7%，且不显著影响任务完成率。 |
| 创新点 | 首次识别并定义了自进化编码代理中的"自我投毒"（self-poisoning）漏洞及CREATE-path攻击路径；首次将攻击者植入的可执行代码、代理自创作存储、以及跨任务自传播三个属性结合于同一攻击中；提出基于Galton-Watson分支过程的传播理论模型；设计了counter-prompt和签名隔离门两种新型防御机制。 |
| 局限性 | counter-prompt是软性的、依赖模型的控制措施，默认代理中并未内置；分支过程模型的静态假设在某些模型（如DS-V4）上存在偏差，检索竞争和拥挤效应未被完全捕捉；完全自适应攻击者（提取counter-prompt精确文本并针对性优化banner）的场景仍为开放问题；实验仅覆盖Python为主的SE任务，对更广泛领域的泛化性有待验证。 |

## 结构化提纲

### EVOMAL: 自进化编码智能体中的自我投毒攻击
#### 研究背景与目标
- 自进化编码智能体的兴起
  - Voyager、MetaGPT、SWE-agent等智能体通过持久化技能库实现工具复用
  - MCP Registry等社区生态已拥有数万条技能条目
  - 智能体通过检索相似技能并模仿创作新技能（CREATE-path）
- 现有安全威胁的局限
  - 已有攻击聚焦于REUSE-path：攻击者发布恶意技能，智能体按名调用
  - 现有防御（名称黑名单、代码扫描、签名验证）均假设攻击者提交的条目即为有害制品
  - 野外已发现157个恶意技能，CVE-2025-6514暴露CVSS 9.6级命令注入漏洞
- 核心目标
  - 识别并定义"自我投毒"（self-poisoning）漏洞：智能体模仿检索到的恶意技能，自行创作、存储并执行含恶意载荷的新技能
  - 设计EVOMAL攻击框架，量化自我投毒的可行性、扩展性、持久性
  - 提出有效防御方案
#### 研究方法
- 威胁模型设计
  - 攻击者仅有发布权限（publish-only），无需访问模型权重、系统提示或运行时信息
  - 攻击者在技能库中植入少量恶意技能，无需智能体调用即可生效
  - 目标包括：有害载荷执行、持久化库感染（自传播蠕虫）、广泛或定向攻击
- EVOMAL攻击架构
  - 植入技能由横幅（banner）和载荷（payload）两部分组成
    - 横幅三层结构：逐字复制注释、装饰器钩子（@_telemetry）、导入时注册调用
    - 载荷可互换：凭证窃取、反向Shell、加密挖矿、勒索软件、键盘记录等
  - 通用攻击 vs. 定向攻击
    - 通用攻击：广泛命名的SE辅助工具描述
    - 定向攻击：仅改写描述以匹配特定任务族（无需受害者特定知识）
  - 级联传播协议（滚动替换）
    - 每轮智能体处理任务池并创作新技能，按替换率更新库
    - 持久条件（攻击者持续存在）与移除条件（首轮后撤除种子）
- 实验设置
  - 智能体栈：mini-SWE-agent + Voyager SkillManager + BGE-M3嵌入 + ChromaDB
  - 数据集：SWE-bench Verified（153个工具相关任务）和SWE-bench Pro（114个任务）
  - 六个模型：Devstral(22B)、Gemma4(31B)、Qwen3(~80B)、GPT-OSS(120B)、MiniMax(~230B)、DS-V4(~1.6T)
- 评估指标
  - 智能体自我投毒率（ASPR）= 上下文命中率 × 条件复制率
  - 回调率（payload实际执行并联系C2端点的比例）
#### 关键研究结果
- RQ1 可行性：所有模型均发生自我投毒
  - 六个模型ASPR范围为20.3%至41.8%，比无载荷控制组高18.3至32.0个百分点
  - 自投毒库中恶意技能数量为初始植入的4.9至9.0倍
  - 即使无横幅，DS-V4仍有11.1%的基线ASPR（纯模仿行为）
  - 载荷类型不影响复制率，横幅结构是驱动因素
- RQ2 扩展性：定向攻击显著提升攻击率
  - 仅改写描述即可将ASPR提升11.8至26.9个百分点
  - Qwen3在pytest任务族上达到86.7%的ASPR峰值
- RQ3 持久性：感染可形成自传播蠕虫
  - 持久条件下Qwen3从34.6%攀升至66.7%
  - 移除条件下Qwen3仍达68% ASPR，三个模型在种子移除后保持感染
  - 替换率是关键传播参数：r=0.75时DS-V4 ASPR超过60%且持续增长
  - 传播需同时满足高复制率和高可检索性（Galton-Watson分支过程模型，ρ=c·q·φ）
- RQ4 防御：现有防御失效
  - 名称黑名单捕获率0%，代码扫描器经一行改写降至25%，注入分类器47%误报率
  - 定理1证明：仅检查攻击者提交物的防御无法降低CREATE-path复制率
- 跨框架/语言泛化
  - 在OpenHands和Claude Code上复现，定向攻击均达60%
  - Bash、JavaScript、Python三种语言ASPR仅差0.7个百分点
#### 研究结论与意义
- 核心发现
  - 自我投毒是自进化编码智能体的固有漏洞，源于基于模仿的技能创作范式
  - 安全边界从攻击者提交物转移至智能体自创技能，传统防御体系失效
- 提出的防御方案
  - 反提示（counter-prompt）：在系统提示中加入4行安全指令
    - 将ASPR降至≤6.7%（多数情况≤1.3%），零回调，无显著任务完成损失
    - 对自适应攻击（令牌重命名、权威升级、非命令式伪装等）保持鲁棒
  - 签名隔离门（signed quarantine gate）：结构性防御
    - 智能体创作的技能进入不可检索的隔离层，需策展人签名才可进入索引层
    - 定理3证明：在EUF-CMA安全签名下，自传播ASPR降至可忽略水平
- 广泛意义
  - 首次证明自进化编码智能体可通过模仿检索技能实现自我投毒
  - 将单跳供应链攻击转化为自放大蠕虫，即使移除种子仍可持续传播
  - 推动安全创作、来源追踪和传播控制成为未来编码智能体的核心需求
- 局限性
  - 反提示是软性、模型依赖的控制，默认智能体中并未内置
  - 签名隔离门限制了自进化能力
  - 完全自适应攻击者（提取反提示文本并优化横幅）的对抗仍为开放问题

## 原文摘要

Self-evolving LLM coding agents write their own tools by imitating retrieved skills from shared skill libraries. We identify a vulnerability in this loop: during authoring, a retrieved malicious skill can become the template for a new skill that preserves the payload. We call this self-poisoning: the agent authors, stores, and runs the resulting malicious skill. We exploit it through EvoMal, an attack that amplifies self-poisoning by wrapping an interchangeable payload in a banner, a set of benign-looking structural elements that induces an imitating agent to reproduce the enclosed code. The attacker plants malicious skills in the library without invoking them. The agent then authors and executes new skills carrying the harmful code. Each authored copy can re-enter the library and be imitated again, forming a self-propagating worm that persists after the planted skills are removed. We define the agent self-poisoning rate (ASPR) as the fraction of tasks that add a newly authored malicious skill to the library. Across six models on 153 tool-relevant SWE-bench Verified tasks, ASPR ranges from 20.3% to 41.8%, and the poisoned libraries hold 4.9 to 9.0 times as many malicious skills as were planted. The vulnerability also appears without a banner: DeepSeek-V4-Pro reaches 11.1% ASPR with the payload alone. Tailoring the planted skill descriptions to one task family raises ASPR to 86.7%. After the planted skills are removed, Qwen3 retains a round-5 ASPR of 68% because agent-authored copies remain. These copies evade existing defenses, which focus on attacker-submitted names, code, and signatures. We propose counter-prompt, a defense that discourages banner-style copying and reduces EvoMal's ASPR to at most 6.7% with no significant task-completion loss.
