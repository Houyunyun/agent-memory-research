# MIRIX: Multi-Agent Memory System for LLM-Based Agents

Wang, Yu, Chen, Xi · 2025

[论文原文](https://arxiv.org/abs/2507.07957)

## 核心机制

多种记忆类型和多个管理 Agent 组织长期用户信息

## 适用范围与局限

管理调用、视觉存储和权限边界需分别评价

## 详细解读

这篇论文提出了 MIRIX——一个面向 LLM Agent 的模块化多智能体记忆系统，其核心贡献在于将记忆分解为六种结构化类型（Core、Episodic、Semantic、Procedural、Resource、Knowledge Vault），并通过多智能体架构对记忆的写入和检索进行动态路由与协调，从而突破现有系统"平面化存储、单一模态、难以扩展"的根本局限；在多模态截图基准和长对话基准 LOCOMO 上，MIRIX 均取得了显著领先的性能，同时将存储占用压缩了 99.9%。

---

### 一、研究背景与问题动机

当前 LLM Agent 的研究大量聚焦于复杂任务执行能力（代码调试、自主浏览等），但"记忆"这一同样基础的能力却严重不足。大多数 LLM Agent 是**无状态**的——对话窗口结束后一切归零，用户必须反复提供上下文。这与人类认知中记忆的核心作用（回忆对话、识别模式、根据经历调整行为）形成了鲜明对比。

现有的记忆增强方案主要有两条路线：

- **知识图谱**（如 Zep、Cognee）：擅长表达实体间的结构化关系，但难以建模时序事件、情感状态、完整文档，以及图像等多模态输入。
- **平面向量存储**（如 Letta、Mem0、ChatGPT 的记忆系统）：将历史信息切片存入向量数据库，检索灵活，但存在三个核心问题：
  1. **缺乏组合式记忆结构**：所有数据堆在同一个平面存储里，没有按记忆类型分类路由，导致检索效率低、精度差。
  2. **多模态支持差**：以文本为中心，无法处理图像、界面布局等非文字输入。
  3. **可扩展性与抽象能力弱**：直接存储原始输入（尤其是图像）会导致存储需求爆炸，也没有有效的摘要抽象层。

论文的出发点是：有效的记忆系统必须具备两种核心能力——**路由（Routing）**和**检索（Retrieval）**。

### 二、MIRIX 系统设计

#### 2.1 六种记忆组件

这是 MIRIX 区别于所有现有系统最核心的设计，灵感来源于认知科学对人类记忆的分类。

**1. Core Memory（核心记忆）**

受 MemGPT 启发，存储对 Agent 始终可见的高优先级持久信息，分为两个块：

- `persona`：Agent 的身份、语气、行为风格
- `human`：用户的持久属性，如姓名、偏好、自我描述

当存储占用超过容量的 90% 时，系统触发受控重写，在保留关键信息的同时压缩内容。

**2. Episodic Memory（情节记忆）**

记录带有时间戳的事件和交互，相当于一个结构化的日志或日历，让 Agent 能推断用户习惯、跟踪时近性和上下文。每个条目包含：

- `event_type`：事件类型（如 `user_message`、`inferred_result`、`system_notification`）
- `summary`：简洁的自然语言描述
- `details`：扩展上下文，包括对话片段或推断状态
- `actor`：来源（用户或助手）
- `timestamp`：如 `"2025-03-05 10:15"`

**3. Semantic Memory（语义记忆）**

存储与特定时间或事件无关的抽象知识和事实性信息，作为通用概念、实体与关系的知识库，例如 "Harry Potter is written by J.K. Rowling" 或 "John is a friend of the user who enjoys jogging"。每个条目包含：

- `name`：概念或实体的标识符
- `summary`：简洁定义或关系描述
- `details`：扩展背景或上下文
- `source`：来源（如 `user_provided`、`Wikipedia`、对话推断）

语义记忆条目设计为持久存在，除非被概念性地覆盖。

**4. Procedural Memory（程序记忆）**

存储结构化的、目标导向的操作流程，如操作指南、工作流和交互脚本。这类记忆既不是时间敏感的（情节记忆），也不是纯抽象事实（语义记忆），而是可以被调用来协助用户完成复杂任务的"可执行知识"。典型例子包括"如何填写差旅报销表"、"设置 Zoom 会议的步骤"。每个条目包含：

- `entry_type`：`workflow`、`guide` 或 `script`
- `description`：目标或功能描述
- `steps`：指令列表（可选 JSON 格式）

**5. Resource Memory（资源记忆）**

处理用户正在使用的完整或部分文档、转录、多模态文件——这些内容不适合放入其他记忆类别。例如，用户正在阅读的野餐计划文档或项目提案。每个条目包含：

- `title`：资源名称
- `summary`：简要概述
- `resource_type`：`doc`、`markdown`、`pdf_text`、`image`、`voice_transcript` 等
- 完整或摘录的内容正文

**6. Knowledge Vault（知识保险库）**

作为敏感信息的安全仓库，存储需要逐字保留的精确信息，如凭据、地址、联系方式、API 密钥等。这些信息通常不参与对话级推理，但对于执行需要身份验证的任务至关重要。每个条目包含：

- `entry_type`：`credential`、`bookmark`、`contact_info`、`api_key` 等
- `source`：信息来源
- `sensitivity`：敏感级别（`low`、`medium`、`high`）
- `secret_value`：实际内容

高敏感度条目通过访问控制加以保护，不会出现在日常检索中，以防泄露。

---

#### 2.2 主动检索机制（Active Retrieval）

现有记忆系统（如 Mem0、MemGPT）的检索往往需要用户显式触发，否则 LLM 会回退到参数化知识，可能给出过时或错误的答案。例如，用户曾说过"Twitter 的 CEO 是 Linda Yaccarino"，但几天后再问同一问题时，若系统没有主动检索，模型可能依赖训练知识给出"Elon Musk"。

为解决这个问题，MIRIX 提出了**主动检索（Active Retrieval）**机制，分为两个阶段：

1. Agent 根据当前输入上下文**自动生成当前话题**（topic generation）；
2. 以该话题为查询键，在六个记忆组件中各检索 top-10 最相关条目，检索结果被注入系统提示，并用来源标签标注，如 `<episodic_memory>...</episodic_memory>`。

这样就消除了对用户显式指令"搜索你的记忆"的依赖，确保模型在生成回答时能够利用最新的个性化或上下文信息。

除主动检索外，系统还支持多种检索函数：

- `embedding_match`：基于向量嵌入的语义相似度匹配
- `bm25_match`：基于词频的经典信息检索算法
- `string_match`：精确字符串匹配

Agent 会根据具体情境选择最合适的检索方式。

#### 2.3 多智能体工作流

MIRIX 采用模块化多智能体架构管理异构的用户交互：

**整体架构**由以下角色组成：

- **Meta Memory Manager**（元记忆管理器）：中央协调者，负责分析输入并将任务路由到对应的记忆管理器
- **六个 Memory Manager**：每个负责一种记忆类型的维护
- **Chat Agent**：负责与用户进行自然语言交互

**记忆更新工作流**（对应论文图 6）：

1. 收到用户输入后，系统**先自动在记忆库中搜索**；
2. 检索结果与用户输入一并传给 Meta Memory Manager；
3. Meta Memory Manager 分析内容，判断哪些记忆组件需要更新，并将任务并行路由给对应的 Memory Managers；
4. 各 Memory Manager **并行**更新各自的记忆，同时确保不写入冗余信息；
5. 完成后向 Meta Memory Manager 汇报，后者发出确认信号。

**对话检索工作流**（对应论文图 7）：

1. Chat Agent 收到用户查询后，先对六个记忆组件做一次**粗粒度全局检索**，返回高层摘要；
2. Chat Agent 分析查询，决定哪些记忆组件需要更精细的检索，并选择合适的检索方法；
3. 汇总相关信息后，合成最终回答；
4. 若用户的查询涉及记忆更新（如提供新事实或纠正信息），Chat Agent 可直接与对应的 Memory Manager 交互，对指定记忆组件进行精确更新。

### 三、应用与用例

#### 3.1 MIRIX 应用程序

作者基于 MIRIX 构建了一个跨平台桌面应用，前端使用 React-Electron，后端使用 Uvicorn。

**截图监控**：每 1.5 秒截一张图；若与上一张相似度 $> 0.99$ 则丢弃；积累 20 张独特截图后触发记忆更新（约每 60 秒一次）。为降低延迟，采用**流式上传策略**——每张截图一旦从前端接收就立即上传，而不是等凑够 20 张再批量发送，利用 Gemini API 通过 Google Cloud URL 异步加载图像。这将端到端延迟从约 50 秒（GPT-4 直接上传图像）降低至 5 秒以内。

**聊天界面**：用户可以查询助手关于过往活动的信息，Agent 基于积累的记忆内容给出个性化回答。

**记忆可视化**：系统将知识组织为结构化的记忆组件，支持树状视图（如语义记忆按层次分类展示：Favorites → Sports → Basketball）和列表视图（如程序记忆的步骤列表）。

#### 3.2 可穿戴设备与 Agent 记忆市场

论文还展望了两个场景：一是将 MIRIX 集成到 AI 眼镜、AI 引脚等可穿戴设备上，提供基于情节记忆的"上周在会议上看到了什么"等查询能力；二是构建一个去中心化的"Agent 记忆市场"，将个人记忆视为数字资产，通过加密和权限控制实现记忆的共享、交易与货币化。这两部分更像是愿景性描述，不是本文的实验核心。

### 四、实验设计

#### 4.1 数据集

**ScreenshotVQA（新提出的基准）**

作者收集了三名博士生的电脑使用截图数据：

- 第一位：重度用户，单日（2025-03-09）采集 **5,886** 张截图，提出 11 个问题
- 第二位：中度用户，20 天内（2025-05-16 至 06-06）采集 **18,178** 张，提出 21 个问题
- 第三位：轻度用户，一个多月内（2025-05-02 至 06-14）采集 **5,349** 张，提出 55 个问题

每张截图分辨率在 2K 到 4K 之间，总计约 **20,000 张**高分辨率截图。这个规模完全超出了现有长上下文模型的处理能力——以 Gemini 为例，即使缩放到 256×256 分辨率，单次 prompt 最多也只能容纳约 3,600 张图。问题由学生手动创建并经过人工核验，确保可回答性。

**LOCOMO（已有基准）**

包含 10 段对话，每段约 600 轮、平均 26,000 tokens，每段对话对应约 200 个评测问题，覆盖 single-hop、multi-hop、temporal、open-domain 四类（论文遵循 Mem0 的设置，排除了 adversarial 类）。

#### 4.2 评测指标

两个基准均使用 **LLM-as-a-Judge** 作为主要指标，具体是用 GPT-4.1 作为裁判，对比生成的回答与标准答案，判断回答是否成功解答了问题。

#### 4.3 实现细节

- **ScreenshotVQA**：所有实验统一使用 `gemini-2.5-flash-preview-04-17` 作为骨干模型。选择 Gemini 是因为它与 Google Cloud 的原生集成支持异步图像上传，极大加快了处理速度。
- **LOCOMO**：使用 `gpt-4.1-mini` 作为骨干模型，因其在 Berkeley Function Calling Benchmark 上的多轮函数调用准确率（29.75%）显著优于 `gpt-4o-mini`（22.12%），而 MIRIX 的多智能体架构需要大量函数调用能力。

### 五、实验结果

#### 5.1 ScreenshotVQA 结果

对比基线：

- **Gemini（长上下文基线）**：将截图缩放到 256×256 后，取最近 3,600 张直接塞入 prompt 回答问题
- **SigLIP@50（RAG 基线）**：用 SigLIP 模型检索与查询最相关的 50 张原始分辨率图像，再用 Gemini 生成答案

| 方法 | 学生1 准确率 | 学生2 准确率 | 学生3 准确率 | 整体准确率 | 整体存储 |
| --- | --- | --- | --- | --- | --- |
| Gemini | 0.0000 | 0.0952 | 0.2545 | **0.1166** | 236.70 MB |
| SigLIP@50 | 0.3636 | 0.4138 | 0.5455 | **0.4410** | 15.07 GB |
| MIRIX | 0.5455 | 0.5667 | 0.6727 | **0.5950** | 15.89 MB |

MIRIX 相比 RAG 基线（SigLIP）准确率提升约 **35%**，存储降低约 **99.9%**；相比长上下文基线（Gemini）准确率提升约 **410%**，存储降低约 **93.3%**。MIRIX 完全不存储原始图像，只维护一个紧凑的 SQLite 数据库，存储所有提取出的结构化信息。

Gemini 基线表现极差（学生1准确率为 0），是因为截图量超出了其上下文窗口的承载能力，大量早期信息被截断。

#### 5.2 LOCOMO 结果

对比基线包括 A-Mem、LangMem、OpenAI（ChatGPT 记忆）、Mem0、Memobase、Zep 以及 Full-Context（将完整对话文本塞入 prompt，相当于理论上界）。

| 方法 | Single-Hop | Multi-Hop | Open-Domain | Temporal | 整体 |
| --- | --- | --- | --- | --- | --- |
| Zep (gpt-4.1-mini) | 79.43 | 69.16 | 73.96 | 83.33 | 79.09 |
| LangMem (gpt-4.1-mini) | 74.47 | 61.06 | 67.71 | 86.92 | 78.05 |
| Mem0 (gpt-4.1-mini) | 62.41 | 57.32 | 44.79 | 66.47 | 62.47 |
| **MIRIX** | **85.11** | **83.70** | **65.62** | **88.39** | **85.38** |
| Full-Context（上界） | 88.53 | 77.70 | 71.88 | 92.70 | 87.52 |

MIRIX 整体得分 **85.38%**，超越最强基线 Zep 约 **6.3 个百分点**，超越 LangMem 约 **7.3 个百分点**，与理论上界 Full-Context（87.52%）的差距仅约 **2.1 个百分点**。

各类问题的表现分析：

- **Single-Hop**：MIRIX 表现最好，但与 Full-Context 有小幅差距。作者分析原因是某些问题本身存在歧义，例如问"Melanie 计划何时去露营？"，MIRIX 存储的是最终发生的事件，而问题可能期待的是最初计划的日期。
- **Multi-Hop**：MIRIX 领先优势最大，超越所有基线 **24 个百分点以上**，甚至超过了 Full-Context（77.70% vs. 83.70%）。原因在于 MIRIX 会主动将多跳信息整合后存储，例如直接存储"Caroline 4 年前从她的家乡瑞典搬来"，而不是分别存储两条碎片（"Caroline 4 年前从家乡搬来" + "Caroline 的家乡是瑞典"），避免了推理时的跨条目拼接失败。对于非推理模型（如 `gpt-4.1-mini`）而言，这种额外的推理步骤很容易失败。
- **Open-Domain**：MIRIX 表现不错但优势缩小，且与 Full-Context 有明显差距。这类问题通常是"如果……会怎样"式的长期推断，需要全局理解，而 MIRIX 依然依赖 RAG 检索相关片段，缺乏全局视野是 RAG 类方法的固有局限。
- **Temporal**：MIRIX 表现出色（88.39%），仅次于 Full-Context（92.70%）。

三次独立运行的结果（整体准确率分别为 83.98%、87.34%、84.82%）显示系统有一定波动但始终保持 SOTA 水平。

### 六、相关工作对比

论文将相关工作分为三个维度：

**记忆增强 LLM（潜空间记忆）**：包括修改 Transformer 架构在参数、外部记忆矩阵、隐藏状态等处加入记忆。这类方法通常需要重新训练，与 GPT-4、DeepSeek 等闭源模型不兼容；基于 KV 缓存的方法则更像长上下文方法，缺乏真正的记忆抽象与整合能力。

**记忆增强 LLM Agent（Token 级记忆）**：Zep、Mem0、MemGPT 等代表性工作。这类系统在长期对话基准上表现不错，但记忆架构过于简化，缺乏模块化组件导致路由效率低。

**多智能体系统**：AutoGPT、BabyAGI 采用规划-执行循环；MetaGPT 模拟软件开发团队；AgentVerse 引入角色专业化。MIRIX 基于这些思想，部署 8 个专业化 Agent 分别管理不同记忆类型，并有效协调多模态输入的处理。

---

### 七、局限性与未来工作

论文坦诚了若干局限：

1. **Open-Domain 问题的全局理解瓶颈**：依赖 RAG 检索的架构本质上难以获得全局上下文视野，导致需要长链推断的开放式问题表现有所欠缺。
2. **歧义性问题**：记忆整合可能丢失原始信息的部分细节，在问题有歧义时可能选错参考点。
3. **评测规模**：ScreenshotVQA 的问题数量相对有限（共 87 个问题），且来自特定人群（博士生），泛化性有待验证。

未来工作方向包括：构建更具挑战性的真实世界基准，以及持续改进 MIRIX 和配套个人助手应用。

## 原文摘要

Although memory capabilities of AI agents are gaining increasing attention, existing solutions remain fundamentally limited. Most rely on flat, narrowly scoped memory components, constraining their ability to personalize, abstract, and reliably recall user-specific information over time. To this end, we introduce MIRIX, a modular, multi-agent memory system that redefines the future of AI memory by solving the field's most critical challenge: enabling language models to truly remember. Unlike prior approaches, MIRIX transcends text to embrace rich visual and multimodal experiences, making memory genuinely useful in real-world scenarios. MIRIX consists of six distinct, carefully structured memory types: Core, Episodic, Semantic, Procedural, Resource Memory, and Knowledge Vault, coupled with a multi-agent framework that dynamically controls and coordinates updates and retrieval. This design enables agents to persist, reason over, and accurately retrieve diverse, long-term user data at scale. We validate MIRIX in two demanding settings. First, on ScreenshotVQA, a challenging multimodal benchmark comprising nearly 20,000 high-resolution computer screenshots per sequence, requiring deep contextual understanding and where no existing memory systems can be applied, MIRIX achieves 35% higher accuracy than the RAG baseline while reducing storage requirements by 99.9%. Second, on LOCOMO, a long-form conversation benchmark with single-modal textual input, MIRIX attains state-of-the-art performance of 85.4%, far surpassing existing baselines. These results show that MIRIX sets a new performance standard for memory-augmented LLM agents. To allow users to experience our memory system, we provide a packaged application powered by MIRIX. It monitors the screen in real time, builds a personalized memory base, and offers intuitive visualization and secure local storage to ensure privacy.
