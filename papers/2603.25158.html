Trace2Skill: Distill Trajectory-Local Lessons into Transferable Agent Skills

Jingwei Ni, Yihao Liu, Xinpeng Liu, Yutao Sun, Mengyu Zhou, Pengyu Cheng, Dexin Wang, Erchao Zhao, Xiaoxi Jiang, Guanjun Jiang

详细解读

核心总结

Trace2Skill 是一个将 LLM Agent 的执行轨迹（trajectory）蒸馏为可移植技能文档（skill）的框架。其核心思路是：让 Agent 先在一批任务上运行并收集成功/失败的执行轨迹，然后由分析子 Agent 并行地从每条轨迹中提取局部经验教训（称为 patch），最后通过层次化合并将所有 patch 整合为一份紧凑、通用的技能文档。这份技能文档不需要修改模型参数，也不需要在推理时做检索，直接作为 system prompt 的一部分加载即可。实验表明，这样蒸馏出的技能不仅在分布内任务上有效，还能跨模型规模、跨模型家族、跨任务分布迁移——例如用 35B 模型轨迹演化出的技能能让 122B 模型在 WikiTableQuestions 上提升多达 57.65 个百分点。

1. 研究动机与问题背景

1.1 什么是 Agent Skill

在当前 LLM Agent 生态中，skill（技能） 是一种可复用的文档制品，通常以 Markdown 文件为核心，包含任务流程、领域知识、操作规范和注意事项。例如 Anthropic 为 Claude 发布了处理 xlsx、pdf、docx、pptx 等文件的官方 skill。Agent 在推理时加载这些 skill 文档，就能获得特定领域的操作指导。

1.2 现有方法的问题

论文指出现有方法存在三个核心问题：

  1. 人工编写 skill 不可扩展：人工写的 skill 质量不稳定，同一份 skill 对大模型有效但可能对小模型有害。例如 Table 1 显示，Anthropic 官方的 xlsx skill 让 122B 模型提升了，但让 35B 模型反而下降了。
  2. 纯参数知识生成的 skill 质量差：直接让 LLM 从自身参数知识生成 skill（称为 Parametric），效果接近于没有 skill，因为这种方式缺乏实际执行中暴露出的具体失败模式和操作细节。
  3. 现有的经验复用方法有局限： - 检索式记忆（如 ReasoningBank）：将每条轨迹的经验存为独立记忆条目，推理时检索相关条目。问题是知识碎片化，且依赖检索质量。 - 顺序编辑式技能演化：每来一条新轨迹就更新一次 skill，导致后续编辑依赖于之前编辑的顺序，容易产生顺序敏感性。

1.3 核心洞察

人类专家通常不是逐条处理轨迹，而是先广泛审视大量案例，抽象出反复出现的模式，再写出紧凑可复用的操作规程。Trace2Skill 模拟了这一过程。

2. Trace2Skill 方法详解

2.1 形式化定义

一个 skill 被定义为 $\mathcal{S} = (M, \mathcal{R})$，其中 $M$ 是核心的 SKILL.md 文件，$\mathcal{R}$ 包含辅助的参考文件、脚本或资源。
设 $\pi_\theta$ 是一个固定的 LLM Agent（参数不更新），$\mathcal{P}(\mathcal{S}; \pi_\theta, \mathcal{D})$ 表示该 Agent 使用 skill $\mathcal{S}$ 在任务集 $\mathcal{D}$ 上的通过率。给定演化集 $\mathcal{D}_{\text{evolve}}$ 和不相交的测试集 $\mathcal{D}_{\text{test}}$，技能演化的目标是：

$\displaystyle \mathcal{S}^\* = \mathcal{E}(\mathcal{S}_0, \mathcal{D}_{\text{evolve}}; \pi_\theta), \quad \mathcal{P}(\mathcal{S}^\*; \pi_\theta, \mathcal{D}_{\text{test}}) > \mathcal{P}(\mathcal{S}_0; \pi_\theta, \mathcal{D}_{\text{test}}).$

注意，整个过程不更新模型参数 $\theta$，只改变 skill 文档。
论文考虑两种初始 skill $\mathcal{S}_0$：

  • Skill Deepening：从人类专家编写的 skill 出发进行深化。
  • Skill Creation：从 LLM 参数知识生成的弱 skill 出发进行创建。

2.2 三阶段流水线

Stage 1: 轨迹生成（Trajectory Generation）

使用 ReAct 风格的 Agent 框架。对演化集中的每个任务，固定的 Agent $\pi_\theta$ 加载初始 skill $\mathcal{S}_0$ 运行，产生一条轨迹 $\tau_i$，包含：查询、推理/工具使用历史、最终输出、以及一个二值正确性标签。
所有轨迹被分为失败集 $\mathcal{T}^-$ 和成功集 $\mathcal{T}^+$。轨迹生成是完全并行的，各任务之间互不依赖。

Stage 2: 并行 Patch 提议（Parallel Patch Proposal）

一组分析子 Agent 独立地从各条轨迹中提出 skill patch（技能补丁）。关键设计是两种不对称的分析角色：

  • 错误分析师 $\mathcal{A}^-$：处理失败轨迹。使用 ReAct 风格的交互式循环，可以检查输入/输出文件、对比 Agent 输出与标准答案、验证候选修复方案。只有能被因果解释的失败才会被保留，无法解释的失败被排除。这确保了 patch 基于已验证的失败机制而非仅凭日志猜测。
  • 成功分析师 $\mathcal{A}^+$：处理成功轨迹。使用单次调用的工作流，识别成功轨迹中可复用的行为模式。
    两种分析师都被提示按照 skill 编写规范生成简洁、可操作的 patch。最终得到 patch 池 $\mathcal{P} = \mathcal{P}^- \cup \mathcal{P}^+$。
Stage 3: Patch 整合（Patch Consolidation）

这是 Trace2Skill 最核心的步骤。所有 patch 通过层次化合并被整合为一个统一的更新 $p^\*$。合并过程进行 $L = \lceil \log_{B_{\text{merge}}} |\mathcal{P}| \rceil$ 层；在每一层 $\ell$，每次最多将 $B_{\text{merge}}$ 个 patch 合成为一个：

$\displaystyle p^{(\ell+1)} = \mathcal{M}\left(\pi_\theta, \mathcal{S}_0, \{p_1^{(\ell)}, \ldots, p_{B_{\text{merge}}}^{(\ell)}\}\right), \quad \ell = 0, \ldots, L-1,$

其中合并算子 $\mathcal{M}$ 执行以下操作：

  • 去重：多个 patch 提出相同或相似的编辑时，保留最佳版本。
  • 解决冲突：对同一部分提出矛盾编辑时，选择更有依据的版本或综合两者。
  • 保留独特洞察：不同 patch 针对不同失败的独特编辑都被保留。
  • 归纳泛化：由于每个 patch 来自独立的轨迹，多个独立 patch 反复提出相似编辑被视为系统性任务属性的证据（而非一次性修复），$\mathcal{M}$ 被指示优先保留这些高频模式，丢弃特异性编辑。
    一个关键设计是：$\pi_\theta$ 自身同时充当轨迹生成器、分析师和合并算子，不需要外部教师模型。
    最终的 $p^\*$ 被转换为 diff 格式的编辑，并通过确定性的安全机制应用：拒绝对不存在文件的编辑、保留有行范围冲突的编辑、验证更新后的 skill 格式。

3. 实验设置与主要结果

3.1 电子表格实验（主实验）

数据集：SpreadsheetBench-Verified（400 样本，200 用于演化，200 用于测试），Agent 通过工具使用操作 xlsx 文件。还报告了 OOD 迁移到 WikiTableQuestions 和 HiTab 的结果。
Skill 设置：

  • No Skill：不使用任何 skill
  • Human-Written：Anthropic 官方 xlsx skill
  • Parametric：LLM 从参数知识生成的 skill
  • +Error / +Success / +Combined：Trace2Skill 的三个变体，分别只用失败轨迹、只用成功轨迹、或两者都用

模型：Qwen3.5-122B-A10B 和 Qwen3.5-35B-A3B 分别作为 skill 作者（author）和 skill 使用者（user）。采用 100% 自演化：同一个模型生成轨迹、提出 patch、编辑 skill。

3.2 主要结果（Table 1）

Table 1 是论文最核心的结果表。关键发现：

  1. Deepening 和 Creation 都产生可泛化的 skill： - 从 Human-Written 出发的 Deepening 一致性地增强了分布内性能，并经常迁移到其他模型规模和 OOD 任务。 - 从 Parametric 出发的 Creation 在有利条件下可以匹配甚至超过 Human-Written 的质量。
  2. 小模型也能写出好 skill：35B 模型作为 author 的 Deepening +Combined 取得了最高的综合 Avg 分数，说明小模型编写的 skill 也能泛化。
  3. 跨模型规模迁移：用 35B 模型轨迹演化出的 skill 能显著提升 122B 模型的性能。例如，35B Creation +Error 在 WikiTQ 上为 122B 用户带来了 +57.65 个百分点的提升。
  4. +Combined 通常给出最大的综合提升。

3.3 跨模型家族泛化（Figure 3）

用 Gemma-4-31B-it 和 GPT-5.5-high 测试跨家族泛化：

  • 每个模型都能从自己的轨迹中自我改进。
  • 每个模型也能受益于 Qwen3.5 编写的 skill。
  • 例如 Qwen3.5-122B 编写的 Deepening +Combined skill 让 GPT-5.5 从 52.0% 提升到 78.5%。

3.4 数学推理（Table 2）

在 DAPO 数学题上创建 skill，评估在 held-out DAPO（ID）和 AIME 2026（OOD 竞赛数学）上的表现。结果显示 Trace2Skill 在数学领域同样有效，蒸馏出的 skill 同时提升了 ID 和 OOD 性能。+Error 是最稳定的信号。

3.5 视觉问答（Table 3）

在 DocVQA 上测试多模态泛化。仅用 50 个样本做 skill 演化，在剩余 5,299 个样本上评估。所有演化出的 DocVQA skill 都优于 No Skill，+Combined 是最强设置，ANLS 提升最高达 +0.2534。

4. 深入分析

4.1 核心设计对比

论文通过控制变量实验隔离了三个核心设计选择：

并行整合 vs. 顺序编辑（Table 4）

对比了三种方式：

  • Seq-$B$=1：每来一条轨迹就更新一次 skill（~60 分钟）
  • Seq-$B$=4：每 4 条轨迹更新一次（~15 分钟）
  • Parallel（Trace2Skill）：所有轨迹并行分析后一次性合并（~3 分钟）
    结果：并行整合在 122B 用户的所有 SpreadsheetBench 指标上都更好，速度快 5-20 倍。这是因为并行方式避免了顺序依赖，每个分析师看到的都是原始 skill $\mathcal{S}_0$，不受之前编辑的影响。
整体 Skill vs. 检索式记忆（Table 5）

对比了 Trace2Skill 与 ReasoningBank 风格的检索记忆。ReasoningBank 存储每条轨迹的经验教训，推理时用 embedding 检索最相关的记忆。结果：Trace2Skill 的单一整合 skill 一致性地优于 ReasoningBank 检索。这支持了将轨迹证据整合为紧凑 skill 优于在推理时检索孤立记忆的观点。

Agentic 错误分析 vs. 单次 LLM 调用（Figure 4）

对比了交互式 Agentic 错误分析师（可以检查文件、对比答案、验证修复）与单次 LLM 调用（只读执行日志）。结果：Agentic 分析师在大多数设置下取得更高的 Avg。定性分析显示，单次 LLM 调用容易产生日志级别的误报——例如在解析错误消息出现时，单次 LLM 在 57% 的情况下将其归因为主要根因，而 Agentic 分析师只在 14% 的情况下这样做。

4.2 学到的标准操作规程（SoPs）

论文检查了 122B Deepening +Combined 运行产生的 323 个 patch，发现四个主导的 SoP：

  1. 公式重新计算和写回验证（55.1% 的 patch 引用）：写入公式后必须运行 recalc.py 并用 data_only=True 重新打开验证。
  2. 工具选择：openpyxl 优于 pandas.to_excel()（54.8%）：pandas.to_excel() 会静默破坏公式关系。
  3. 显式读回验证（42.7%）：写入后重新打开输出文件确认每个目标单元格的值。
  4. 结构编辑安全（16.4%）：按降序删除行以防止索引偏移损坏。
    低频的特殊情况被路由到 references/ 子目录中的 13 个补充参考文件，而非主 SKILL.md。这自动恢复了人类 skill 设计实践中从通用到特殊的层次结构。

4.3 选择性 Patch 聚合

论文探索了是否选择 patch 子集能比使用全部 patch 更好：

  • 贪心选择（Figure 5）：每次迭代添加验证集上表现最好的单个 patch。结果：贪心曲线快速上升但很快平台化，始终低于 Trace2Skill 的全量聚合。原因有二：(1) patch 无关回归——patch 在修复某些任务的同时也破坏了之前正确的其他任务；(2) 语义重叠——反复出现的失败模式导致 patch 之间高度重叠，新 patch 边际收益很小。这说明 patch 的价值是组合性的，不是单个 patch 贡献的简单加和。
  • 贝叶斯优化（BO）（Table 6）：直接搜索 patch 子集的二值包含向量。BO 能进一步提升性能（例如 Vrf 从 65.83 提升到 69.83），但计算成本高——每个候选子集都需要物化为 skill 并在验证集上运行。

4.4 更广泛的应用

Trace2Skill 还在 PDF 提取、PPTX 编辑、DOCX 编辑三个领域验证了有效性（Table 13）：

  • PDF：VRDU 轨迹迁移到 VAREX，通过率从 76.9% 提升到 85.3%
  • PPTX：TSBench 轨迹迁移到不同幻灯片的 OOD 分割，从 72.5% 提升到 88.8%
  • DOCX：合成任务轨迹迁移到 OfficeBench DOCX 子集，从 79.7% 提升到 87.5%

5. 与同期系统的对比（Appendix G）

论文在附录中与三个同期系统（XSkill、EvoSkill、SkillGen）进行了直接对比（Figure 7），统一使用 Qwen3.5-122B-A10B 模型和 SpreadsheetBench-Verified。结果：

  • XSkill：23.0% Vrf
  • SkillGen：27.5% Vrf
  • EvoSkill (Claude Code)：33.5% Vrf
  • EvoSkill (React)：59.5% Vrf
  • Trace2Skill +Error：65.8% Vrf
  • Trace2Skill +Combined：69.8% Vrf
    论文谨慎地指出，整体系统对比混淆了设计理念与工程实现，因此主要因果性声明基于 §4.1 的控制变量实验。

6. 关键技术细节

模型服务

使用 Qwen3.5-122B-A10B 和 Qwen3.5-35B-A3B，都是 instruct/think 混合 MoE 模型。多轮 ReAct Agent 使用 instruct 模式，单次调用步骤（层次合并、成功分析、patch 转换）使用 thinking 模式。通过 vLLM 服务。

效率

Stage 2 使用 128 个并行 worker，merge batch size 为 32。整个 patch 分析和合并过程约 3 分钟完成（8×A100 节点），而顺序编辑需要 15-60 分钟。

实验规模

总计约 20,000 GPU 小时。所有结果在三个随机种子（41, 42, 43）上取平均。

7. 局限性

Trace2Skill 默认应用所有整合后的 patch。虽然贝叶斯优化可以选择更高质量的子集，但成本很高：需要大规模的代表性验证集，且 BO 必须为每个候选子集物化并评分一个新 skill。论文将更深入的组合式 patch 选择留作未来工作。

8. 总结性要点

Trace2Skill 的核心贡献可以概括为：

  1. 方法论：提出了一种模拟人类专家 skill 编写过程的自动化框架——先广泛分析轨迹，再归纳整合为紧凑 skill。
  2. 可迁移性：蒸馏出的 skill 是静态文档，不需要参数更新或推理时检索，可以跨模型规模、跨模型家族、跨任务分布直接复用。
  3. 并行优于顺序：并行整合不仅更快（20 倍加速），而且通常质量更好，因为避免了顺序依赖。
  4. 整合优于检索：单一紧凑 skill 优于检索式记忆，因为它将分散的局部经验压缩为系统性的操作规程。
  5. Agentic 分析优于被动分析：交互式错误分析（可检查文件、验证修复）比仅读日志的单次分析更准确。

  • 手动编写技能无法规模化
  • 纯参数知识生成的技能缺乏实际执行中的失败模式与操作细节
  • 现有技能演化方法的不足
  • 按轨迹逐条检索局部经验，知识碎片化
  • 顺序编辑技能导致依赖更新顺序，效率低且不稳定
  • 核心目标
  • 将大量执行轨迹并行整合为统一、可移植的技能目录
  • 支持两种场景：深化已有人工技能 & 从弱LLM草稿创建新技能
  • 生成的技能可跨模型规模、模型家族及分布外任务迁移

研究方法

  • 三阶段流水线（Trace2Skill Pipeline）
  • 阶段1：轨迹生成
    • 使用ReAct风格框架，冻结智能体收集成功/失败轨迹
    • 轨迹包含查询、推理/工具使用历史、最终输出及正确性标签
  • 阶段2：并行补丁提议
    • 错误分析师（A⁻）：ReAct循环，可检查工件、对比真值、验证修复
    • 成功分析师（A⁺）：单次调用，提取可复用行为模式
    • 无法因果解释的失败被排除，确保补丁基于验证的失败机制
  • 阶段3：补丁层级合并
    • 层级式合并：去重、解决冲突、保留非重叠洞察
    • 归纳泛化：优先保留跨轨迹反复出现的模式，丢弃特异性编辑
    • 最终生成一个紧凑的技能目录，推理时直接使用，无需检索
  • 技能形式化
  • 技能定义为人类可读目录 S = (M, R)，包含根文档SKILL.md与辅助文件
  • 同一模型同时充当轨迹生成器、分析师和合并操作者（100%自演化）
  • 两种模式
  • 技能深化（Skill Deepening）：从人工编写技能出发
  • 技能创建（Skill Creation）：从LLM参数知识生成的草稿出发

关键研究结果

  • 电子表格任务（主实验）
  • 深化与创建模式均显著提升分布内和分布外性能
  • 35B模型编写的技能可提升122B模型表现，反之亦然
  • 35B轨迹演化的技能在WikiTableQuestions上提升122B智能体高达57.65个百分点
  • 跨模型家族迁移
  • Gemma-4和GPT-5.5均可受益于Qwen3.5编写的技能
  • 各模型也可从自身轨迹自我改进
  • 数学推理与视觉问答
  • 数学领域：DAPO和AIME均获提升，+Error信号最稳定
  • DocVQA：所有演化技能均优于无技能基线，+Combined效果最强
  • 核心设计对比分析
  • 并行合并 vs 顺序编辑：质量相当或更优，速度快20倍（约3分钟 vs 60分钟）
  • 整合技能 vs 检索记忆：单一蒸馏技能优于ReasoningBank风格的检索
  • 智能体式错误分析 vs 单次LLM调用：交互式诊断产生更精准的根因补丁
  • 学习到的标准操作程序（SoPs）
  • 公式重算与回读验证（55.1%补丁）、工具选择指南（54.8%）、显式回读验证（42.7%）、结构编辑安全（16.4%）
  • 补丁价值具有组合性
  • 贪心选择快速上升后停滞，低于全量聚合
  • 贝叶斯优化可进一步提升但计算成本高

研究结论与意义

  • 核心贡献
  • 提出Trace2Skill框架，模拟人类专家从广泛轨迹中归纳紧凑可复用程序的过程
  • 并行归纳推理优于顺序编辑和检索式记忆
  • 广泛影响
  • 技能可跨模型规模、模型家族和分布外任务迁移，无需参数更新或测试时检索
  • 适用于多种领域：电子表格、数学推理、文档VQA、PDF/PPTX/DOCX编辑
  • 在与XSkill、EvoSkill、SkillGen等并发系统的对比中展现优势
  • 局限性
  • 默认应用所有合并补丁；贝叶斯优化选择子集有效但成本高
  • 组合式补丁选择的高效方法有待未来探索

原文摘要

Large Language Model (LLM) agents increasingly rely on domain-specific skills, yet manually authoring such skills does not scale, and skills generated purely from parametric knowledge often miss critical operational pitfalls. We introduce Trace2Skill, a framework that consolidates broad execution trajectories in parallel into a unified skill directory through inductive reasoning over agent experience. Trace2Skill supports both deepening existing human-written skills and creating useful skills from weak LLM-generated drafts. Experiments demonstrate the effectiveness of Trace2Skill across diverse domains, including office workflows, math reasoning, and vision QA. Importantly, the evolved skills are not merely memorized artifacts of the trajectories used to create them: they often transfer across model scales, across model families, and to out-of-distribution settings. For example, skills evolved from Qwen3.5-35B trajectories improve a Qwen3.5-122B agent by up to $57.65$ percentage points on WikiTableQuestions. Further analyses show that Trace2Skill outperforms sequential skill editing and ReasoningBank-style retrieval memories, compresses recurring failures and workarounds into standard operating procedures (SoPs), and yields portable skills that can be reused without parameter updates or test-time retrieval.
