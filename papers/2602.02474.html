MemSkill: Learning and Evolving Memory Skills for Self-Evolving Agents

Haozhen Zhang, Quanyu Long, Jianzhu Bao, Tao Feng, Weizhi Zhang, Haodong Yue, Wenya Wang

论文原文 ↗下载文献卡片 Markdown

核心机制

控制器选择记忆技能，执行器构建记忆，designer 用难例修订技能库

详细解读

论文核心总结

MemSkill 提出了一种面向 LLM Agent 的自进化记忆管理方法。其核心思想是：将传统记忆系统中人工设计的固定操作（如增/删/改/跳过）重新定义为可学习、可进化的"记忆技能"（memory skills）。系统维护一个共享的技能库，通过一个可训练的控制器（controller）为当前上下文选择相关技能子集，再由 LLM 执行器（executor）在这些技能的指导下一次性生成结构化记忆。更关键的是，系统引入了一个设计者（designer）模块，周期性地从训练中的困难案例中挖掘失败模式，据此改进现有技能或提出新技能，形成"学习使用技能"与"进化技能本身"交替进行的闭环优化流程。实验在 LoCoMo、LongMemEval、HotpotQA 和 ALFWorld 四个基准上验证了该方法的有效性和跨场景泛化能力。

一、研究背景与动机

1.1 现有 Agent 记忆系统的问题

当 LLM Agent 参与越来越长的开放式交互时，它们需要管理不断增长的交互历史。现有的记忆系统通常依赖一套静态的、人工设计的记忆操作原语，例如：

  • 固定操作：add（添加）、update（更新）、delete（删除）、skip（跳过）
  • 启发式模块：手动编码"什么值得存储"、"如何修改记忆"、"何时剪枝"
    这些设计将人类的先验假设硬编码到系统中，存在三个核心缺陷：
  1. 刚性不足：在多样化的交互模式下表现脆弱，难以适应分布变化
  2. 扩展性差：随着历史长度增长，逐轮（turn-by-turn）处理效率低下
  3. 不可进化：固定的流程无法根据任务需求自动调整

1.2 理想记忆系统的三个属性

论文认为理想的 Agent 记忆系统应满足：

  • (i) 最小化对人类先验的依赖：记忆行为应由交互数据塑造，而非手动编码
  • (ii) 支持更大粒度的提取：不应局限于逐轮处理，应能在更长的文本跨度（span）上操作
  • (iii) 技能条件化的组合式记忆构建：选择并组合一小组相关技能，在一次生成步骤中完成记忆构建，而非依赖固定的专用模块

二、方法详解

2.1 系统总览

MemSkill 的核心架构如 Figure 2 所示，包含两个交织的优化过程：

  1. 学习使用技能：控制器选择上下文相关的技能，执行器应用这些技能生成记忆更新
  2. 进化技能本身：设计者周期性地基于困难案例修改现有技能并提出新技能
    系统维护两种存储：
  • 记忆库（Memory Bank）：每条交互轨迹（trace）特有的，存储该轨迹的具体记忆
  • 技能库（Skill Bank）：跨所有轨迹共享的，包含可复用的记忆技能

2.2 技能库（Skill Bank）

每个记忆技能 $s \in \mathcal{S}$ 是一个结构化的指导模板，包含：

  • (i) 简短描述（description）：用于技能的表示和选择
  • (ii) 详细内容规范（content）：指导执行器如何进行记忆提取或修改，具体包括四个字段：
  • Purpose：技能的目的
  • When to use：何时适用
  • How to apply：如何应用
  • Constraints：约束条件
    技能库从四个基本原语初始化：INSERT（插入新记忆）、UPDATE（更新现有记忆）、DELETE（删除无效记忆）、SKIP（无操作）。设计者会在训练过程中逐步改进和扩展这个技能库。

2.3 学习使用记忆技能

2.3.1 控制器：技能选择策略

MemSkill 在 span 级别（而非 turn 级别）更新记忆：将每条交互轨迹按 token 数切分为固定长度的连续文本段（span），然后顺序处理。
状态和技能表示：设 $x_t$ 为第 $t$ 步的当前文本段，$M_t = \{m_{t,1}, \ldots, m_{t,R}\}$ 为从当前记忆库中检索到的记忆。首先用固定的嵌入模型 $e(\cdot)$ 编码，然后通过可训练的网络得到状态和技能表示：

$\displaystyle h_t = f_\theta^{\text{ctx}}([e(x_t); \bar{m}_t]), \quad u_i = f_\theta^{\text{skill}}(e(\text{desc}(s_i)))$

其中 $\bar{m}_t = \frac{1}{R}\sum_{r=1}^{R} e(m_{t,r})$ 是检索记忆嵌入的均值。$f_\theta^{\text{ctx}}$ 和 $f_\theta^{\text{skill}}$ 是控制器中的可训练神经网络。
兼容进化技能库的评分机制：控制器不使用固定维度的动作头，而是将状态表示与每个候选技能表示拼接后，通过共享评分器并行打分：

$\displaystyle z_{t,i} = f_\theta^{\text{score}}([h_t; u_i]), \quad p_\theta(i \mid h_t) = \text{softmax}(z_t)_i$

其中 $z_t \in \mathbb{R}^{|\mathcal{S}_t|}$ 会随技能库大小变化而自适应调整。
Top-K 技能选择：给定分类分布 $p_\theta(i \mid h_t)$，控制器通过 Gumbel-Top-K 采样选择一个有序的 Top-K 技能子集 $A_t = (a_{t,1}, \ldots, a_{t,K})$，只将选中的技能传递给执行器。

2.3.2 执行器：技能条件化的记忆提取

执行器是一个固定的 LLM，以 (i) 当前文本段 $x_t$、(ii) 检索到的记忆 $M_t$、(iii) 选中的技能 $A_t$ 为条件，在一次 LLM 调用中生成结构化的记忆更新（INSERT/UPDATE/DELETE 操作）。
这种设计的优势在于：通过为同一文本段组合多个技能并在一次 LLM 调用中提取记忆，减少了逐轮重复处理的开销，更好地扩展到长交互历史。

2.3.3 控制器优化

使用强化学习训练控制器，以下游任务表现作为技能选择的反馈信号。
对于每条训练轨迹，控制器做出一系列 Top-K 选择，执行器逐步构建记忆库。构建完成后，在该轨迹的记忆依赖型训练查询上评估记忆库质量，将任务表现（如 F1 或成功率）作为奖励。
由于控制器的动作是一个无放回的有序 Top-K 列表，其联合概率为：

$\displaystyle \pi_\theta(A_t \mid h_t) = \prod_{j=1}^{K} \frac{p_\theta(a_{t,j} \mid h_t)}{1 - \sum_{\ell < j} p_\theta(a_{t,\ell} \mid h_t)}$

当 $K=1$ 时退化为标准的单动作情况。使用 PPO 算法进行优化，将上述联合对数概率替代标准的单动作对数概率。
具体的 PPO 目标函数为：

$\displaystyle \mathcal{L}_{\text{policy}}(\theta) = \mathbb{E}_t\left[\min\left(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right)\right]$

其中重要性比率 $r_t(\theta) = \frac{\pi_\theta(A_t \mid h_t)}{\pi_{\theta_{\text{old}}}(A_t \mid h_t)}$。

2.4 通过设计者反馈进行技能进化

困难案例缓冲区（Hard-case Buffer）

在控制器训练过程中，维护一个滑动窗口缓冲区，记录最近观察到的困难案例。每个案例以查询为中心，记录查询、真实答案、模型预测、检索到的记忆、任务表现和失败次数。
每个案例的难度分数定义为：

$\displaystyle d(q) = (1 - r(q)) \cdot c(q)$

其中 $r(q) \in [0,1]$ 是任务奖励，$c(q)$ 是累计失败次数。

选择代表性困难案例

通过聚类（如 KMeans）将困难案例分组，在每个聚类中优先选择难度分数高的代表性案例，确保覆盖不同的错误类型。

两阶段技能进化
  1. 分析阶段：LLM 分析选中的困难案例，识别缺失或错误指定的记忆行为
  2. 提议阶段：基于分析结果，提出对现有技能的具体修改和新技能的引入
    系统维护最佳技能库的快照，如果更新导致性能下降则回滚。当连续多次更新都无法改善训练信号时，执行早停。
新技能的探索激励

每次进化后，通过在 logit 层面偏向新引入的技能来短暂增加探索：

$\displaystyle z'_{t,i} = \begin{cases} z_{t,i} + \delta_q, & i \in \mathcal{S}_{\text{new}} \\ z_{t,i}, & \text{otherwise} \end{cases}$

目标阈值线性衰减：$\tau_q = \tau_0 \cdot (1 - \frac{q}{T_{\text{explore}}})$，默认 $\tau_0 = 0.3$，在前 $T_{\text{explore}} = 50$ 步内应用。

2.5 闭环优化

MemSkill 交替进行：

  1. 学习阶段：在当前技能库上训练控制器，构建记忆并积累困难案例
  2. 进化阶段：设计者利用代表性困难案例更新技能库
    每个循环结束后，如果性能没有改善则回滚到之前的最佳快照。下一个循环在更新后的技能库上继续训练，并增加探索以鼓励使用新技能。

三、实验设置

3.1 数据集

  • LoCoMo：长对话记忆基准，评估从长对话中构建记忆的能力
  • LongMemEval：长期交互记忆评估，每个样本约 100K tokens 的超长对话
  • HotpotQA：多跳问答数据集，用于研究分布偏移下的技能迁移
  • ALFWorld：具身交互任务环境，评估记忆对多步决策的支持能力
  • AppWorld（附录）：交互式工具使用基准

3.2 基线方法

包括 No-Memory、CoN、ReadAgent、MemoryBank、A-MEM、Mem0、LangMem、MemoryOS 等多种记忆方法。

3.3 评估指标

  • 对话基准：F1 分数和 LLM 判断分数（L-J）
  • 具身任务：成功率（SR）和交互步数（#Stps）

3.4 实现细节

  • 控制器中的 $f_\theta^{\text{ctx}}$、$f_\theta^{\text{skill}}$、$f_\theta^{\text{score}}$ 实现为独立的轻量级 MLP
  • 基础 LLM 使用 LLaMA-3.3-70B-Instruct 和 Qwen3-Next-80B-A3B-Instruct
  • 嵌入模型 $e(\cdot)$ 使用 Qwen3-Embedding-0.6B
  • 训练时每个对话 session 为一个处理单元，控制器选择 $K=3$ 个技能
  • 评估时 span 大小默认 512 tokens，对话基准 $K=7$，ALFWorld $K=5$
  • 技能进化每 100 个训练步触发一次，每轮最多 3 次技能编辑

四、实验结果

4.1 主实验结果（Table 1）

在所有数据集上，MemSkill 均取得了最优或最具竞争力的表现：

  • LoCoMo：LLaMA 上 L-J 达到 53.82（最佳基线 MemoryOS 为 48.64）
  • LongMemEval（迁移评估，无额外训练）：L-J 达到 60.89（最佳基线 CoN 为 56.44）
  • ALFWorld：平均成功率 80.36（LLaMA），81.29（Qwen 迁移）
    关键发现：
  • 跨模型泛化：仅在 LLaMA 上训练，直接迁移到 Qwen 仍保持竞争力
  • 跨数据集迁移：在 LoCoMo 上学到的技能直接迁移到 LongMemEval 仍取得最佳结果

4.2 分布偏移下的技能泛化（Figure 3）

将 LoCoMo 训练的技能库直接应用到 HotpotQA（文档风格叙述，非多轮对话），在 50/100/200 篇拼接文档三种设置下，MemSkill 均优于 MemoryOS 和 A-MEM，且在长上下文（200 篇）设置下优势更明显。这表明学到的记忆技能不依赖于对话特定的表面形式，而是捕获了可复用的提取和修改行为。
增加选择的技能数 $K$ 通常能提升性能，$K=7$ 在所有设置下表现最佳。

4.3 消融实验（Table 2）

在 LoCoMo 上的消融结果：

变体 LLaMA Qwen
MemSkill（完整） 53.82 54.14
w/o 控制器（随机选择技能） 48.43 42.84
w/o 设计者（固定初始技能） 46.50 36.15
仅精炼（不添加新技能） 47.45 48.88

关键结论：

  • 移除控制器（随机选择技能）导致明显下降，说明学习选择相关技能很重要
  • 移除设计者导致更大下降（尤其在 Qwen 上），说明技能进化对学习可复用记忆行为至关重要
  • 仅精炼优于固定技能，但不如完整版本，说明引入新技能带来额外收益

4.4 案例研究（Figure 4）

进化后的技能展现出明显的领域特化：

  • LoCoMo 技能：强调时间上下文（Capture Temporal Context）和活动细节（Capture Activity Details），表明对话记忆受益于轻量级事件结构
  • ALFWorld 技能：聚焦动作约束（Capture Action Constraints）和物体位置追踪（Track Object Location），表明具身任务需要可操作的世界状态记忆

五、与先前工作的对比

与现有方法的核心区别在于：

  1. vs. 固定操作方法（MemoryBank、A-MEM、MemoryOS 等）：这些方法使用人工设计的固定操作流程，MemSkill 将操作本身变为可学习、可进化的技能
  2. vs. RL 优化记忆方法（Memory-R1、Mem-α）：这些方法用 RL 优化记忆管理，但记忆操作仍是静态的手工设计；MemSkill 不仅学习如何使用技能，还进化技能本身
  3. vs. 自进化 Agent 方法（ExpeL、EvolveR、SkillWeaver 等）：这些方法关注任务技能或推理策略的进化，MemSkill 专注于记忆技能的进化——即 Agent 如何构建和维护记忆

六、技术亮点总结

  1. 技能抽象：将记忆操作从固定流程提升为结构化的可复用技能，每个技能包含目的、适用条件、应用方法和约束
  2. Span 级处理：不逐轮处理，而是在更大粒度的文本段上操作，显著减少 LLM 调用次数
  3. 兼容进化的控制器设计：通过共享评分器对状态-技能对打分，天然支持技能库大小的动态变化
  4. Top-K 无放回选择的 RL 优化：扩展 PPO 到有序 Top-K 动作空间，计算联合概率用于策略梯度
  5. 闭环进化：学习使用技能 → 收集困难案例 → 进化技能 → 继续学习，形成自改进循环
  6. 强泛化性：跨模型（LLaMA→Qwen）、跨数据集（LoCoMo→LongMemEval/HotpotQA）、跨领域（对话→具身任务→工具使用）均表现良好

原文摘要

Most Large Language Model (LLM) agent memory systems rely on a small set of static, hand-designed operations for extracting memory. These fixed procedures hard-code human priors about what to store and how to revise memory, making them rigid under diverse interaction patterns and inefficient on long histories. To this end, we present \textbf{MemSkill}, which reframes these operations as learnable and evolvable memory skills, structured and reusable routines for extracting, consolidating, and pruning information from interaction traces. Inspired by the design philosophy of agent skills, MemSkill employs a \emph{controller} that learns to select a small set of relevant skills, paired with an LLM-based \emph{executor} that produces skill-guided memories. Beyond learning skill selection, MemSkill introduces a \emph{designer} that periodically reviews hard cases where selected skills yield incorrect or incomplete memories, and evolves the skill set by proposing refinements and new skills. Together, MemSkill forms a closed-loop procedure that improves both the skill-selection policy and the skill set itself. Experiments on LoCoMo, LongMemEval, HotpotQA, and ALFWorld demonstrate that MemSkill improves task performance over strong baselines and generalizes well across settings. Further analyses shed light on how skills evolve, offering insights toward more adaptive, self-evolving memory management for LLM agents.
