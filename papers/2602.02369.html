Live-Evo: Online Evolution of Agentic Memory from Continuous Feedback

详细解读

论文核心总结

这篇论文提出了LIVE-EVO，一个面向持续在线任务流的自演化智能体记忆系统。与传统的"先在训练集上构建记忆、再在测试集上使用"的静态范式不同，LIVE-EVO能够在真实的、不断变化的数据流中持续学习和更新记忆。其核心创新在于将"发生了什么"（经验）和"如何使用经验"（元指南）解耦为两个独立的记忆库，并通过一个四阶段闭环（检索-编译-执行-更新）来持续优化记忆的使用方式。系统为每条经验维护权重，通过对比评估（有记忆 vs 无记忆）来判断经验是否有用：有用的经验被强化、更频繁地被检索，而误导性或过时的经验则被降权并逐渐遗忘，这类似于人类记忆中的强化与衰退机制。在Prophet Arena这一真实在线预测基准上，LIVE-EVO在10周时间跨度内将Brier分数改善了20.8%，市场回报提升了12.9%。

1. 研究背景与动机

1.1 LLM智能体的记忆系统

大语言模型（LLM）越来越多地被用作智能体系统的核心，使智能体能够通过工具使用与外部环境交互，解决复杂的多步骤任务。近年来出现了一类自演化智能体（self-evolving agents），它们能够从训练集中学习，构建工具、知识和任务解决策略。其中，从过去经验中学到的知识和策略被称为智能体的记忆（memory）。
这些记忆系统通常是分层组织的：

  • 低层级：原始观察和交互日志
  • 高层级：总结后的经验和抽象的指导原则（guidelines）
    在训练阶段，智能体可以根据交互结果动态地添加、更新或删除记忆条目；在测试阶段，智能体利用演化后的记忆来指导对未见任务的决策。

1.2 现有方法的局限性

现有的自演化记忆系统存在一个根本问题：它们大多是为静态的训练/测试划分设计的。如图1所示，传统方法在训练集上构建记忆，然后在固定的测试集上评估。即使有少数方法尝试研究在线任务流中的记忆问题，它们也只是通过将静态基准数据集折叠（folding）成多个子集来近似在线学习，因此基本忽略了真正流式任务中的分布漂移（distribution shift）问题。
然而，记忆演化本质上是一个在线问题。在真实部署中，智能体的经验是按时间顺序积累的，记忆必须持续更新——添加新证据、修订过时条目、整合反复出现的模式——而不是从静态语料库中重建。

1.3 在线预测基准的挑战

像Prophet Arena和FutureX这样的在线基准（live benchmarks）将智能体评估重新定义为纵向的未来预测问题。智能体需要预测即将发生的事件的概率，并通过校准指标（如Brier分数）和决策导向的结果（如市场回报）来评估。与静态任务不同，未来预测要求智能体在测试时持续演化，不断适应全新的任务。
在这种设置下，过去的经验可以提供有用的归纳偏置，但也可能随着模式漂移或失效而变得过时或具有误导性。因此，一个自演化记忆系统必须超越简单的存储：它应该主动管理经验，学习何时以及如何使用它们。

2. LIVE-EVO方法

2.1 整体架构

LIVE-EVO由两个记忆库组成：

  1. 经验库（Experience Bank）$\mathcal{E}$：存储过去的任务交互，以结构化、可复用的形式保存。每条经验包含问题、失败原因、改进建议、遗漏信息、类别等字段。
  2. 元指南库（Meta-Guideline Bank）$\mathcal{M}$：存储更高层级的组合指令，即元指南（meta-guidelines），指定如何在不同条件下将检索到的经验转化为任务自适应的指南。
    这两个库实现了一个关键的解耦：经验记录"发生了什么"，元指南编码"如何使用经验"。这使得记忆的使用方式能够随着新任务的到来而不断改进。

2.2 四阶段闭环

对于每个新任务批次，智能体执行四个阶段的循环：检索（Retrieve）→ 编译（Compile）→ 执行（Act）→ 更新（Update）。

阶段一：检索（Retrieve）

给定任务 $q$，智能体首先检索可能相关的经验和元指南：

$\displaystyle E_q, \hat{m} \leftarrow \text{RETRIEVE}(q, \mathcal{E}, \mathcal{M})$

关键设计：任务不会直接用于查询记忆库。相反，智能体从给定任务中生成多个查询，分别用于问题匹配和经验内容匹配。这种主动检索（active retrieval）设计使智能体能够从多个维度检索相关信息，寻找结构类比或推理模式，而不仅仅是简单的语义重叠。
检索时，每条经验按以下分数排序：

$\displaystyle \text{Score} = Weight \times Sim(exp, query)$

这里不仅考虑经验与查询之间的相似度，还乘以一个经验权重，该权重在演化周期中不断更新。只有加权相似度超过阈值 $\tau = 0.3$ 的经验才会被检索。

阶段二：编译（Compile）

智能体将检索到的经验转化为任务自适应的指导：

$\displaystyle g = \text{COMPILEGUIDELINE}(q, E_q, \hat{m})$

具体来说，COMPILEGUIDELINE执行元认知编译：

  1. 从多条经验中提取跨经验的规律性
  2. 将这些规律锚定在当前任务上下文中
  3. 根据元指南 $\hat{m}$ 实例化一个指南 $g$，用于指导下游决策
    这与以往方法形成对比——以往方法要么直接将检索到的日志拼接为上下文，要么依赖固定的抽象操作（如摘要或启发式规则），这些操作是静态的，不会从在线反馈中改进。
阶段三：执行（Act）

在任务和编译后的指南条件下，智能体执行策略：

$\displaystyle r_q, \tau_q = \text{ACT}(q \mid g)$

其中 $\tau_q$ 是执行轨迹，$r_q$ 是结果信号。在传统推理基准中，$r$ 通常是二元的（成功/失败）；而在在线基准中，$r$ 是连续反馈（如Brier分数），提供了比稀疏正确性奖励更丰富的学习信号。
关键机制——对比评估（Contrastive Evaluation）：对每个任务，系统额外执行一次不使用编译指南的推理，然后比较两次结果，量化记忆使用是否在该任务上提供了净收益。具体地，得到两个分数：$r_q^{on}$（使用记忆）和 $r_q^{off}$（不使用记忆）。

阶段四：更新（Update）

更新机制分为三个部分：
（1）经验权重更新
根据对比评估的经验增益 $r_q^{on} - r_q^{off}$ 来调整被选中经验的检索权重：

$\displaystyle Weight_{new} = Weight_{old} + (score_{noexp} - score_{exp})$

  • 当指南改善了性能时，对应经验的权重增加
  • 当指南损害了性能时，权重减少
    这种强化-衰退动态类似于人类记忆：有用的经验通过反复成功而被强化，误导性或过时的经验则逐渐被抑制。

（2）元指南生成
当 $r_q^{on} - r_q^{off} \leq 0$（即使用记忆反而更差）时，触发反思步骤，生成一条新的元指南，添加到元指南库中，以改进未来的指南编译：

$\displaystyle \mathcal{M} \leftarrow \mathcal{M} \cup \{\text{REFLECT}(q, g_q, E_q)\}$

（3）选择性经验获取
处理完一个批次后，系统不会无差别地存储每条轨迹，而是执行选择性经验获取：

  1. 识别在使用记忆设置下表现最差的 $\rho$ 比例的任务（论文中 $\rho = 0.3$）
  2. 从存储的轨迹中总结并反思，生成候选经验
  3. 用候选经验重新评估该任务
  4. 只有当候选经验带来统计显著的改善时，才将其提交到经验库
    这种"先验证再更新（Verify Before Update）"的协议控制了记忆增长，确保新条目有可衡量的收益支持。

2.3 完整算法流程

Algorithm 1给出了完整的伪代码。输入包括任务流批次 $\mathcal{Q}$、带权重的经验库 $\mathcal{E}$、元指南库 $\mathcal{M}$ 和差案例比例 $\rho$。对每个任务 $q$：

  1. 检索top-k经验和选定的元指南
  2. 编译任务特定的记忆指南
  3. 执行对比评估，得到有/无记忆的分数
  4. 更新经验权重；如果记忆使用失败，生成新的元指南
    批次处理完后，选择最差的 $\rho$ 比例任务，从轨迹中总结新经验，验证后提交。

3. 实验设置

3.1 评估基准

Prophet Arena：一个未来预测基准，跨越最近10周，共500个任务。每个任务包含一个问题、候选列表和关闭前6小时的出价快照。系统对Google搜索工具实施严格的基于时间的检索过滤，防止信息泄露。
Xbench-DeepResearch：用于评估LIVE-EVO在未来预测之外的泛化能力。将基准分成10折，按顺序学习经验，报告总体平均准确率。

3.2 评估指标

Brier分数（越低越好）：衡量预测概率的校准质量。给定查询 $q$ 和候选结果集 $\mathcal{C} = \{c_1, \ldots, c_K\}$，智能体输出概率 $\hat{\mathbf{p}} = (\hat{p}_1, \ldots, \hat{p}_K)$，真实结果为 $\mathbf{y} \in \{0,1\}^K$：

$\displaystyle \text{BS} = \sum_{k=1}^{K} (\hat{p}_k - y_k)^2$

市场回报（越高越好）：量化LIVE-EVO相对于市场共识的优势。当预测概率 $\hat{p}_k$ 超过市场隐含概率 $m_k$ 时，对结果 $c_k$ 做多：

$\displaystyle R = \sum_{k=1}^{K} \mathbb{I}[\hat{p}_k > m_k](y_k - m_k)$

3.3 基线方法

  1. 基础模型（Base Model）：检索top-10网页搜索结果，提供模型自身生成的摘要版本，基于静态信息输出概率分布。
  2. 深度研究方法（Deep Research）：Qwen Deep Research和MiroFlow，支持多工具和复杂多智能体工作流。还评估了不带经验的LIVE-EVO作为基础搜索智能体。
  3. 自演化记忆系统：ReMem，从原始轨迹构建总结经验，在测试时检索相关记忆。

3.4 实现细节

  • 骨干模型：GPT-4.1-mini
  • 温度：0.2
  • 差案例百分位：0.3
  • 最小Brier改善阈值：0.05
  • 经验相似度阈值：0.5
  • 语义相似度基于all-MiniLM-L6-v2模型计算
  • 每个任务最大交互轮次：20

4. 实验结果

4.1 主要结果（Prophet Arena）

Table 1报告了10周内的Brier分数。关键发现：

  • LIVE-EVO平均Brier分数为0.14，显著优于所有基线
  • GPT-4.1-mini基础模型：0.22
  • 开源深度研究方法表现较差（MiroFlow: 0.32, Qwen: 0.20），因为它们优化的是发现部分线索或支持证据，而非产生校准的概率预测
  • ReMem：0.16，相比基础模型有一致改善，但弱于LIVE-EVO，说明主动管理和适应经验的重要性
  • LIVE-EVO在大多数单周中都优于所有基线

5. 附录中的完整案例

论文附录提供了一个关于NFL比赛预测的完整执行轨迹：
任务：预测2025年10月16日Cincinnati vs Pittsburgh的比赛结果。
检索阶段：系统检索到两条相关的过去失败经验——一条关于过度依赖赛前赔率、一条关于未能反映赛程变更。同时检索到一条元指南，警告不要将体育预测经验过度泛化到其他领域。
编译阶段：基于检索到的经验和元指南，生成任务特定指南：优先使用接近比赛日的权威信息源、验证赛程、显式建模关键球员缺阵的影响。
执行阶段：LIVE-EVO智能体按照指南先验证赛程、检查伤病报告，而非直接查询胜率。
结果：

  • 基线智能体（无记忆）：预测Pittsburgh 0.65, Cincinnati 0.35 → Brier分数 0.5329
  • LIVE-EVO智能体：预测Cincinnati 0.55, Pittsburgh 0.45 → Brier分数 0.2500
  • Brier分数改善：0.2829

6. 局限性

  1. 对密集环境反馈的依赖：LIVE-EVO依赖密集的环境反馈来确保稳健的校准，这可能限制其在反馈稀疏或主观的场景中的适用性。
  2. "先验证再更新"协议的保守性：严格要求新经验只有在带来统计显著改善时才被接纳，这可能延迟对微妙或新兴启发式的采纳。

7. 与相关工作的区别

与现有的自演化记忆系统相比，LIVE-EVO的核心区别在于：

  1. 真正的在线学习：不是将静态基准折叠为多个子集来模拟在线学习，而是在真实的持续数据流上学习。
  2. 经验与使用方式的解耦：通过经验库和元指南库分离"发生了什么"和"如何使用"，使记忆使用策略本身也能演化。
  3. 基于对比评估的权重更新：通过有/无记忆的对比实验来量化经验的因果贡献，而非简单地基于任务成功/失败来更新。
  4. 选择性经验获取：不是存储所有轨迹，而是只在验证改善后才提交新经验，控制记忆增长。

研究方法 提出LIVE-EVO系统，包含经验库（Experience Bank）和元指南库（Meta-Guideline Bank）两个记忆模块，通过四阶段闭环流程（Retrieve检索、Compile编译指南、Act对比评估执行、Update权重更新与反思）实现在线记忆演化。采用对比评估量化记忆贡献，基于反馈调整经验权重，并通过选择性经验写入控制记忆增长。
主要发现 在Prophet Arena基准上10周时间跨度内，LIVE-EVO将Brier分数改善20.8%，市场回报提升12.9%。在Xbench-DeepResearch基准上也取得最高准确率（0.46），超越专门的深度研究方法。消融实验证明各组件（权重更新、元指南、指南编译、主动检索）均不可或缺，性能提升源于组件间的协同作用。
创新点 （1）首个面向真实在线基准的自演化智能体记忆系统，将"发生了什么"（经验）与"如何使用"（指南）解耦；（2）引入对比评估机制量化记忆的因果贡献；（3）基于反馈的经验权重强化与衰减机制，类比人类记忆的强化与遗忘；（4）元指南库实现对记忆使用策略的元认知学习。
局限性 （1）依赖密集的环境反馈信号，在反馈稀疏或主观的场景中适用性可能受限；（2）"验证后更新"协议严格要求新经验必须带来统计显著的改善才能写入，可能延迟对微妙或新兴启发式规则的采纳。

原文摘要

Large language model (LLM) agents are increasingly equipped with memory, which are stored experience and reusable guidance that can improve task-solving performance. Recent \emph{self-evolving} systems update memory based on interaction outcomes, but most existing evolution pipelines are developed for static train/test splits and only approximate online learning by folding static benchmarks, making them brittle under true distribution shift and continuous feedback. We introduce \textsc{Live-Evo}, an online self-evolving memory system that learns from a stream of incoming data over time. \textsc{Live-Evo} decouples \emph{what happened} from \emph{how to use it} via an Experience Bank and a Meta-Guideline Bank, compiling task-adaptive guidelines from retrieved experiences for each task. To manage memory online, \textsc{Live-Evo} maintains experience weights and updates them from feedback: experiences that consistently help are reinforced and retrieved more often, while misleading or stale experiences are down-weighted and gradually forgotten, analogous to reinforcement and decay in human memory. On the live \textit{Prophet Arena} benchmark over a 10-week horizon, \textsc{Live-Evo} improves Brier score by 20.8\% and increases market returns by 12.9\%, while also transferring to deep-research benchmarks with consistent gains over strong baselines.
