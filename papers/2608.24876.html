Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses

核心总结

这篇论文提出了Recuris，一种面向长时域（long-horizon）智能体任务的递归式"经验记忆–工作记忆"（Experiential–Working Memory, EM–WM）架构。其核心思想是：在单个任务执行过程中，用工作记忆（WM）持续追踪任务进度并据此从经验记忆（EM）中选取最相关的技能，而非依赖完整的交互历史；在跨任务层面，利用EM–WM耦合产生的结构化执行轨迹，由固定的Meta-Agent精确定位失败所归因的记忆组件，进行组件级别的定向修补，并通过验证门控决定是否接受更新，从而形成一个有界的递归记忆演化循环。整个过程中底层LLM权重完全冻结，所有改进都发生在外部化的记忆控制层。在四个长时域基准测试和十个模型上，Recuris在37个模型–基准组合中的35个上提升了任务成功率，将前沿模型推至SOTA水平，且优势随任务交互长度增长而扩大。

一、研究动机与问题背景

1.1 长时域任务中的递归自我改进困难

大语言模型（LLM）智能体在推理、工具使用和自主执行方面已展现出强大能力。这些能力越来越多地通过智能体框架（agent harness）来协调——即围绕底层模型的外部执行层，负责记忆管理、技能调用、任务状态追踪、工具交互和验证。
然而，在长时域任务中实现递归自我改进（Recursive Self-Improvement, RSI）仍然是一个根本性挑战。长时域任务的特点是：目标、观察和失败在执行过程中持续演变。随着交互历史不断增长，智能体经常会：

  • 丢失未完成的目标
  • 调用与当前任务状态不匹配的技能
  • 积累了经验，但组织、选择和改进经验的记忆机制本身保持固定

1.2 现有方法的局限

现有的经验记忆方法通常从初始指令或完整交互历史中检索技能，但这两种方式在长时域执行中都越来越不可靠：

  • 初始指令可能不再反映当前问题
  • 不断增长的上下文混合了过时信息、已完成步骤、未解决需求和执行噪声
    核心限制不是缺少有用经验，而是缺少一个紧凑且可靠的任务状态，能够持续地将存储的经验与智能体当前的执行需求对齐。

1.3 现有记忆演化方法的问题

现有方法通常仅从最终的成功/失败信号中学习。这种信号能揭示"出了问题"，但无法指导修复应该针对存储的技能、追踪的任务状态、技能调用机制还是进度验证器中的哪一个。结果是记忆更新往往粗糙或目标不明确。

二、方法详解

2.1 问题设定与技能记忆架构

Recuris围绕一个冻结的LLM $\pi_\theta$ 和工具集 $\mathcal{T}$ 构建智能体框架。给定任务 $x$，智能体在步骤 $t$ 维护交互历史 $h_t$ 和工作状态 $w_t$。调用策略选择一组经验技能 $\mathcal{E}_t$，然后LLM产生动作并接收环境观察：

$\displaystyle a_t \sim \pi_\theta(\cdot \mid x, h_t, w_t, \mathcal{E}_t), \quad o_t = \text{Env}(a_t; \mathcal{T})$

其中 $a_t$ 是面向用户的消息或工具调用，$\text{Env}$ 返回下一个用户响应或工具结果。一次运行产生原始轨迹 $\tau = \{(a_t, o_t)\}_{t=1}^L$ 和任务结果 $y \in \{0, 1\}$。
关键设计原则：Recuris保持 $\theta$ 冻结，通过更新条件化公式(1)的外部记忆控制机制来改变未来的框架行为。

技能记忆架构

在演化轮次 $k$，Recuris将演化中的技能记忆表示为：

$\displaystyle \mathcal{M}_k = (\mathcal{E}_k, \mathcal{W}_k, \rho_k, \mathcal{C}_k)$

四个组件分别是：

  • 经验记忆 $\mathcal{E}_k$：存储可复用技能（采用Anthropic的agent-skill格式）
  • 工作记忆规范 $\mathcal{W}_k$：定义状态模式和更新提案，用于维护任务特定的实例 $w_t$
  • 调用策略 $\rho_k$：决定在哪些执行事件处检索技能，以及 $\mathcal{E}_k$ 的哪些条目进入上下文
  • 检查器集 $\mathcal{C}_k$：测试观察是否支持提议的状态变更
    这四个组件共同构成智能体框架的可演化记忆控制层，也定义了Recuris的修补空间。外部改进程序（基础LLM、工具、Meta-Agent、定位和修补程序、验证门控等）在各轮次中保持不变。
方法概览

Recuris有两个循环：

  1. 任务级执行循环：当前工作状态引导技能调用，执行证据控制下一次状态更新
  2. 跨任务演化循环：固定的Meta-Agent使用失败运行来定位有效修复目标，提出组件特定的记忆补丁，并依赖固定的验证门控决定是否接受
    连接这两个循环的是结构化执行轨迹：

$\displaystyle \Gamma_k = \left(x_k, \{w_t, \mathcal{E}_t, a_t, o_t, \widetilde{w}_{t+1}, c_t, w_{t+1}\}_{t=1}^{L_k}, y_k\right)$

其中 $\widetilde{w}_{t+1}$ 是提议的状态，$c_t$ 包含步骤 $t$ 后的检查器决定。与原始轨迹 $\tau$ 不同，$\Gamma_k$ 将每个动作和观察与触发技能调用的状态、提议的状态更新以及用于接受或拒绝该更新的证据联系起来。

2.2 任务内经过验证的EM–WM耦合

2.2.1 结构化工作状态

执行框架根据规范 $\mathcal{W}_k$ 从任务初始化 $w_0$。每个目标条目记录其内容、状态、支持证据和可选的阻碍因素。状态属于 pending（待处理）、done（已完成）或 blocked（被阻塞）。在步骤 $t$，$w_t$ 暴露了什么已完成、什么仍未解决，以及哪些观察支持记录的进度。

2.2.2 基于状态的技能调用

技能调用决定智能体何时需要外部经验以及哪些技能应进入上下文。Recuris在定义的执行事件处做出此决定，而非每个任务只做一次：

$\displaystyle \mathcal{E}_t = \rho_k(x, w_t, e_t, \mathcal{E}_k), \quad \mathcal{E}_t \subseteq \mathcal{E}_k$

其中 $e_t$ 是步骤 $t$ 触发的执行事件（如起草的状态变更调用或轮次边界）。两个条件参数都描述任务当前所处的位置而非最初被要求的内容：$w_t$ 是框架迄今验证的进度，$e_t$ 是需要经验的执行时刻。
论文实例化了两种调用方式：

  • 调用时调用（Call-time invocation）：当智能体起草状态变更工具调用时触发，检索键是该调用命名的工具。起草的调用不会被执行——框架返回一个合成的"未执行"结果，使检索到的技能在任何状态变更动作发出之前到达模型
  • 边界调用（Boundary invocation）：在轮次边界处根据工作状态的谓词触发，不依赖于特定工具
2.2.3 基于证据的状态更新

智能体收到 $o_t$ 后，工作记忆规范提议下一个状态。检查器集评估提案与返回的观察是否一致，固定的内核仅提交被支持的变更：

$\displaystyle \widetilde{w}_{t+1} = U_{\mathcal{W}_k}(w_t, a_t, o_t)$

$\displaystyle c_t = \mathcal{C}_k(w_t, \widetilde{w}_{t+1}, a_t, o_t)$

$\displaystyle w_{t+1} = K(w_t, \widetilde{w}_{t+1}, c_t)$

其中 $U_{\mathcal{W}_k}$ 在 $\mathcal{W}_k$ 下提议状态变更，$c_t$ 记录检查器决定，$K$ 是执行框架中的固定提交规则。检查器 $C_{k,g} \in \mathcal{C}_k$ 是目标 $g$ 的显式完成谓词，它评估工具或环境结果，而非模型自己声称动作成功。
关键约束：目标只有在 $C_{k,g}(w_t, \widetilde{w}_{t+1}, a_t, o_t) = 1$ 时才能从 pending 变为 done。调用技能或尝试工具调用不构成完成证据。
由此产生的任务级循环为：

$\displaystyle w_t \xrightarrow{\rho_k} \mathcal{E}_t \xrightarrow{\pi_\theta, \mathcal{T}} (a_t, o_t) \xrightarrow{U_{\mathcal{W}_k}, \mathcal{C}_k, K} w_{t+1}$

2.3 有界的跨任务技能记忆演化

2.3.1 基于轨迹的失败定位

对于轮次 $k$ 的失败运行，Meta-Agent的固定定位阶段产生诊断——一组观察到的失败，每个归因于提供最有效修复的组件：

$\displaystyle D_k = \mathcal{A}_{\text{fixed}}(\Gamma_k, \mathcal{M}_k) = \{(f_j, z_j)\}_{j=1}^{J_k}, \quad z_j \in \{\mathcal{E}, \mathcal{W}, \rho, \mathcal{C}\}$

其中 $f_j$ 是诊断出的失败，$z_j$ 是它被归因的组件。这是一个修复决策而非因果识别声明：

  • 归因到 $\mathcal{E}$：缺失或有缺陷的技能
  • 归因到 $\mathcal{W}$：遗漏的目标、不合适的状态字段或不正确的状态更新提案
  • 归因到 $\rho$：错过的、延迟的或不相关的技能调用
  • 归因到 $\mathcal{C}$：支持的转换被拒绝或不支持的转换被接受
2.3.2 组件特定的修补

固定的修补阶段为每个被牵连的组件提出一个编辑，并将它们作为单个候选一起应用：

$\displaystyle \Delta m_z = \mathcal{P}_{\text{fixed}}(\Gamma_k, \mathcal{M}_k, D_k, z) \quad \text{for } z \in Z_k, \quad \mathcal{M}_k^+ = \mathcal{M}_k \oplus_{Z_k} \{\Delta m_z\}_{z \in Z_k}$

操作符 $\oplus_{Z_k}$ 仅更改被牵连的组件；$Z_k$ 之外的每个组件从 $\mathcal{M}_k$ 复制。每个编辑都限制在其失败被归因的组件内部。

2.3.3 验证门控的补丁准入

候选不会立即进入部署的记忆控制层。固定的门控 $\mathcal{G}_{\text{fixed}}$ 在失败任务和留出的开发集上比较 $\mathcal{M}_k^+$ 与 $\mathcal{M}_k$：

$\displaystyle \mathcal{M}_{k+1} = \begin{cases} \mathcal{M}_k^+, & \text{if } \mathcal{G}_{\text{fixed}}(\mathcal{M}_k^+, \mathcal{M}_k; x_k, \mathcal{D}_{\text{dev}}) = 1 \\ \mathcal{M}_k, & \text{otherwise} \end{cases}$

门控仅在补丁修复了目标失败且满足预设的回归标准时才接受。

2.3.4 有界递归演化

完整的循环为：

$\displaystyle \mathcal{M}_k \to \Gamma_k \xrightarrow{\mathcal{A}_{\text{fixed}}} D_k \xrightarrow{\mathcal{P}_{\text{fixed}}, \oplus_{Z_k}} \mathcal{M}_k^+ \xrightarrow{\mathcal{G}_{\text{fixed}}} \mathcal{M}_{k+1} \to \Gamma_{k+1}$

这个过程是递归的，因为每个准入决策改变了用于未来执行的记忆控制层，而由此产生的框架行为产生新的证据，可以触发后续更新。递归是有意有界的：基础LLM、Meta-Agent、定位和修补程序、验证门控以及 $\mathcal{M}_k$ 之外的框架机制保持不变。

2.3.5 测试时适应模式

同样的机制也在第二种模式下运行——将证据池和修补空间缩小到单个任务。给定单个任务和 $N$ 次尝试的预算，智能体执行任务，隐藏验证器返回一个比特。失败时，Meta-Agent接收任务指令、失败轨迹和该比特（永远看不到验证器、其测试或任何预期输出），提出对经验记忆的局部更新，智能体在更新后的记忆下重试。

三、实验设置

3.1 基准测试

论文在四个长时域基准上评估：

  1. $\tau^2$-Retail（114个任务）和 $\tau^2$-Airline（50个任务）：来自$\tau^2$-Bench，智能体必须通过受策略约束的工具调用满足模拟用户的请求。只有环境验证器返回完全奖励时才算成功。
  2. SkillFlow（166个任务）：终身技能发现基准，任务组织为20个家族，家族内的任务共享一个执行流程。每个任务有自己的验证脚本，返回二元奖励。
  3. Terminal-Bench 2.1（87个任务）：终端工作任务，用于测试时适应实验。

3.2 模型

覆盖十个模型，从3B参数的开源模型到前沿模型：

  • 开源模型：Granite-4.1-3B、Qwen3.5-4B/9B、GPT-OSS-20B、Qwen3.6-27B/35B
  • 前沿模型：Gemini 3.7 Flash、GPT-5.6 Sol、Claude Opus 5
  • 部署模型：doubao-seed-2-0-pro（中等规模，用于演化循环）
    所有模型权重在整个过程中都不更新。每个任务独立尝试 $k=4$ 次。

3.3 技能记忆的构建与评估

对每个基准构建一个技能记忆，仅在部署模型上构建。该模型运行基准自带的参考智能体，其产生的失败是循环唯一看到的证据。固定的Meta-Agent（基于Claude Code构建，从不修改，从不看测试集）读取失败轨迹、归因失败到记忆组件、编写组件范围的补丁。
评估时，该记忆被加载到Recuris中直接用于推理：评估期间不进行演化，每行的基础模型保持冻结。比较三种配置：基础智能体、携带初始记忆 $\mathcal{M}_0$ 的Recuris、携带演化后记忆的Recuris。

四、实验结果

4.1 总体性能

Recuris在37个完成的模型–基准组合中的35个上提升了任务成功率（表1）。主要亮点：

  • $\tau^2$-Retail：部署模型从58.1%提升到81.4%（+23.3），GPT-5.6 Sol从58.3%到76.1%（+17.8），Claude Opus 5从72.4%到87.9%（+15.6）
  • SkillFlow：Qwen3.6-27B从42.2%到58.7%（+16.6），Qwen3.6-35B从35.3%到48.8%（+13.5）
  • $\tau^2$-Airline：GPT-5.6 Sol从79.0%到86.0%（+7.0）
    重要发现：增益不来自更多上下文或更多计算。将整个技能库放在提示中的模型控制方案比Recuris多3,111个token，但得分低18个百分点，每次成功的成本高46%。

4.2 EM–WM耦合在长时域任务中的分析

4.2.1 优势随交互长度增长而扩大

将$\tau^2$-Retail按任务固有完成长度分为四分位数，Recuris在所有四个四分位数中都领先基础智能体17.0到44.7个百分点，没有随长度单调下降。
关键发现：长度不会破坏检索。读操作召回率（read-action recall）在所有变体的所有四分位数中保持在88.0%–97.9%。分离完全在写路径上——基础智能体在42%需要写操作的episode中一个写操作都没执行，而Recuris只有16%。长度因此损害的是完成（completion）而非理解（comprehension）。

4.2.2 EM–WM耦合改善长时域执行

五种配置的消融实验（表2）：

变体 $\tau^2$-Retail成功率 相对基础的增益
基础（无EM，无WM） 58.1% —
仅EM 60.1% +2.0（不显著）
仅WM 82.0% +23.9（显著）
模型控制调用 65.6% +7.5（显著）
EM+WM（Recuris） 83.6% +25.4（显著）

核心结论：

  • 工作状态承载了主要水平：仅添加经验记忆只值+2.0，而添加经过验证的工作状态值+23.9
  • 经验记忆是调用条件性的：它的价值不取决于包含什么，而取决于是否有东西知道何时需要它
  • 模型控制方案持有相同的技能库但让模型自己决定何时使用，结果比不带任何技能的WM-only还差
4.2.3 关键记忆组件因领域而异

通过逐一移除四种机制（写审查、真实性守卫、状态板、门控终止），发现了双重分离：

  • 在$\tau^2$-Airline上，移除写审查损失13.5个百分点，状态板无影响
  • 在$\tau^2$-Retail上，移除状态板损失17.3个百分点，写审查无影响
    这意味着关键机制是领域的属性而非架构的属性，不能在设计时预先选择——这正是跨任务演化（2.3节）的动机。
4.2.4 基于状态的技能调用更准确高效

保持技能库固定，变化谁决定调用时机（表3）：

  • Recuris执行了82.4%的必需数据库写操作，模型控制方案只有61.1%
  • Recuris每次成功消耗101k agent token，模型控制方案消耗147k
  • 优势体现为覆盖率而非速度：所有四种配置中首次正确写操作的中位轮次都是18，改变的是写操作是否被执行

4.3 递归技能记忆演化的分析

4.3.1 结构化轨迹改善失败定位

通过注入已知故障的受控实验（表4）：

给判断者的证据 $\mathcal{E}$ $\mathcal{W}$ $\rho$ 宏平均
仅结果 0.0% 38.9% 0.0% 13.0%
原始轨迹 61.1% 50.0% 0.0% 37.0%
结构化轨迹 $\Gamma$ 72.2% 83.3% 38.9% 64.8%

结构化轨迹将定位准确率从13.0%（仅结果）提升到64.8%。增益集中在轨迹无法显示的故障上——调用策略故障是一个"非事件"（对话中什么都不出现），从$\Gamma$的机制事件中才能识别。

4.3.2 递归演化产生一致的留出增益

每个演化运行的演化后记忆都以排除零的置信区间超过 $\mathcal{M}_0$（表5）。迭代可以累积：Run C的第二轮在第一轮基础上增加+6.98个百分点。但并非每轮都有效——Run A停滞，Run B的第四轮候选从未被调用。
增益是执行增益：必需写操作召回率与任务成功率在九个最终包上的相关系数 $r = 0.97$。

4.3.3 两种Meta-Agent实现收敛

将Meta-Agent从Claude Code完全重新实现到DeepSeek Harness上，结果在统计上不可区分（表6）：Claude Code +11.92，DeepSeek Harness +10.47和+9.30，配对差异−1.45在$[-7.85, +4.65]$内（$p = 0.72$），在两次运行字节相同的$\mathcal{M}_0$包的$[-6.98, +7.27]$带内。
更重要的是，两种实现得出了相同的组件族：追踪服务请求授权的工作记忆字段、执行门控检查和一组反升级技能。循环学到的内容由它诊断的证据决定，而非执行诊断的机制。

4.3.4 门控更新保留现有能力

接受的更新仅破坏了42个开发任务中的4个（9.5%），而重新运行字节相同的包破坏了25.9%（$p = 0.013$）。被拒绝的候选的破坏率与此空值不可区分——锚点任务上的回归主要由解码噪声而非补丁主导。

4.3.5 演化后的技能记忆跨任务迁移

记忆从16个训练任务的失败中提炼，在86个从未触及的留出任务上，每个到达它们的包都以排除零的区间超过$\mathcal{M}_0$ 9.01到17.44个百分点。但迁移有条件：在留出池不再包含记忆修复的那类失败的地方，没有东西可以迁移。

4.3.6 演化后的技能记忆跨模型迁移

在一个中等规模部署模型上演化一次的记忆包，不经修改地交给从未参与其产生的模型（表7）：

  • GPT-5.6 Sol在$\tau^2$-Retail上+17.76（显著）
  • Claude Opus 5在$\tau^2$-Retail上+15.57（显著）
  • 最强目标模型也达到该基准的最高分（87.9%），高于包在其来源模型上达到的81.4%
    这不是弱模型的拐杖——如果包仅补偿缺失能力，在能力最高处剩余空间最少。

4.4 测试时适应

在Terminal-Bench 2.1上（87个终端任务），测试时适应解决了53/87个任务（60.9%）。但分解显示：重试本身值+26.4个百分点，在匹配预算下适应仅增加+2.3个百分点（$p = 0.774$）。然而，7个任务仅在适应下被解决。在每次尝试成功率（额外尝试无法购买的指标）上，携带学习技能的56个任务从17.4%升至21.9%（+4.5），方向一致但区间包含零。

五、与现有工作的区别

论文在图2中清晰对比了Recuris与先前方法的两个关键转变：
记忆如何被使用：先前的框架从不断增长的聊天历史中检索，丢失未解决的目标。Recuris在执行事件处检索，检查器将环境响应转化为经过验证的状态更新，而非信任对话。
记忆如何演化：先前的框架从一个任务结果重写整个记忆。Recuris读取结构化轨迹，将每个失败归因到一个组件，仅修补被牵连的组件，并仅通过留出任务上的验证门控才接受结果。

六、核心贡献总结

  1. 确立了基于状态的记忆使用作为长时域智能体框架中递归自我改进的关键需求
  2. 引入了Recuris架构，将持久经验与动态维护的、基于证据的任务状态耦合
  3. 展示了EM–WM耦合如何将框架执行转化为结构化诊断证据，实现组件级失败定位和技能记忆的定向演化
  4. 在四个基准和十个模型上进行了全面评估，观察到跨模型规模的一致增益，包括GPT-5.6 Sol +17.8和Claude Opus 5 +15.6
    论文的核心洞察是：记忆控制层（而非权重）可以作为冻结智能体的可训练表面，产生可归因到组件、可逆且可跨模型移植的改进。

研究问题 在长时程任务中，递归自我改进（RSI）面临交互历史不断增长导致任务状态模糊和技能调用失准的问题，现有经验记忆方法缺乏紧凑可靠的任务状态来持续对齐存储经验与当前执行需求。
研究方法 提出Recuris架构，通过工作记忆（WM）跟踪已验证的任务状态并引导从经验记忆（EM）中选择技能，形成EM-WM耦合闭环；跨任务层面，固定的Meta-Agent基于结构化执行轨迹进行组件级故障定位和针对性修补，经验证门控后递归演化技能记忆。在四个长时程基准（τ²-Retail、τ²-Airline、SkillFlow、Terminal-Bench 2.1）和十个模型（从3B开源到前沿模型）上进行评估。
主要发现 Recuris在37个已完成的模型-基准对中的35个上提升了任务成功率；在τ²-Retail上为GPT-5.6 Sol提升+17.8分、Claude Opus 5提升+15.6分（达87.9%）；优势随交互时长增长而扩大，最长任务达+32.2分；常见长时程失败模式减少高达80%；结构化轨迹的故障定位准确率为64.8%，远超仅用任务结果的13.0%。
创新点 首次提出EM-WM耦合机制，将技能调用锚定于经验证的当前任务状态而非完整历史；将执行过程转化为结构化诊断证据，实现组件级故障定位和有针对性的记忆演化；构建了有界的、验证门控的递归记忆演化循环，在保持基础LLM冻结的前提下仅更新外部记忆控制层。
局限性 在缺乏跨任务共享结构的基准（如Terminal-Bench 2.1）上跨任务演化未能生效，仅能依赖测试时适应模式且增益较小（+2.3分，置信区间包含零）；验证门控在小规模开发集上分辨率有限，可能拒绝实际有效的补丁；演化记忆仅增长不删减，存在冗余；τ²-Airline因任务数少（50个），多数对比的置信区间包含零。

原文摘要

Recursive self-improvement (RSI) remains hard in long-horizon tasks, where growing histories obscure the task state and misalign skill invocation. We introduce Recuris, a recursive Experiential-Working Memory architecture for long-horizon agent harnesses, in which Working Memory tracks task progress and guides skill selection from Experiential Memory, grounding skill use in current needs rather than the full history. This coupling also turns execution into structured evidence that localizes failures to specific memory components. Across tasks, a fixed Meta-Agent turns that evidence into localized, validation-gated updates to Skill Memory that reshape execution and yield new evidence, forming a bounded recursive memory-evolution loop. Across four long-horizon benchmarks and ten models, Recuris improves task success in 35 of the 37 completed model-benchmark pairs, carrying frontier models to SOTA-level task success: on tau-bench it adds +17.8 points to GPT-5.6 Sol and +15.6 to Claude Opus 5, taking Opus 5 to 87.9%, and +16.6/+13.5 points on Qwen3.6-27B/35B on SkillFlow. The advantage widens as the interaction horizon grows, to +32.2 points on the longest tasks, and common long-horizon failures fall by up to 80%. These results position recursively evolving memory as a scalable foundation for RSI, enabling agents to continuously transform accumulated experience into increasingly effective long-horizon behavior.
