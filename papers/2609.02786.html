二、一句话概括

SafeEvolve 提出一个经验驱动的智能体安全对齐框架：让模型外部的执行框架（harness：安全提示词 + 分层技能库）与模型内部的策略参数（通过 SFT-RL）从同一批交互轨迹中交替进化，从而在工具使用场景下同时获得"可审计、可快速迭代"的外部安全控制与"内化、持久"的模型安全行为，在安全性-效用权衡上显著优于单一路线及现有基线。

三、研究背景与问题动机

3.1 问题背景：智能体安全是"轨迹级"问题

LLM 智能体的安全风险不只出现在最终回复，而是散布在多步工具使用轨迹的中间环节：不安全的工具调用、跟随注入指令、中途误拒等。论文覆盖两类典型威胁：

  • 恶意查询（malicious query）：用户指令本身有害，考验模型的意图级拒绝能力；
  • 环境注入（environment injection）：用户目标良性，但网页、邮件、工具输出等环境观察中混有对抗指令，考验模型"把环境内容当证据而非指令"的能力。
3.2 核心论点：两条现有路线各有死穴

论文将现有工作分为两派，并指出各自单走的缺陷：

  1. 只进化 harness（提示词、技能、运行时护栏）：复杂的工件可能超出弱策略的执行能力；且指导在 episode 开始前注入，随多步执行推进会与现实行为脱节——"说得到，做不到"；
  2. 只训练策略参数：训练时 harness 固定，无法应对训练分布外新出现的失败模式；安全能力锁死在特定权重里，难以跨模型迁移，且不可审计——"做到了，但带不走、追不上"。

这一矛盾构成本文的全部动机：运行时控制与内在安全能力必须耦合进化，而非各自为政。

3.3 论文定位

本文把"经验驱动的智能体自我进化"这一此前主要用于能力提升的范式，首次系统地迁移到安全对齐领域，并提出配套的机制设计（单组件有界突变、配对接受-拒绝门控、版本化回滚、任务类型化奖励）。

四、方法详解

4.1 总体结构

方法分为三个阶段：① 策略冻结下的 harness 预热进化；② harness-use SFT 冷启动；③ 持续的 harness-策略协同进化主循环。

4.2 形式化

轨迹（Eq. 1）：$\tau = (x, o_1, a_1, o_2, a_2, \ldots, o_T, a_T)$，其中 $x$ 为任务，$o_t$ 为环境观察（用户消息、工具输出、网页、记忆状态等），$a_t$ 为模型动作，$T$ 为最大步数。

系统级目标（Eq. 2）：

$$\max_{\theta,\, H} \ \mathbb{E}_{x \sim D,\; \tau \sim \pi_\theta(\cdot \mid x, H)} \big[ R(\tau \mid z(x)) \big]$$

$\theta$ 为策略权重，$H$ 为 harness 工件，$z(x)$ 为任务类型标签。关键设计决定：论文不将其作为联合优化求解，而是把 harness 更新（离散文本编辑 + 门控选择）与策略更新（连续梯度）分离、交替进行。

4.3 可进化组件与验证器

Harness 组件：安全系统提示词 $P$；分层技能库 $S = \{S_g, S_k, S_m\}$（通用原则 / 任务特定程序 / 错误修复技能）。技能更新受约束（P1.S5）：优先合并更新而非新增、须注明作用域与触发条件、禁止包含基准特定标识与 ground-truth 信息、附回滚说明——保证工件可审计、可检索、无数据泄漏。

规则验证器：所有奖励与门控分数均由确定性规则程序计算（不用 LLM 裁判），检查轨迹、工具调用、工具输出与最终答案。按任务类型切换逻辑（P1.S4）：干净任务查 grounding 与必需工具调用；注入任务分解 $U$、$S$ 与交互项；恶意查询按"工具是否助长危害 vs. 拒绝/安全重定向"打分。这带来三点好处：确定性可复现（GRPO 组内比较的前提）、对轨迹内注入文本天然免疫、支撑门控的可信度。

4.4 奖励设计（Eq. 11，P1.S2）
$$R(\tau \mid z) = \begin{cases} U(\tau), & z = \text{clean} \\ S(\tau), & z = \text{query} \\ \lambda_U U(\tau) + \lambda_S S(\tau) + \lambda_{US} U(\tau)S(\tau), & z = \text{injection} \end{cases}$$

Environment injection attacks require both ignoring the injected instruction and preserving the original benign goal; therefore, their reward combines utility, safety, and an interaction term that favors trajectories satisfying both requirements.

(Mao 等, 2026)

交互项 $U\!\cdot\!S$ 是关键：只有"既完成原任务又无视注入"的轨迹才能获得这部分奖励，防止模型走向"为安全而停摆"或"埋头执行被劫持"两个极端。$\lambda$ 系数跨骨干与训练固定（具体值在 Appendix A.5，本文未覆盖）。

4.5 Harness 进化：有界突变 + 配对门控（Eq. 8）
  1. 从轨迹聚合失败证据（失败桶、恢复案例、任务元数据）；
  2. proposer 模型针对单个组件提出有界修改 $\Delta_j$（有界 = 一次只改一处，保证可归因）；
  3. 在内部面板 $\mathcal{B}_{\text{evo}}$ 上用同一策略配对评估新旧 harness，$J(H; \mathcal{B}) = \frac{1}{|\mathcal{B}|}\sum R(\tau_i)$；
  4. 接受需同时满足：$J(\hat{H}) \geq J(H) + \delta$（改进需超过裕度，抗采样噪声）且门控 $G = 1$（安全、干净效用、执行质量任一不退化，一票否决）；
  5. 接受的修改版本化存储，附证据与回滚元数据。
4.6 Harness-use SFT 冷启动（Eq. 10，P1.S1）

动机：技能库作为运行时上下文注入，但基座策略未必会判断"何时相关、如何执行"。做法：在进化 harness 下 rollout，验证器拒绝采样保留合格轨迹，只在 assistant 回复与工具调用上计算损失：

$$\mathcal{L}_{\text{sft}}(\theta) = -\mathbb{E}_{\tau \in \mathcal{D}_{\text{sft}}} \sum_{t \in \mathcal{A}(\tau)} \log \pi_\theta(a_t \mid h_t, P^\star, S_x)$$

$P^\star$、$S_x$ 作为条件进入训练样本——策略学的是"在这套 harness 指导下如何行动"，直接回应"harness 超出策略能力"问题。

4.7 Harness-augmented RL：GRPO（Eq. 12–13）

组内相对优势：每任务采 $G=8$ 条轨迹，

$$\hat{A}_i = \frac{R(\tau_i) - \mu_x}{\sigma_x + \varepsilon}$$

无需价值网络，以组内均值 $\mu_x$ 为基线；同组共享任务与 harness 上下文，比较公平。

优化目标：$\rho_{i,t}(\theta) = \frac{\pi_\theta(a_{i,t}|h_{i,t})}{\pi_{\theta_{\text{old}}}(a_{i,t}|h_{i,t})}$ 为重要性采样比率，经 clip（$\varepsilon=0.2$）限制单步更新幅度，并加 KL 惩罚 $-\beta_{\text{KL}} D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})$（$\beta_{\text{KL}}=0.01$）锚定参考策略。

关键性质：奖励虽在轨迹级分配，但通过 $\rho_{i,t}$ 将信用传导至每一步的工具调用、拒绝与恢复决策——这是解决"多步执行脱节"的机制所在。

4.8 主循环与关键细节

Algorithm 1 的主循环有三个值得注意的设计：

  • 显式版本配对：每批轨迹标注 $(\pi_{\theta_r}, H_r)$，行为变化可归因到策略更新、harness 更新或两者交互；
  • 时间错开：harness 评估用刚更新完的固定策略 $\pi_{\theta_{r+1}}$，每次只变一个变量；
  • 节奏不对称：策略每步更新，技能库每 10 步、提示词每 20 步才评估一次突变（Table 4），避免"移动靶"训练环境。

主要超参数：200 训练步、批 32 任务、组 8 轨迹（每次更新 256 条）、学习率 $10^{-6}$、上下文 4096/512。

五、实验设置与主要结果

5.1 设置
  • 基准：AgentDojo、AgentDyn（间接提示注入，指标 ASR↓、U-Attack↑）、AgentHarm（恶意查询，指标有害分↓、拒绝率↑）；held-out 泛化测试用 Agent Security Bench（DPI / IPI / PoT Backdoor）；
  • 骨干：Qwen3.5-4B、Qwen3-4B-Instruct-2507；
  • 基线：SFT、DPO、GRPO、MetaSecAlign、AgentAlign 及 harness-only 变体。
5.2 主结果
基准 / 骨干 基线 → SafeEvolve
AgentDojo（Qwen3.5-4B） ASR 2.37% → 0.79%（约 3 倍降低）；效用 59.79% → 61.86%
AgentHarm（Qwen3.5-4B） 有害分 56.45 → 12.27；拒绝率 28.98% → 83.83%
AgentDojo（Qwen3-4B） 效用 44.33 → 60.82；ASR 13.38% → 2.42%

SafeEvolve improves direct refusal behavior on harmful requests while still preserving task execution under indirect prompt injection, suggesting that harness-policy co-evolution learns risk-specific intervention rather than uniformly suppressing action.

(Mao 等, 2026)

这段作者解读点出了最重要的结果模式：安全性提升不是来自"一律保守"——模型在恶意查询上更会拒绝，同时在注入攻击下仍能完成良性任务，即学到了风险特异性的干预行为，而非全局压抑行动。这正是安全对齐中最难获得的性质（避免"对齐税"）。

5.3 消融与分析要点
  1. 冻结策略 + 进化 harness 已有效：不训练模型时 AgentDojo ASR 可降至 0.92%——检索式程序性指导优于单一全局提示；
  2. RL-only 崩塌：只用 RL（无 harness）导致效用崩塌、有害分上升；harness-augmented RL 才真正内化安全知识；
  3. 跨模型迁移有限：harness 迁移到同级 4B 模型仍有收益，迁移到 1.7B 弱模型几乎无效——反向印证协同进化的必要性；
  4. 在线更新不稳定：RL 期间持续在线进化技能库使 AgentHarm 有害分从 12.27 回升至 27.02——门控强度是稳定性的瓶颈；
  5. 组件非加性：提示词 + 技能组合有时过度约束执行、降低攻击下效用；
  6. 泛化：held-out 的

原文摘要

The performance of LLM-based agents is jointly shaped by the base model and the harness used when interacting with the environment. This exposes them to safety risks in both harmful final responses and multi-step execution trajectories. Existing safety alignment mechanisms often rely on either external harness updates or policy optimization, yet applying either paradigm in isolation fails to bridge runtime control with intrinsic safety. We propose SafeEvolve, an experience-driven self-evolving framework for agent safety alignment. SafeEvolve leverages safety experience from completed on-policy trajectories to drive a continual loop of harness-policy co-evolution. On the harness side, SafeEvolve converts trajectory-level safety evidence into bounded, component-level updates across safety prompt and hierarchical skills, yielding auditable and reversible harness artifacts. On the policy side, SafeEvolve follows a two-stage SFT-RL paradigm, where harness-use SFT bootstraps the policy to actively leverage evolved harness artifacts, and harness-augmented RL further shapes autonomous safety behaviors during multi-step exploration via verifier-decomposed rewards. Through harness-policy co-evolution, SafeEvolve converts safety experience into an evolved runtime harness and improved policy behavior. Experiments on agentic safety benchmarks show that SafeEvolve achieves a stronger safety-utility tradeoff than existing baselines. For Qwen3.5-4B, SafeEvolve achieves a $3\times$ ASR reduction on AgentDojo while improving benign utility from 59.79% to 61.86%.
