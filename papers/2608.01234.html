Learning What to Remember and What to Internalize in LLM Self-Evolution via Adaptive Memory-Parameter Coordination

论文核心总结

这篇论文研究的是LLM智能体（Agent）在部署后如何持续自我进化的问题。现有的自我进化方法分为两类：一类是harness-based（外挂式）方法，将经验存储在外部可编辑的记忆/技能库中，在推理时检索使用，优点是灵活快速但能力提升有限；另一类是parameter-based（参数式）方法，通过微调或强化学习将经验内化到模型参数中，优点是能力提升深入但成本高且对环境变化脆弱。论文提出了COVE（Channel Orchestrated Volatility-aware Evolution）框架，通过三个核心机制——任务感知路由（Task-aware Routing）、阶段感知调度（Stage-aware Scheduling）和双模态知识优化（KnowledgePO）——来协调这两种进化通道，根据任务特性、学习阶段和知识的易变性，自适应地决定哪些经验应该"记住"（存在外部记忆中）、哪些应该"内化"（写入模型参数中），从而实现比单一通道更鲁棒、更高效的自我进化。

一、研究背景与问题动机

1.1 LLM智能体面临的挑战

LLM智能体已经从被动的文本生成器发展为可以规划、调用工具、写代码、进行多步推理的交互式系统。但外部世界是不断变化的——API会更新、数据库schema会变、新的库会出现、用户需求会变化。在这种动态环境下维持高性能的智能体，需要反复的人工重配置或重训练，代价很高。
智能体自我进化（Agent Self-Evolution） 提供了一条有前景的路径：不把部署当作学习的终点，而是把任务执行本身当作监督信号的来源，让智能体从环境反馈中持续学习。

1.2 两种现有的自我进化范式

如图1所示，现有方法分为两大类：
（1）Harness-based（外挂式/工具侧）方法：

  • 代表工作：Evo-Memory、Reflexion、Voyager
  • 做法：将环境反馈总结为外部记忆（Memory）或可执行技能（Skill），存储在外部知识库中，推理时通过检索注入到prompt中
  • 优点：更新快、灵活，适合应对变化的任务表面
  • 缺点：当基础模型本身能力不足时，可能产生误导性的经验；仅靠外部记忆无法提升模型的底层能力

（2）Parameter-based（参数式）方法：

  • 代表工作：WizardLM、Self-Challenging Agent
  • 做法：用生成的数据、任务奖励或反馈通过SFT（监督微调）或RL（强化学习）更新模型权重
  • 优点：能内化更深层的模式，如潜在策略或领域特定的推理套路
  • 缺点：训练成本高、适应速度慢，对于简单的常规更新来说是不必要的开销；而且会把易变的表面知识（如API名称）也记忆到参数中，导致环境变化时模型变得脆弱

1.3 核心问题

单独使用任何一种方法都存在"灵活性vs性能"的权衡。论文的核心问题是：智能体如何协调这两个通道来实现鲁棒的自我进化？

二、进化范式分析（Evolving Paradigm Analysis）

论文在提出方法之前，先通过实验分析了两种范式各自的局限性，从任务维度和知识维度两个角度展开。

2.1 任务维度分析

作者设计了两个诊断性任务：
任务一：Lean定理证明（MiniF2F数据集）——测试harness-based方法
实验发现（图2和图3）：

  • 随着episode增加，智能体积累了越来越多的记忆和技能，但成功率几乎没有提升（不到3%的改善）
  • 即使每个任务检索的记忆/技能条目从2增加到8，Lean编译错误也没有减少
  • 各类错误（语法错误、未解决目标、重写失败、类型不匹配等）没有呈现一致的下降趋势，最基本的语法错误甚至变得更频繁

结论： Harness记忆可以存储提示或策略模式，但无法可靠地创建执行这些策略所需的操作能力。对于这类需要深层能力的任务，外部记忆是不够的。
任务二：带动态工具接口的表格问答（WikiTableQuestions数据集）——测试parameter-based方法
用Qwen3-8B训练了一个参数式自进化模型，然后在两种条件下测试：API名称不变 vs API名称被重命名。
结果（表1）：

  • API名称不变时：成功率40.5%，API调用正确率96.5%
  • API名称重命名后：成功率暴跌至16.5%，API调用正确率暴跌至54.0%

结论： 参数式进化在接口表面形式变化时会让模型变得脆弱。
跨任务的互补性瓶颈： 易变的任务需要可编辑的harness侧适应，而能力受限的任务需要参数侧学习。因此需要在两个层面做出决策：

  • 任务间决策（inter-task）： 哪种通道适合某个任务族
  • 任务内决策（intra-task）： 在学习过程中何时应该切换通道

关于任务内的时机选择（图4）：
作者比较了三种策略在对齐训练阶段后的表现：

  • Plateau-triggered（平台期触发的参数更新）： 达到最高的平均分和成功率
  • Always-training（持续参数训练）： 表现平平
  • Harness-only（仅外挂式进化）： 表现平平
    这说明参数更新的收益不仅来自于使用参数更新本身，更来自于在正确的时机使用它——即当harness侧探索暴露了稳定的瓶颈并积累了有用信号之后。
    反过来，在冷启动场景（如Lean定理证明）中，基础模型可能无法生成有用的轨迹，此时需要先进行参数更新来建立最低能力基线，然后harness侧进化才能变得有效。

2.2 知识维度分析

任务级分析决定了激活哪个进化通道，但还没有决定什么知识应该存储在哪个通道。
一个诱人的标准是频率——如果某个知识反复出现且帮助智能体成功，似乎应该吸收到参数中。但频率是一个不安全的信号，因为它混淆了"有用性"和"持久性"。
反直觉的关键案例： 高频的接口知识（如API调用）恰恰是最危险的需要内化的知识。表1已经展示了这一点：API调用是高频且实用的知识，但直接内化会导致API名称变化后成功率暴跌59.3%。
论文因此提出易变性（Volatility） 作为决定知识应该外化还是内化的关键标准，并将知识分为三类：

  • 易变知识（Volatile Knowledge）： 依赖于外部表面形式，如API名称、表格schema。应保留在外部记忆中，并在训练时明确防止被内化。
  • 稳定知识（Stable Knowledge）： 捕获持久的底层模式，如算法惯用法、领域推理套路。适合参数式内化。
  • 策略知识（Strategic Knowledge）： 更高层的启发式，如调试计划。应保留在记忆中，只有在反复证明其稳定性后才内化。
    如表1最后一行所示，在标注知识易变性并引入相应奖励后，模型在重命名API的任务上仍然保持了92.5%的API调用正确率（对比直接参数学习的54.0%）。

三、COVE方法

基于上述分析，论文提出了COVE（Channel Orchestrated Volatility-aware Evolution）框架，由三个核心机制组成。

3.1 任务形式化

智能体在一个任务序列 $\{\tau_i\}_{i=1}^T$ 上运行，每个任务从任务分布 $\mathcal{D}$ 中采样。智能体由参数化策略模型 $\pi_\theta$、外部知识库 $\mathcal{K} = \{k_j\}$ 和执行环境 $\mathcal{E}$ 组成。
COVE支持两类更新：
Harness侧更新：

$\displaystyle \mathcal{K} \leftarrow U_h(\mathcal{K}, \tau_i, f_i)$

参数侧更新：

$\displaystyle \theta \leftarrow U_\theta(\theta, \mathcal{D}_{train}, \mathcal{K})$

优化目标是在推理和训练预算约束下最大化累积任务效用：

$\displaystyle \max \sum_{i=1}^T R_i - \alpha \sum_{i=1}^T C_i^{\text{tok}} - \beta \sum_{m=1}^M C_m^{\text{train}}$

其中 $R_i$ 是任务奖励，$C_i^{\text{tok}}$ 是提示token成本，$C_m^{\text{train}}$ 是第 $m$ 次参数更新的计算成本。

3.2 任务感知路由（Task-aware Routing）

COVE不会对每个任务同时应用两种进化方式，而是根据任务需要的知识类型和暴露的失败类型来路由。
路由器被实例化为一个反馈条件决策策略。给定任务描述 $\tau_i$ 和执行反馈 $f_i$（包含结果状态、标量分数和诊断消息），路由器查询一个受约束的判断器，返回结构化决策记录 $d_i = (m_i, s_i, r_i)$：

  • $m_i$：选择的进化通道
  • $s_i$：描述任务特征的自由形式描述符（如 dynamic_tool、logical_rigor）
  • $r_i$：一句话的理由
    通道从三个选项中选择：$\mathcal{M} = \{\text{harness\_only}, \text{parametric\_candidate}, \text{hybrid}\}$
  • harness_only： 当失败源于易变的或上下文内的知识时选择
  • parametric_candidate： 当任务奖励的是可内化的能力、且难以用prompt表达时选择
  • hybrid： 当任务同时展现两种信号时选择（如既需要形式推理又需要工具交互）

3.3 阶段感知调度（Stage-aware Scheduling）

除了按任务类型路由，还需要决定何时调用每个进化通道。COVE引入了一个阶段感知进化触发器，基于三个可测量的条件动态决定：
性能平台期（Plateau）： 最近 $w$ 个episode窗口内的成功率或平均奖励的改善低于阈值 $\epsilon$。
数据充分性（DataSufficient）： 高质量轨迹数量 $|\mathcal{D}_q| \geq N$。
冷启动失败（ColdStartFailure）： 某个任务族的前 $k$ 个任务的成功率低于阈值 $\tau_c$，表明harness侧进化无法自行启动。
对于被路由为 parametric_candidate 或 hybrid 的任务族，COVE在以下条件满足时触发参数更新：

$\displaystyle \text{Trigger} = \text{Plateau} \lor \text{DataSufficient} \lor \text{ColdStartFailure}$

前两个条件支持"先harness探索，后参数内化"的常见路径；第三个条件捕获相反的路径——参数训练必须先建立最低能力基线。

3.4 KnowledgePO：双模态知识优化

路由和调度决定了何时使用每个通道，KnowledgePO决定了两个通道如何交换知识。其目标是形成一个闭环：外部记忆提高训练rollout的质量，训练后的参数减少对外部记忆的依赖（当相关知识已被稳定内化时）。

3.4.1 Harness辅助参数学习：记忆感知Rollout

知识易变性标注： 在创建每个知识条目 $k_j$ 时，COVE为其分配一个易变性标签 $\ell_j \in \mathcal{L} = \{\text{volatile}, \text{stable}, \text{strategic}\}$。此外，如果一个最初非易变的条目被反复修订，系统会将其提升为 volatile。
记忆感知推理： 在每次尝试前，智能体检索与任务相关的top-$k$记忆/技能条目 $\mathcal{K}_r \subseteq \mathcal{K}$，注入到消息列表中。这让模型利用之前harness侧探索发现的知识，提高rollout成功率和训练轨迹 $\mathcal{D}_{rollout}$ 的质量。易变条目用显式标记 &lt;volatile>...&lt;/volatile> 包裹。
反背诵奖励（Anti-Recitation Reward）： 这是一个关键设计。在训练开始前，易变条目中的名称被随机重命名。设 $\mathcal{N}_i$ 为当前episode中检索到的记忆提供的合法易变名称集合。如果模型调用了过时的或未观察到的易变名称（说明它依赖于记忆化而非检索条件执行），就会受到惩罚：

$\displaystyle R = R_{\text{task}} - \lambda \cdot \mathbb{I}[\text{uses stale or unobserved volatile name}]$

其中 $R_{\text{task}}$ 衡量任务正确性和格式有效性。这个惩罚阻止模型从固定接口名称到固定动作的捷径。期望的行为不是"记住并重复"，而是"读取当前条目并据此行动"。稳定知识不受此惩罚约束，允许可复用模式被内化到模型权重中。

3.4.2 参数辅助Harness：记忆释放（Memory Release）

由于累积的记忆会消耗上下文并增加检索噪声，COVE在训练后评估稳定知识是否仍需保留在在线检索集 $\mathcal{K}_{online}$ 中。
对每个稳定记忆 $k_j$，COVE在留出子集 $\mathcal{D}_{held}$ 上进行A/B评估：

  • 条件A：在检索上下文中包含 $k_j$
  • 条件B：移除 $k_j$
    如果性能差距：

$\displaystyle \Delta_j = \text{Score}_A(k_j) - \text{Score}_B(\varnothing)$

在训练后低于阈值，且 $k_j$ 在训练前有正效用，则该条目被标记为 internalized 并从在线检索中释放。易变记忆永远不会被释放，因为它们的价值在于携带当前的外部符号。

四、实验

4.1 实验设置

  • 基础模型： Qwen3-8B
  • 硬件： 4块NVIDIA A100 80GB GPU
  • 评估任务（5个）：
  • WikiTableQuestions（TableQA）：知识密集型表格问答
  • HotpotQA：工具使用推理
  • APPS：代码生成
  • MiniF2F（Lean4）：形式化定理证明
  • MATH：数学推理
  • 基线方法：
  • 原始Qwen3-8B（无自进化）
  • Evo-Memory（harness-based）
  • Self-Challenging（parameter-based）
  • Harness-only（仅COVE的harness组件）
  • Parametric-only（仅COVE的参数组件）

五、总结

论文的核心贡献：

  1. 系统性分析： 从任务特性、学习阶段和知识易变性三个角度分析了智能体自我进化，阐明了何时应使用harness-based方法、何时应使用parameter-based方法。
  2. COVE框架： 集成了任务路由、任务内调度和双模态知识优化，将记忆的灵活性与参数学习的深度结合起来。
  3. 实验验证： 在推理、QA、编码和定理证明等多种任务上，协调进化优于单通道进化策略，且训练成本大幅降低。
    论文的核心洞察是：未来的自我进化智能体不应将反馈视为统一的训练数据，而应将其视为异质性知识——其存储和更新机制必须匹配其稳定性和复用模式。

研究方法 提出COVE框架，包含三个核心机制：（1）任务感知路由器（Task-aware Router），根据任务特征和反馈将任务分配到合适的进化通道；（2）阶段感知调度器（Stage-aware Scheduler），基于性能平台期、数据充分性和冷启动失败等信号动态决定何时切换通道；（3）KnowledgePO双模态知识优化，通过知识波动性标注、反背诵奖励和记忆释放机制协调外部记忆与参数学习之间的知识流动。实验基于Qwen3-8B模型，在WikiTableQuestions、HotpotQA、APPS、MiniF2F和MATH五个任务上进行评估。
主要发现 COVE在Lean4定理证明、APPS代码生成、HotpotQA和MATH等任务上优于单通道进化策略，同时训练token消耗减少86%。反背诵奖励有效防止模型记忆易变的API接口知识，在API重命名场景下保持92.5%的API调用正确率（对比直接微调的54.0%）。任务感知路由器以仅0.16倍的参数训练成本达到接近全量训练的性能。
创新点 （1）首次系统分析了智能体自我进化中任务特征、学习阶段和知识波动性三个维度对通道选择的影响；（2）提出知识波动性（volatility）概念，将知识分为易变、稳定和策略性三类，分别匹配不同的存储机制；（3）设计反背诵奖励机制，通过随机重命名易变知识中的接口名称来防止模型将表面形式记忆到参数中；（4）实现了harness-based和parameter-based两种进化范式的统一协调框架。
局限性 论文未明确讨论局限性。从实验设计来看，潜在局限包括：仅在Qwen3-8B单一基座模型上验证；路由器依赖LLM判断，其准确性受限于判断模型能力；知识波动性标注依赖自动化判断，可能存在分类误差；实验任务类型有限，未涵盖更复杂的多模态或长期交互场景。
与本研究的关联 该论文为LLM智能体的持续学习和自适应进化提供了一个统一框架，对研究如何在动态环境中平衡外部知识检索与内部参数更新具有重要参考价值，尤其是其知识波动性分类和双通道协调机制的设计思路。

原文摘要

Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.
