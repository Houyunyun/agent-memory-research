核心总结

这篇论文是一篇关于LLM（大语言模型）Agent长期记忆（Long-Term Memory, LTM）安全性的综述。论文指出，当LLM Agent从无状态的聊天机器人进化为拥有可写入、跨会话持久化记忆的自主系统时，安全威胁的性质发生了根本性变化——攻击者不再仅仅试图影响当前回复，而是可以操纵系统如何"记住、检索、规划和行动"。论文提出了一个记忆生命周期框架（Memory Lifecycle Framework），将攻击、防御及其跨阶段依赖关系组织在六个生命周期阶段（写入、存储、检索、执行、共享与传播、遗忘与回滚）和四个安全目标（完整性、机密性、可用性、治理）两个维度上。在此基础上，论文进一步提出了可验证记忆治理（Verifiable Memory Governance, VMG）框架，定义了五个架构原语，为长期记忆系统提供可审计、可恢复的控制能力。

一、研究背景与动机

1.1 从无状态到有状态：安全范式的转变

传统的LLM安全研究主要集中在两个方面：一是编码在模型权重中的参数化知识（如训练数据提取、机器遗忘），二是单轮或多轮交互中的提示操纵（如prompt injection）。这些研究本质上都是以输入为中心的，关注的是瞬时的、无状态的威胁。
然而，随着LLM Agent越来越多地配备了持久化的长期记忆（例如MemGPT、Mem0、MemOS等系统），安全关注的焦点正在从"瞬时输入"转向"持久状态"。攻击者不再只是想影响一次回复，而是想操纵系统在未来多次交互中的记忆、检索、规划和行为。

1.2 现有方法的根本局限

论文指出，现有的prompt注入防御和RAG（检索增强生成）污染缓解方法对LTM安全是根本不够的，原因在于：

  • 它们主要在单个会话或单次检索范围内运作，无法处理跨会话、有状态的持久记忆问题。
  • 扩大上下文窗口并不等同于持久记忆——更大的上下文窗口只改善了会话内的回忆能力，但其内容不会自动跨会话保留、共享或检索。
  • 当内容超出单个会话的生命周期或跨越主体（principal）边界时，就需要来源标记（provenance tagging）、主体范围检索（principal-scoped retrieval）、可回滚状态（rollbackable state）和可验证遗忘（verified forgetting）等机制。

1.3 长期记忆引入的三个根本性质

论文通过系统文献综述，识别出长期记忆引入的三个关键性质，这些性质是现有安全模型未能充分应对的：

  1. 持久性（Persistence）：一条被投毒的记忆条目可以在原始上下文关闭很久之后，在无限多个未来会话中被召回。
  2. 有状态性（Statefulness）：安全分析的单元从孤立的输入实例转变为Agent不断演化的记忆状态。一个积累了一系列微妙偏见的情景记忆的Agent，可能在任何单条记忆触发传统安全分类器之前就已经表现出行为漂移。
  3. 传播性（Propagation）：在多Agent和共享状态系统中，污染通过Agent间消息、共享存储和工具参数传播，产生跨会话、跨角色、跨用户的级联效应。

1.4 与现有综述的对比

论文通过表格对比了与现有综述的差异，从三个维度进行比较：是否覆盖完整生命周期、是否考虑良性风险（benign risk）、是否提出统一的概念框架。现有综述最多只部分覆盖其中一个维度，而本文在三个维度上都做到了完整覆盖。

二、记忆生命周期框架（Memory Lifecycle Framework）

论文的核心组织原则是将记忆的生命周期分解为六个阶段，如图2所示。这种分解的关键价值在于：它揭示了攻击在哪里被植入、如何跨阶段传播、以及防御在哪里最有效地介入。

❶ 写入（WRITE）

将内容提交到长期记忆中。写入可以通过以下方式发生：

  • 用户的显式指令
  • 隐式的对话摘要
  • 环境观察
  • 跨Agent的记忆共享

核心安全问题：记忆写入是否经过了显式的来源认证和授权检查？是否允许不受信任的外部内容以"用户认可"的身份进入记忆？
典型产物：原始输入、观察、摘要、外部内容。

❷ 存储（STORE）

对写入的内容进行索引、压缩、合并、衰减和驱逐。这个阶段决定了被投毒的记忆是否能持久存在、是否可追溯、是否会被放大。
关键安全含义：

  • 索引决定了哪些未来查询能重新激活一条记忆，使得检索键、语义标签和存储优先级成为潜在的对抗性放大器。
  • 保留/衰减/驱逐策略共同调节可用性和机密性。基于访问频率或时间近度的保留方案可能无意中让对抗性条目存活，同时丢弃合法条目。
  • 版本控制和审计决定了事后取证、回滚和可验证遗忘是否可能。
    当一条被投毒的条目被蒸馏为高层"教训"时，它实际上被提升到了更高的检索优先级，并以更大的表面权威性呈现。

典型产物：向量/图索引、摘要/教训、元数据与来源信息、保留策略。

❸ 检索（RETRIEVE）

通过嵌入相似度、关键词匹配、图检索或混合路由，将先前存储的记忆条目带回当前上下文。
关键安全含义：检索不是一个中性的查找机制，它通过选择哪些记忆进入模型上下文、哪些被排除，来塑造下游推理。检索是连接过去写入和当前使用的瓶颈点（chokepoint）——一条数周前写入的记忆可以重新进入活跃上下文窗口，影响Agent当前的行为。
典型产物：检索到的条目、分数与排名、检索上下文、来源信息。

❹ 执行（EXECUTE）

检索到的记忆开始影响模型的规划、推理和工具使用决策。
关键安全含义：MCFA（Memory Control-Flow Attack）研究表明，一条足够显著的检索记忆可以覆盖用户的显式指令，决定Agent调用哪些工具、调用顺序和参数。这将记忆投毒从数据完整性问题提升为控制流问题。MemoryGraft进一步表明，被投毒的程序性记忆一旦被检索为先前的"成功经验"，可以作为任务解决策略被复用，在没有单独触发器的情况下静默替换Agent的行为。
典型产物：带记忆的提示、计划/思维链、工具调用、动作/输出。

❺ 共享与传播（SHARE & PROPAGATE）

决定污染是否横向传播（Agent到Agent通过共享记忆）、纵向传播（从个人用户到组织记忆）或时间传播（从一个会话到另一个会话通过持久化配置文件）。
关键安全含义：

  • Agent Smith研究表明，单个对抗性输入可以通过成对交换指数级传播，达到约一百万个多模态Agent。
  • ComPromptMized构建了零点击自复制提示，可以穿越基于GenAI的邮件助手，每个接收者的Agent吸收并重新发送payload给自己的联系人。

典型产物：消息、共享记忆、工具参数、跨Agent日志。

❻ 遗忘与回滚（FORGET & ROLLBACK）

系统删除被污染的记忆、回滚到已知安全状态、追溯被投毒条目的来源、并验证修复的有效性。
关键安全含义：与WRITE或RETRIEVE不同，FORGET阶段的风险不是引入新的payload，而是未能完全移除被发现的有毒或敏感记忆状态。不完全遗忘的原因在于，单条记忆可能在原始对话日志、摘要记忆卡、向量索引、反思教训、共享存储和审计记录中留下衍生物。仅删除可见条目可能在压缩摘要、检索索引或传播副本中留下可检索的残留，导致污染在表面清理后重新出现。
典型产物：删除记录、回滚快照、审计日志、验证证明。

跨阶段攻击链

论文特别强调了跨阶段攻击链的概念：毒在WRITE阶段被植入 → 在STORE阶段潜伏 → 在RETRIEVE阶段被重新激活 → 在EXECUTE阶段引导行为 → 通过SHARE传播 → 在FORGET阶段幸存。这种端到端的攻击链是单轮检测无法观察到的，因为投毒窗口在执行开始之前就已经关闭。

三、攻击模式（Attack Patterns）

3.1 写入阶段攻击：植入投毒记忆

论文按照攻击者权限递减的顺序组织写入路径攻击（见表2）：

  1. 语料库级投毒（Corpus-level Poisoning）： - AgentPoison：具有语料库写入权限的攻击者可以在嵌入空间中植入后门，投毒率低于0.1%，攻击成功率超过80%。 - BadRAG、Phantom：类似的语料库级后门攻击。
  2. 查询诱导注入（Query-induced Injection）： - MINJA：证明仅通过查询交互就足以永久改变记忆状态。它使用桥接步骤和指示提示，让Agent自己创建恶意记忆。 - InjecMEM：结合锚点和Multi-GCG技术，在MemoryOS上达到76.6%的攻击成功率。
  3. 环境注入（Environment-injected）： - eTAMP：完全消除了权限差距——攻击者无需与Agent交互，只需操纵Agent在正常操作中遇到的网页。对抗性网页内容在浏览过程中被吸收，产生8倍的"挫败感"放大。 - SpAIware：通过持久记忆中的恶意内容实施攻击。
  4. 程序性嫁接（Procedural Grafting）： - MemoryGraft：模仿语义程序而非注入事实性记忆，无需触发器即可跨会话持久化。

关键防御启示：有效的写入阶段攻击面不仅包括显式的记忆更新，还包括任何可以影响Agent决定存储什么的可观察上下文。

3.2 存储阶段攻击：来源、保留与审计

存储阶段是长期记忆安全的关键控制点：

  • 压缩放大（Compression Amplification）：A-MEM和MemGPT等系统中的压缩/摘要机制可能将投毒条目提升为更高优先级的"教训"。
  • 来源剥离（Provenance Stripping）：MemOS等系统中，如果来源信息在压缩过程中丢失，就无法追溯投毒条目的来源。
    论文强调：记忆安全必须锚定在存储时的来源追踪、版本控制、可审计性和策略感知保留上，而不是仅在检索或执行时事后补救。

3.3 检索与执行阶段攻击：从选择到行为引导

  • 控制流劫持（Control-flow Hijacking）：MCFA表明，足够显著的检索记忆可以覆盖用户的显式指令，决定Agent调用的工具、调用顺序和参数。
  • 检索投毒（Retrieval Poisoning）：PoisonedRAG、KEPo等通过操纵检索结果来影响生成。
  • 后门/触发器（Backdoor/Trigger）：AgentPoison、Phantom等在检索阶段通过特定触发器激活。
    WRITE→STORE→RETRIEVE→EXECUTE构成了端到端的攻击链。例如：一个在日常浏览中遇到的被操纵的网页观察可以被摘要为记忆条目并持久化到长期存储中。数天或数周后，在不同的会话和可能不同的任务上下文中，该条目被检索并静默引导工具调用。

3.4 共享与传播阶段攻击

  • 跨Agent传染（Cross-agent Contagion）：Agent Smith展示了单个对抗性输入通过成对交换指数级传播。
  • 自复制蠕虫（Self-replicating Worms）：ComPromptMized构建了零点击自复制提示。
  • 跨用户污染（Cross-user Contamination）：在共享状态的LLM Agent中，即使没有攻击者，也可能发生无意的跨用户污染。

3.5 遗忘与回滚阶段攻击

  • 残留衍生物（Residual Derivatives）："Ghost of the Past"展示了LLM记忆中的隐私泄露。PersistBench评估了长期记忆何时应该被遗忘。
  • 删除后重现（Reappearance after Deletion）：删除可见条目后，污染可能在压缩摘要、检索索引或传播副本中重新出现。
  • 失败的恢复/追溯（Failed Recovery/Traceback）：RAGForensics和MemOS试图解决追溯问题，但对动态更新的Agent记忆的端到端评估仍然有限。

四、防御机制（Defenses）

论文按照生命周期阶段组织防御机制，强调没有单一干预点足以打破完整的攻击链，需要分层防御架构。

4.1 写入时防御（Write-time Prevention）

  • 人工验证冻结（Human-verified Freeze）：VerificAgent在候选记忆被提交到冻结的安全合约之前进行审计。
  • 来源标记（Provenance Tagging）：MemCube风格的记忆单元在写入时附加来源、版本、敏感度和时间元数据，使后续审计、访问控制和回滚成为可能。PROV-AGENT扩展了W3C PROV-DM标准到Agent工作流来源追踪。

4.2 存储时防御（Store-time Defenses）

存储时防御相对不发达。但版本化快照、写入日志、内容可寻址记录和压缩审计为后续恢复提供了必要的架构基础。W3C PROV等来源标准提供了表示和管理这些带有血缘关系的记忆对象的序列化层。

4.3 检索时防御（Retrieve-time Detection）

这是防御机制开发最集中的阶段：

  • 可认证聚合（Certifiable Aggregation）：RobustRAG通过"隔离-然后-聚合"生成提供对检索污染的可认证鲁棒性。
  • 信任评分（Trust Scoring）：TrustRAG和SeCon-RAG使用聚类、信任评分、语义相似度和矛盾感知过滤来区分良性和恶意检索内容。
  • 基于激活的检测（Activation-based）：RevPRAG通过投毒和非投毒生成之间的激活差异来检测投毒。
  • 记忆原生共识（Memory-native Consensus）：A-MemGuard检索语义相关的记忆，比较独立推理路径，将分歧视为异常信号，并将检测到的攻击蒸馏为教训记忆用于未来加固。

4.4 执行时防御（Execute-time Containment）

  • 信息流控制（Info-flow Control）：CaMeL、FIDES和PCAS通过分离数据平面和控制平面，限制不受信任内容对工具使用或程序流的影响。
  • 工具权限（Tool Privilege）：Progent、IsolateGPT和类型导向的权限分离通过细粒度工具策略、执行隔离和类型化权限边界来减少爆炸半径。
  • 上下文隐私（Contextual Privacy）：针对LLM Agent的上下文化隐私防御和运行时规范执行。

4.5 共享时防御（Share-time Governance）

  • 主体范围访问（Principal-scoped Access）：Collaborative Memory通过时间演化的主体-资源图建模多用户和多Agent访问。
  • 传染检测（Contagion Detection）：BlindGuard使用无监督图级异常检测来标记先前未见的多Agent传染模式。

4.6 遗忘/回滚防御（Forget/Rollback Recovery）

这一阶段的防御相对稀少：

  • 取证追溯（Forensic Traceback）：RAGForensics展示了对静态RAG语料库的事后追溯是可行的。
  • 快照/回滚（Snapshot/Rollback）：MemOS提供了完整性检查、策略执行、快照和回滚原语。
  • 机器遗忘（Machine Unlearning）：TOFU、RAG-unlearn等尝试从RAG系统中删除知识。
    但对于动态更新的Agent记忆，端到端评估仍然有限，特别是在验证删除、确保可靠回滚和支持取证追溯方面。

五、可验证记忆治理框架（Verifiable Memory Governance, VMG）

5.1 核心问题

在综述了攻击和防御之后，论文提出了一个核心问题：一个长期记忆Agent或LLM系统必须提供哪些可验证的机制，才能维持对其自身记忆状态的可审计、可恢复的控制？

5.2 五个核心原语

  1. 写入授权（Write Authorization, WA）：每条提交到长期记忆的条目必须可归因于一个经过认证的来源，并在合并前通过显式授权检查，防止不受信任的外部内容以用户认可的身份进入记忆。
  2. 来源可见性（Provenance Visibility, PV）：每条记忆条目必须携带可查询的、血缘完整的来源记录，可追溯到其原始写入事件（经过任何中间摘要或合并步骤），支持事后归因和取证分析。
  3. 主体范围检索（Principal-Scoped Retrieval, PS）：检索函数只返回授权范围包含查询主体的条目，即使在对抗性查询下也能防止跨用户或跨Agent的记忆泄露。
  4. 可回滚性（Rollbackability, RB）：系统维护版本化快照和写入日志，足以将记忆存储恢复到任何先前时间点的已知安全状态，支持攻击后恢复。
  5. 可验证遗忘（Verified Forgetting, VF）：删除操作后，系统可以通过删除后成员测试证明目标内容不再可从任何基底恢复——包括原始日志、压缩摘要、向量索引和传播副本。

5.3 形式化定义

为使五个原语可评估，论文将它们定义为记忆存储 $M_t$（时刻 $t$ 的记忆状态）上的谓词。每条记忆 $m \in M_t$ 携带元数据 $(\text{src}(m), \text{scope}(m), \text{prov}(m), \text{ver}(m))$，分别表示来源主体、授权主体集合、来源记录和版本标识符。
写入授权：

$\displaystyle \textbf{WA}(M_t) := \forall m \in M_t,\ \text{src}(m) \neq \bot \wedge \text{auth}_W(\text{src}(m), m, t) = 1$

其中 $\bot$ 表示未定义或缺失的来源主体，$\text{auth}_W$ 表示显式的写入时授权检查。
来源可见性：

$\displaystyle \textbf{PV}(M_t) := \forall m \in M_t,\ \text{Queryable}(m) \wedge \text{LineageComplete}(m)$

要求每条记忆条目维护可查询的来源，可追溯到其原始写入事件，血缘在摘要、合并或蒸馏过程中保持完整。
主体范围检索：

$\displaystyle \textbf{PS}(M_t) := \forall q, \pi,\ R(q, \pi, M_t) \subseteq \{m \in M_t : \pi \in \text{scope}(m)\}$

对于任何查询 $q$ 和请求主体 $\pi$，检索函数 $R(q, \pi, M_t)$ 的输出严格限制在 $\pi \in \text{scope}(m)$ 的条目中。
可回滚性：

$\displaystyle \textbf{RB}(M_t) := \forall\, t_0 < t\ \text{s.t.}\ \text{rollback}(M_t, t_0) = M_{t_0}$

系统能够将当前记忆存储回滚到某个先前状态 $M_{t_0}$（$t_0 < t$）。
可验证遗忘：

$\displaystyle \textbf{VF}_\varepsilon(M_t) := \forall X,\ \Pr_{q \sim Q_X}[\text{Expose}_X(q, F_X(M_t)) = 1] \leq \varepsilon$

其中 $F_X(\cdot)$ 是从记忆存储中删除目标内容 $X$ 的删除算子，$Q_X$ 是意图恢复 $X$ 的对抗性探测查询分布，$\text{Expose}_X(q, M')$ 是一个二值指示器，当删除后存储 $M' = F_X(M_t)$ 返回的响应充分重建了 $X$ 时等于1。该谓词将任何探测查询能在删除后重新暴露目标内容 $X$ 的概率限制在 $\varepsilon$ 以内。
最优系统应在时刻 $t$ 满足 $\varepsilon$-VMG：

$\displaystyle \textbf{MS}_\varepsilon(M_t) := \textbf{WA} \wedge \textbf{PV} \wedge \textbf{PS} \wedge \textbf{RB} \wedge \textbf{VF}_\varepsilon$

5.4 原语间的依赖关系

在基于血缘的删除下，原语形成一个设计预序：

$\displaystyle \textbf{VF}_\varepsilon \preceq \textbf{RB} \preceq \textbf{PV} \preceq \textbf{WA}$

其中 $X \preceq Y$ 表示实现 $X$ 需要 $Y$ 作为架构前提条件。PS（主体范围检索）与这条血缘链正交，但对任何机密性声明都是必要的。
具体来说：

  • PV依赖于WA：血缘完整的来源追踪要求每个写入事件携带经过认证的来源主体 $\text{src}(m) \neq \bot$；没有写入时授权，来源记录可能存在但无法锚定到已验证的来源，使血缘不完整且事后归因不可靠。
  • RB依赖于PV：可靠的回滚需要知道哪些条目来自哪里。
  • VF依赖于RB：可验证遗忘需要能够追踪和回滚所有衍生物。
    论文将这种依赖关系可视化为一个依赖塔（图3）：最宽、最成熟的基础是WA；每个后续层变窄且部署程度降低。当前文献表明，PV（支撑RB和VF的基础）在已发表的架构中仍然罕见。这产生了一个关键诊断洞察：近期进展应聚焦于构建来源基础设施，然后再追求其架构前提条件尚未就位的更高层原语。

5.5 各原语的威胁、防御与评估指标

论文在附录表3中为每个原语指定了代表性威胁、对应防御方向和建议评估指标：

原语 代表性威胁 代表性防御 建议指标
WA 查询诱导注入、环境注入投毒 类型化写入验证、人工/策略仲裁 有界假阳性率下的自适应注入存活率
PV 来源监控失败、模仿嫁接 来源门控检索、保留血缘的压缩 可追溯到来源事件的条目比例
PS 跨用户污染、黑盒提取 基于能力或标签的检索策略 脚本化查询套件下的跨主体泄露率
RB 压缩放大毒素、行为漂移 RAGForensics风格的追溯 修复时间；定位的有毒条目比例
VF 残留衍生物、摘要中的重现 跨原始/摘要/索引/权重的协调删除 删除后成员/重现测试

六、与人类记忆的类比（概念基础）

论文的生命周期视角部分受到人类记忆的启发。认知神经科学将记忆视为一个重建性和可再巩固的系统，其中经验被编码、巩固、重新激活，有时随着上下文和目标的变化而被改写。
在人类记忆中，错误信息通常通过来源监控失败、信心膨胀、回忆后再巩固和社会传染来运作，而非直接覆写。对应的Agent级失败包括：

  • 来源失败：注入的内容可能被错误归因为Agent自身的经验。
  • 读取时改写：通过摘要或反思，投毒内容被提升为更权威的教训记忆。
  • 跨Agent污染：通过共享记忆和Agent间通信传播。

七、关键发现与未来方向

主要发现

  1. 写入和检索阶段的威胁研究较为充分，而存储、共享和遗忘阶段的防御相对稀少。
  2. 没有现有基准测试覆盖完整的记忆生命周期。
  3. LTM安全不能仅在检索或执行时事后补救，必须从一开始就锚定在存储时的来源追踪、版本控制和策略感知保留上。
  4. 来源基础设施（PV）是支撑回滚和可验证遗忘的关键前提，但在现有架构中仍然罕见。

未来方向

  • 设计覆盖整个记忆生命周期的基准测试，包括跨会话污染、共享时传播和遗忘时恢复。
  • 构建来源基础设施作为近期优先事项。
  • 解决跨主体传播和删除后验证的关键差距。

局限性

  1. LLM Agent长期记忆安全是一个快速发展的领域，论文可能无法完全捕捉最新或未发表的进展，特别是工业记忆系统的内部设计。
  2. 记忆生命周期框架是一个组织性脚手架而非严格分解——实践中阶段之间的边界可能模糊（检索和执行可能紧密耦合，存储和摘要可能持续发生，共享可能通过工具调用隐式发生），因此某些攻击和防御可能跨越多个阶段。

原文摘要

The emergence of writable, cross-session persistent memory in LLM agents introduces a qualitatively different threat landscape from conventional input-centric security concerns, characterized by three properties: persistence, statefulness, and propagation. To systematically characterize this landscape, we propose a Memory Lifecycle Framework that organizes attacks, defenses, and their cross-phase dependencies along two axes: six lifecycle phases (Write, Store, Retrieve, Execute, Share & Propagate, Forget & Rollback) and four security objectives (Integrity, Confidentiality, Availability, Governance). This analysis in turn exposes the need for formal security guarantees at the system level, motivating Verifiable Memory Governance(VMG), a framework of five architectural primitives that specifies what verifiable mechanisms a long-term-memory system must provide to maintain auditable, recoverable control over its memory state. Our analysis indicates that robust Long-Term Memory (LTM) security cannot be retrofitted at retrieval or execution time alone, but must be anchored in storage-time provenance, versioning, and policy-aware retention from the outset.
