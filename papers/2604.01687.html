CoEvoSkills: Self-Evolving Agent Skills via Co-Evolutionary Verification

Hanrong Zhang, Shicheng Fan, Henry Peng Zou, Yankai Chen, Zhenting Wang, Jiayu Zhou, Chengze Li, Wei-Chieh Huang, Yifei Yao, Kening Zheng, Xue (Steve) Liu, Xiaoxiao Li, Philip S. Yu

论文原文 ↗下载文献卡片 Markdown

核心机制

CoEvoSkills 让技能生成器与代理验证器协同迭代，构建包含说明、脚本和参考资料的多文件技能包；代理测试通过后，再调用隐藏的真实测试决定是否继续改进。

适用范围与局限

主要研究技能效用与跨模型迁移，不是恶意技能的安全准入保证。生成器和代理验证器看不到真实测试内容，但仍依赖隐藏 ground-truth oracle 的反馈，不能理解为完全没有外部正确性信号。

与现有文献的关系

可与 AWM 的经验工作流、Trace2Skill 的轨迹到技能提取，以及 SEDM 的写入验证对照：共同问题是如何把一次执行变成可复用资产，但优化对象与反馈可见性不同。验证器共同演化也不等于它可以自行定义安全标准。

详细解读

论文核心总结

该论文提出了CoEvoSkills框架，解决的核心问题是：如何让LLM agent自主生成高质量的"技能包"(skills)。Anthropic提出的agent skill概念不同于简单的工具(tool)调用——skill是一个包含工作流指令、可执行脚本和领域参考材料的多文件结构化包。目前skill的生成高度依赖人工撰写，不仅费时费力，而且存在人机认知错位问题（人类设计的skill未必适合LLM agent的实际推理方式）。CoEvoSkills通过让Skill Generator（技能生成器）和Surrogate Verifier（代理验证器）进行协同进化，在生成器与代理验证器看不到 ground-truth 测试内容的条件下，迭代生成、验证和改进多文件 skill 包；代理测试通过后，仍依赖隐藏 oracle 的外部反馈。在 Claude Opus 4.6 + Claude-Code 的 SkillsBench 设置中，该方法达到71.1%的通过率，比无skill基线高40.5个百分点，比人工撰写的skill高17.6个百分点，并且进化出的skill可以跨模型迁移。

1. 研究背景与动机

1.1 从Tool到Skill的演进

LLM agent近年来在推理、规划、记忆和交互等方面快速进步，其中一个关键能力是调用外部工具和API。然而，面对复杂的专业任务（如多步软件修复、科学分析、企业数据管道编排），仅靠孤立的工具调用远远不够。agent需要跨多个步骤协调一致的操作过程：分解目标、协调工具、从失败中恢复、验证中间输出。

为此，Anthropic提出了agent skills的概念。论文Figure 1清晰展示了tool和skill的区别：

  • Tool（工具）：一个简单的、自包含的函数。例如一个货币转换函数 convert(amount, from_ccy, to_ccy, rates)。
  • Skill（技能）：一个结构化的多文件包，包含一个文件夹结构，里面有核心入口文件SKILL.md、参考资料目录references/、可执行脚本目录scripts/、资源文件目录resources/等。它是工作流指令、可执行脚本和领域参考资料的打包集合。

SkillsBench的评估证实，配备精心设计的skill能在软件工程、科学分析等多个专业领域带来一致的性能提升。

1.2 现有方法的问题

尽管skill有用，但当前的skill生成几乎完全依赖人工撰写，存在两个核心问题：

（1）人工撰写费力且质量不稳定。 SkillsBench的评估发现，人工撰写的skill效果极不均匀——某些领域（如Energy、Robotics）受益明显，但某些领域（如Natural Science）在加入人工skill后性能反而下降。

（2）人机认知错位（Human–Machine Cognitive Misalignment）。 论文假设这种不一致性的关键原因在于：对人类专家来说直观的工作流和抽象方式，并不天然匹配LLM agent处理上下文、推理和执行的方式。换句话说，人类觉得好的skill，agent未必能有效使用。

1.3 为什么现有自进化方法不够

近年来有一些让LLM agent自进化工具或工具库的方法（如Voyager、SkillCraft等），但它们存在工具-技能鸿沟（tool-skill gap）：

  • 这些方法本质上是为一次性生成简单的、自包含的函数而设计的，无法处理多文件skill包的创建。
  • EvoSkill等方法依赖ground-truth答案进行失败诊断，依赖验证集性能进行skill选择，这在实际场景中通常不可用。

2. 方法：CoEvoSkills框架

2.1 方法概览

CoEvoSkills需要克服两个核心困难：

  1. 单次生成多文件skill包本质上不可靠——复杂的多文件结构容易出现覆盖缺口和逻辑错误。
  2. agent在自进化过程中缺乏详细的ground-truth诊断反馈——方法隐藏真实测试内容，但仍保留 oracle 的通过/失败信号。

CoEvoSkills的核心思路是让两个组件协同进化：

  • Skill Generator（技能生成器）：迭代地生成和改进skill包。
  • Surrogate Verifier（代理验证器）：一个独立的LLM会话，在没有ground-truth测试内容的情况下，自主合成测试断言，提供结构化的失败诊断反馈。

两者通过"生成-验证-改进"（generate–verify–refine）的迭代循环协同进化。

2.2 问题形式化

由于agent永远不知道隐藏的ground-truth测试到底检查什么（成功标准完全隐藏），论文将任务环境建模为一个部分可观察马尔可夫决策过程（POMDP） $\mathcal{M} = \langle \mathcal{X}, \mathcal{A}, \mathcal{T}, \mathcal{O}, \Omega, \mathcal{R} \rangle$，其中：

  • $\mathcal{X}$：底层状态空间（完整的文件系统和进程）
  • $\mathcal{A}$：agent动作空间（终端命令和文件编辑）
  • $\mathcal{T}(x' | x, a)$：确定性状态转移
  • $\mathcal{O}$：观察空间（命令执行结果）
  • $\Omega(o | x, a)$：从后续状态到部分观察的映射
  • $\mathcal{R}(y_H) \in [0, 1]$：根据隐藏的ground-truth测试评估终态输出

Agent只能接收部分观察 $o_t \sim \Omega(\cdot | x_t, a_t)$，基于观察-动作历史 $h_t = (o_1, a_1, \ldots, a_{t-1}, o_t)$ 行动。

优化目标：Skill $\mathcal{S}$ 条件化agent的策略：

$$a_t \sim \pi_\theta(a_t | h_t, \mathcal{S})$$ 定义skill $\mathcal{S}$ 下的期望终态奖励：

$$J(\mathcal{S}) \triangleq \mathbb{E}_{\tau \sim P(\tau | \pi_\theta, \mathcal{S}, \mathcal{M})}[\mathcal{R}(y_H)]$$ 目标是找到最优skill：

$$\mathcal{S}^* = \arg\max_{\mathcal{S}} J(\mathcal{S})$$

2.3 CoEvoSkills的核心机制

直接优化 $J(\mathcal{S})$ 是不可行的：ground-truth评估计算昂贵且只返回不透明的通过/失败信号。为此引入代理验证器奖励 $\tilde{\mathcal{R}}(y, \mathcal{V})$：

$$\tilde{\mathcal{R}}(y, \mathcal{V}) \triangleq \frac{1}{|\mathcal{V}|} \sum_{k=1}^{|\mathcal{V}|} \mathbf{1}[e_k(y)] \in [0, 1]$$ 其中 $\mathcal{V} = \{e_1, \ldots, e_{|\mathcal{V}|}\}$ 是由独立验证器生成的确定性测试断言集合。

CoEvoSkills通过交替优化进行：

Skill改进（固定验证器测试，改进skill）：

$$\mathcal{S}^{(i+1)} \leftarrow \arg\max_{\mathcal{S}} \tilde{\mathcal{R}}(\Phi(\mathcal{S}, \mathcal{E}), \mathcal{V}^{(j)})$$ 测试升级（当代理验证器通过但oracle失败时，升级测试）：

$$\mathcal{V}^{(j+1)} \sim \pi_\theta^V(\cdot | I, \mathcal{D}, y^{(i)}, \mathcal{V}^{(j)}), \quad \text{if } \mathbf{1}[\tilde{\mathcal{R}}(y^{(i)}, \mathcal{V}^{(j)})=1 \wedge \mathcal{R}(\hat{y}^{(i)})<1]$$

Skill Generator的工作方式

Skill Generator维护一个持久的对话上下文 $C$。初始上下文 $C^{(0)} = (I, \mathcal{B}, \mathcal{S}_{\text{meta}})$，其中 $I$ 是任务指令，$\mathcal{B}$ 是任务相关背景知识，$\mathcal{S}_{\text{meta}}$ 是一个领域无关的"元技能"（教agent如何创建skill）。

每次修订时：

$$\mathcal{S}^{(i+1)} \sim \pi_\theta(\cdot | \mathcal{S}^{(i)}, C^{(i+1)}), \quad C^{(i+1)} = C^{(i)} \oplus \mathcal{F}^{(i,j)}$$ 其中 $\mathcal{F}^{(i,j)}$ 是Surrogate Verifier提供的失败诊断，包括失败的测试用例、根因分析和可操作的修改建议。$\oplus$ 表示将反馈追加到LLM上下文。

Surrogate Verifier的工作方式

Surrogate Verifier使用独立的LLM会话 $\pi_\theta^V$，与Generator信息隔离——它只能访问任务指令 $I$、可观察输入 $\mathcal{D}$、agent输出 $y^{(i)}$ 和自己之前的测试 $\mathcal{V}^{(j)}$。它无法访问Generator的推理过程、skill源代码、隐藏的oracle标准或测试内容。

它迭代地改进测试套件：

$$\mathcal{V}^{(j+1)} \sim \pi_\theta^V(\cdot | I, \mathcal{D}, y^{(i)}, \mathcal{V}^{(j)})$$ 当代理奖励 $\tilde{\mathcal{R}} < 1$ 时，它还生成结构化的失败诊断 $\mathcal{F}^{(i,j)}$，反馈给Generator。

协同进化的双反馈路径

整个协同进化有两条反馈路径：

  1. 代理验证器失败（$\tilde{\mathcal{R}} < 1$）：测试套件 $\mathcal{V}$ 固定不变，失败诊断 $\mathcal{F}$ 驱动skill修订。
  2. 代理验证器通过但oracle失败：只返回一个不透明的通过/失败位（不暴露测试内容或失败细节，以减少直接针对隐藏测试内容的过拟合；反复使用通过/失败反馈仍可能产生自适应过拟合）。此时Surrogate Verifier必须独立升级其测试套件——例如生成更多样、更全面、更有挑战性的测试用例。

Algorithm 1详细描述了完整流程，设定最多 $K=5$ 轮Ground Truth Oracle测试和 $M=15$ 次代理修复重试，以及上下文使用比例上限 $\beta=0.7$。

3. 实验

3.1 实验设置

  • 评测基准：SkillsBench，85个任务，覆盖11个专业领域，每个任务配有确定性验证器，支持可复现的二值通过/失败评估。
  • 主要指标：通过率（pass rate），即所有测试通过的任务比例。
  • 进化骨干模型：Claude Opus 4.6和GPT-5.2。
  • Agent执行工具：Claude-Code和Codex。

五个基线：

  1. No-Skill Baseline：无任何skill
  2. Self-Generated Skills：agent一次性生成1-5个skill文档（来自SkillsBench的条件）
  3. CoT-Guided Self-Generation：在2的基础上加五步思维链提示
  4. Skill-Creator：Anthropic官方的skill创建工具（替换为自动化模式）
  5. Human Curated Skills：SkillsBench发布的人工撰写skill

3.2 RQ1：Skill质量对比

CoEvoSkills在Claude Opus 4.6 + Claude-Code上达到71.1%的通过率：

  • 比No-Skill基线（30.6%）高 +40.5pp
  • 比Human Curated Skills（53.5%）高 +17.6pp
  • Skill-Creator只达34.1%，两个Self-Generated基线分别为32.0%和30.7%，几乎与无skill基线持平

这些对照支持迭代验证循环在所测设置中的作用，而不能推出所有不采用共同演化的技能生成方法都无效。

Takeaway 1：在所测任务与模型下，自进化 skill 可以优于人工 skill。 这种比较受任务集合、技能质量与验证预算影响，不是对人类技能设计能力的一般排序。

3.3 RQ2：跨模型迁移性

用Claude Opus 4.6进化出的skill，迁移到6个不同厂商的额外模型上：

模型 有skill 无skill 提升
Claude Opus 4.6（自进化） 71.1% 30.6% +40.5
GPT-5.2（自进化） 69.8% 29.6% +40.2
GPT-5.2（迁移） 65.0% 29.6% +35.4
Claude Sonnet 4.5（迁移） 63.1% 20.0% +43.1
Claude Haiku 4.5（迁移） 54.5% 10.4% +44.1
Qwen3 Coder（迁移） 50.8% 8.4% +42.4
DeepSeek V3（迁移） 48.8% 13.0% +35.8
Mistral Large 3（迁移） 43.1% 4.9% +38.2

所有模型都获得约35-44个百分点的显著提升。有趣的是，GPT-5.2使用Opus进化的skill（65.0%）不如自己进化的skill（69.8%），说明模型匹配的进化有温和但一致的优势。

Takeaway 2：Skill可跨模型族迁移。 进化出的skill编码了可复用的任务结构，而非模型特定的产物。

3.4 RQ3：领域级分析

在11个专业领域中，自进化skill在9/11个领域超越人工skill，最大优势在Finance（+56.9pp）和Cybersecurity（+23.2pp）。

特别值得注意的是Natural Science领域：人工skill反而导致性能下降，而自进化skill则带来了显著提升——这一现象与论文提出的人机认知错位解释一致，但性能差异本身不能独立证明该机制。

Takeaway 3：人工技能可能发生负迁移。 在所测领域中，协同进化产生了更适合执行模型的流程；这种结果不排除技能覆盖、实现质量和验证预算等其他解释。

3.5 进化动态

Figure 2展示了进化轮次的通过率变化：

  • 第0轮（无验证的一次性生成）：与无skill基线持平（~32%）
  • 验证迭代开始后急剧上升：第2轮44%，第3轮63%（超过人工skill的53.5%），第5轮收敛至75%

每个任务平均需要4.1次验证周期和2.4次Ground Truth Oracle轮次即可收敛。约40%的迭代由Surrogate Verifier自行解决，无需escalate到oracle。

4. 消融实验

设置 通过率 相对完整框架的下降
CoEvoSkills（完整框架） 71.1% —
去掉Surrogate Verifier 41.1% −30.0
去掉进化（仅用上下文） 42.4% −28.7
No-Skill基线 30.6% −40.5
  • 去掉Surrogate Verifier：性能从71.1%骤降至41.1%。Generator仍可进化5轮，但只能依赖oracle的不透明通过/失败信号，无法进行有针对性的修复。
  • 仅用背景上下文（无进化）：30.6% → 42.4%，说明上下文提供了有用的基底，但协同进化将其转化为结构化、经验证的可执行skill包。

5. 案例研究：系外行星凌星周期检测

论文附录C详细展示了一个进化轨迹。任务是从TESS光变曲线数据中检测系外行星轨道周期，要求精确到5位小数。

进化过程经历了4个版本：

  • V1：使用BLS + biweight去趋势。Surrogate Verifier捕获bug（0/15测试通过），未到达oracle。
  • V2：优化BLS参数。Oracle返回75%——检测到的周期接近真值但BLS网格分辨率不足以达到5位小数精度。
  • V3：换用中值滤波去趋势。Oracle仍返回75%。agent意识到在BLS框架内的增量调参不够。
  • V4：根本性转换——从BLS切换到TLS（Transit Least Squares，使用真实的临边变暗凌星模型），加入Savitzky-Golay滤波、两阶段周期搜索（粗搜+精炼±2%）、周期谐波别名检查。Oracle返回100%。

这个案例展示了协同进化的三个关键性质：

  1. Surrogate Verifier早期捕获实现bug和检测重构导致的回退，节省oracle预算
  2. Ground Truth Oracle暴露根本算法限制（BLS精度上限），这是Surrogate Verifier无法检测的
  3. 协同进化循环使agent实现了质的方法转变——从固定算法内的参数调优（V1-V3）到彻底更换算法（V4）

对比人工skill和自进化skill：人工提供了5个skill共1096行文档但无可执行代码，平等地罗列BLS/TLS/Lomb-Scargle三种算法；自进化skill只有1个统一skill（64行文档+142行Python，9个可调用函数），明确指定TLS并附带经3次BLS失败验证的理由。

6. 总结与局限

CoEvoSkills通过代理诊断减少了对详细真实测试内容的依赖，但仍需要隐藏 ground-truth oracle 和任务环境，未解决完全没有外部正确性信号的验证问题。多轮 oracle 反馈也不能等同于从未查询过的最终封闭测试。其局限还包括初始化时可用的任务相关背景知识；技能效用验证不能直接替代恶意行为的安全验证。未来方向是开放世界skill进化，即agent自主寻找和验证超出初始任务上下文的额外知识。

原文摘要

Anthropic proposes the concept of skills for LLM agents to tackle multi-step professional tasks that simple tool invocations cannot address. A tool is a single, self-contained function, whereas a skill is a structured bundle of interdependent multi-file artifacts. Currently, skill generation is not only label-intensive due to manual authoring, but also may suffer from human--machine cognitive misalignment, which can lead to degraded agent performance, as evidenced by evaluations on SkillsBench. Therefore, we aim to enable agents to autonomously generate skills. However, existing self-evolving methods designed for tools cannot be directly applied to skills due to their increased complexity. To address these issues, we propose CoEvoSkills, a self-evolving skills framework that enables agents to autonomously construct complex, multi-file skill packages. Specifically, CoEvoSkills couples a Skill Generator that iteratively refines skills with a Surrogate Verifier that co-evolves to provide informative and actionable feedback without access to ground-truth test content. On SkillsBench, CoEvoSkills outperforms five baselines on both Claude Code and Codex, and generalizes strongly to six additional LLMs. The code is publicly available at https://github.com/Zhang-Henry/CoEvoSkills.
