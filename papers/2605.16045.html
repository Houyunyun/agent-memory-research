RecMem: Recurrence-based Memory Consolidation for Efficient and Effective Long-Running LLM Agents

Zijie Dai, Shiyuan Deng, Sheng Guan, Yizhou Tian, Xin Yao, Xiao Yan, James Cheng

论文原文 ↗下载文献卡片 Markdown

核心机制

原始交互轻量缓冲，重复触发情景与语义整合

适用范围与局限

详细解读

论文核心总结

这篇论文提出了RecMem，一种面向长期运行LLM智能体的高效记忆系统。其核心洞察是：现有记忆系统对每一条用户交互都调用LLM进行记忆提取和整合（即"急切式记忆巩固"），导致巨大的token消耗。RecMem借鉴重复经验有助于长期记忆巩固的认知启发，提出了"基于重现的记忆巩固"策略：将原始交互存入轻量级的"潜意识记忆"层，仅当语义相似的交互反复出现达到阈值时，才调用LLM提取情景记忆和语义记忆。同时引入"语义精炼"机制恢复被摘要遗漏的细粒度事实。实验表明，RecMem在LoCoMo和LongMemEval-S两个基准上，将记忆构建的token成本降低了最高87%，同时问答准确率超过了三个SOTA基线系统。

一、研究背景与问题动机

1.1 LLM智能体的长期记忆需求

大语言模型（LLM）虽然在各类任务上表现出色，但要让它们作为长期运行的智能体（long-running agents），就需要在持续的用户交互中不断积累经验。然而LLM面临两个核心限制：

  • 有限的上下文窗口：无法保留超出窗口长度的信息；
  • "迷失在中间"效应（lost-in-the-middle）：即使相关信息在长输入中存在，模型也可能无法有效利用。
    因此，外部记忆系统成为构建长期运行LLM智能体的关键组件。

1.2 现有记忆系统的共同问题：急切式记忆巩固

论文观察到，尽管现有记忆系统（如Zep、Mem0、A-Mem等）在记忆结构和提取方法上各有不同，但它们都采用了急切式记忆巩固（eager memory consolidation）方案：对每一条到来的用户交互，都调用LLM来提取事实并与已有记忆合并。
这种方案的问题在于：

  • 有些交互信息量很少或包含噪声；
  • 有些交互与已有记忆无关，可以直接检索原文而无需整合；
  • 对每条交互都运行LLM级别的处理是过度的（overkill），导致记忆构建阶段的token消耗极大。

1.3 认知科学的启发

论文借鉴多存储理论（Atkinson & Shiffrin, 1968）和互补学习系统框架，将重复出现的经验作为触发长期整合的信号。这是 RecMem 的设计启发，不意味着认知科学证明“只有重复经验才能形成长期记忆”，也不意味着一次性事件不重要。

二、问题形式化

2.1 对话式记忆的问题设定

论文聚焦于对话式记忆场景：智能体通过长期、多轮交互积累信息。形式化地，在时间步$t$，交互历史表示为序列$O_{1:t} = \{o_1, \ldots, o_t\}$，每个交互单元定义为：

$\displaystyle o_t = (s_t, x_t, \tau_t)$

其中$s_t \in \{\text{USER}, \text{ASSISTANT}\}$是说话者角色，$x_t$是消息内容，$\tau_t$是时间戳。给定查询$q$，目标是从基于$O_{1:t}$构建的外部记忆中检索相关证据，支持推理和回答生成。
与采用预先构建文档库的 RAG 设置相比，这里的重点是：对话信息以流式方式持续到达，系统必须在线地构建和更新记忆。RAG 本身也可以使用动态知识库，因此“静态还是动态”并不是 RAG 与 Agent Memory 的普遍分界。

2.2 记忆系统的范围

论文关注的是无需训练的、基于文本的外部记忆系统，用于流式对话场景中的LLM智能体。参数化记忆方法（需要重新训练或修改架构）和基于强化学习的方法被排除在讨论范围之外。

三、RecMem框架详解

3.1 总体架构

RecMem是一个三层记忆系统，其核心原则是：并非所有交互都值得LLM级别的巩固处理。
整体工作流程如下：

  1. 到来的消息首先被组织为原子交互单元，写入潜意识记忆（Subconscious Memory），仅使用轻量级的嵌入模型进行向量化，不调用LLM（§3.2）；
  2. 当系统观察到语义相似的交互内容持续重现时，才触发基于重现的巩固，调用LLM生成情景记忆（Episodic Memory）——对选中的多轮交互进行事件级抽象（§3.3）；
  3. 随后进行语义精炼（Semantic Refinement），从原始交互中恢复被情景摘要遗漏的细粒度事实，存入语义记忆（Semantic Memory）（§3.4）；
  4. 查询时，从三个存储层检索少量条目，合并上下文后由LLM生成回答（§3.5）。
    三种记忆的定义：
  • 情景记忆：存储有时间锚定的事件叙述，是关于某个主题如何跨多轮交互演变的连贯摘要；
  • 语义记忆：存储原子事实，包括通用知识、用户偏好、约束和实体关系；
  • 潜意识记忆：保存原始交互的忠实记录，作为安全网确保所有信息都可检索。

3.2 潜意识记忆

潜意识记忆管理器以最小计算成本维护交互历史的忠实记录。
粒度选择是一个关键设计考量。现有系统采用不同的摄入策略：有的处理单条消息，有的处理交互对，有的累积固定大小的上下文缓冲区。静态分组可能将时间相邻但语义无关的主题混在一起，稀释嵌入的特异性；而孤立处理单条消息则可能碎片化语义上下文（因为助手的回复通常依赖前面的用户查询才有意义）。
RecMem将每次消息交换（一个用户-助手轮次）作为原子单元。形式化地，$t$轮的多轮对话定义为：

$\displaystyle \mathcal{H}_t = (u_1, u_2, \ldots, u_t)$

$\displaystyle u_i = (m_i^{\text{usr}}, m_i^{\text{ast}}, \tau_i)$

其中$u_i$是第$i$轮的交互单元，包含用户消息$m_i^{\text{usr}}$、助手回复$m_i^{\text{ast}}$和时间戳$\tau_i$。
每个新到来的交互单元$u_i$被独立处理，构建潜意识记忆单元：

$\displaystyle s_i = (v_i, u_i) \quad \text{其中} \quad v_i = \Phi(u_i)$

$\Phi(\cdot)$是稠密向量编码器（即嵌入模型）。这些单元被立即索引到潜意识记忆存储$S_{\text{sub}}$中，实现为向量数据库，支持高效的语义检索和增量更新。

基于重现的记忆巩固触发机制

对于新到来的单元$s_i = (v_i, u_i)$，系统查询$S_{\text{sub}}$，检索与$v_i$余弦相似度排名前$k$的单元集合$\mathcal{N}_i$。然后基于严格的语义接近度过滤，定义相关集：

$\displaystyle \mathcal{R}_i = \{ s_j \in \mathcal{N}_i \mid \cos(v_i, v_j) \geq \theta_{\text{sim}} \}$

巩固仅在相关集大小满足重现计数阈值时触发（即$|\mathcal{R}_i| \geq \theta_{\text{count}}$）。此时，簇$\mathcal{C}_i = \mathcal{R}_i \cup \{s_i\}$被提升到更高层的记忆模块（情景记忆和语义记忆）；否则，$s_i$仅留在$S_{\text{sub}}$中。
这确保了巩固仅针对具有持续长期重现证据的记忆进行。

3.3 情景记忆

情景记忆捕捉跨多轮的事件级结构。为保持记忆紧凑，RecMem采用合并优先（merge-first）策略。
当潜意识单元$s_i = (v_i, u_i)$到来时，从情景存储$S_{\text{epi}}$中检索最近邻的情景$E^\star$。令$v_{E^\star} = \Phi(E^\star)$为该情景的嵌入。如果语义相似度允许，则严格执行就地更新：

$\displaystyle E^\star \leftarrow \text{LLM}_{\text{merge}}(E^\star, u_i) \quad \text{如果} \quad \cos(v_i, v_{E^\star}) \geq \theta_{\text{sim}}$

$\text{LLM}_{\text{merge}}$将新轮次$u_i$的内容整合到$E^\star$的叙述中。
为什么需要合并优先？ 如果没有这一步，每次重现触发的巩固都会在同一主题上产生一个新的独立情景，导致同一演变话题的情景表示被碎片化为多个断开的条目。合并优先将它们折叠为单个持续更新的叙述，保持情景存储紧凑且每个主题的叙述连贯。
如果合并不适用，则等待基于重现的巩固触发。给定触发的簇$\mathcal{C}_i$，提取交互单元$\mathcal{U}_C = \{u_j \mid (v_j, u_j) \in \mathcal{C}_i\}$，按时间戳排序形成时间序列$U_i^{\text{seq}} = (u^{(1)}, \ldots, u^{(|\mathcal{C}_i|)})$。巩固提示被设计为归纳式组织而非简单摘要。LLM处理格式化的序列以合成连贯叙述，必要时分割不同子主题：

$\displaystyle \mathcal{M}_i^{\text{epi}} = \text{LLM}_{\text{epi}}\left(\bigoplus_{k=1}^{|\mathcal{C}_i|} \text{Fmt}(u^{(k)})\right)$

$\text{Fmt}(\cdot)$是将每个交互单元格式化为文本表示的固定模板。输出$\mathcal{M}_i^{\text{epi}}$是一组新的情景单元；每个情景$E \in \mathcal{M}_i^{\text{epi}}$通过$\Phi(\cdot)$编码后存入$S_{\text{epi}}$。

3.4 语义记忆与语义精炼

语义记忆通过存储细粒度事实来补充情景记忆，解决两个问题：

  1. 事件级摘要可能遗漏细粒度但对查询关键的细节；
  2. 合并优先策略的副作用——随着情景通过反复合并吸收更多轮次，其摘要必然变得更宽泛和抽象，稀释了针对特定细节查询的检索精度。
    语义记忆通过将这些细节存储为独立的、范围狭窄的条目来对抗这一问题。

语义精炼的过程如下：
当新情景$E \in \mathcal{M}_i^{\text{epi}}$从源交互单元$\mathcal{U}_C$生成时，首先检索相关的已有语义事实作为历史上下文：

$\displaystyle \mathcal{V} = \text{TopK}_k(S_{\text{sem}}, \Phi(E))$

然后使用LLM精炼器推导新事实。以原始交互单元$\mathcal{U}_C$、情景摘要$E$和检索到的事实$\mathcal{V}$为条件，模型执行两个并行任务：

  1. 细节恢复（Detail Recovery）：扫描$\mathcal{U}_C$中的原始文本，识别被摘要$E$遗漏的关键实体；
  2. 事实维护（Fact Maintenance）：通过过滤$\mathcal{V}$中已知信息防止冗余，同时更新演变中的用户状态（如偏好变化）。
    提取过程形式化为：

$\displaystyle \mathcal{M}_i^{\text{sem}} = \text{LLM}_{\text{refine}}(E, \mathcal{U}_C, \mathcal{V})$

每个提取的事实$f \in \mathcal{M}_i^{\text{sem}}$作为独立条目存储，以保持检索特异性。

3.5 问答

生成回答时，RecMem首先将用户查询$q$编码为向量$v_q = \Phi(q)$，然后从三个存储中检索最相关的条目。为高效管理上下文窗口并确保多样覆盖，设置固定的潜意识检索预算，并将情景和语义预算耦合（$k_{\text{sem}} = 2k_{\text{epi}}$），得到三个上下文集$\mathcal{K}_{\text{sub}}$、$\mathcal{K}_{\text{epi}}$和$\mathcal{K}_{\text{sem}}$。最终答案由LLM基于检索到的上下文和原始查询生成。
默认参数：$k_{\text{sub}}=10$，$k_{\text{epi}}=5$，$k_{\text{sem}}=10$。

3.6 超参数设置与讨论

RecMem的巩固行为由两个关键超参数控制：

  • 相似度阈值$\theta_{\text{sim}}$：控制哪些交互被视为相关；
  • 重现阈值$\theta_{\text{count}}$：触发巩固所需的最小重现次数。
    较大的$\theta_{\text{sim}}$和$\theta_{\text{count}}$使巩固更保守，适合休闲开放式对话；较小的阈值使巩固更积极，适合任务导向的交互。推荐值：
  • 休闲场景：$\theta_{\text{sim}}=0.7$，$\theta_{\text{count}}=5$
  • 任务导向场景：$\theta_{\text{sim}}=0.6$，$\theta_{\text{count}}=4$
    灵敏度分析表明，性能在推荐默认值附近平滑变化，不依赖于精确的阈值校准。

通用性：虽然RecMem将情景记忆和语义记忆组织为扁平条目用于相似性检索，但基于重现的巩固是一个通用思想，不限于特定的记忆结构。更高层的记忆也可以采用知识图谱等替代结构。

四、实验评估

4.1 实验设置

评估协议：严格遵循增量评估协议——消息轮次按顺序流式输入记忆系统，模拟自然对话流，然后进行多轮查询。
数据集：

  • LoCoMo：伴侣式、生活分享对话，10个多会话对话（平均16K token），测试对演变个人历史的推理；
  • LongMemEval-S：智能体式、任务导向交互，500个对话（平均115K token），对记忆系统在高负载场景下的严格测试。

基线：

  • Full Context：将所有历史交互输入LLM回答；
  • Naive RAG：标准RAG，分块后基于嵌入相似度检索；
  • Mem0：事实提取管道，动态提取信息并通过LLM操作管理一致性；
  • A-Mem：受Zettelkasten笔记法启发的智能体记忆系统，通过实体链接连接记忆笔记；
  • MemoryOS：OS风格的分层框架，管理短期、中期和长期记忆。

评估指标：

  • 问答准确率：使用GPT-4o-mini作为LLM评判者的判断分数作为主要指标（优先于F1分数，因为F1对释义的开放式生成可能低估正确性）；
  • 计算效率：测量LLM token使用量，分为构建成本（记忆摄入阶段每对话平均）和查询成本（回答阶段每问题平均）。

实现细节：使用GPT-4o-mini和GPT-4.1-mini两个后端，嵌入使用text-embedding-3-small。

4.2 主要结果

LoCoMo上的结果

使用GPT-4.1-mini时，RecMem平均仅使用193.2K构建token，而Mem0为1520.8K，A-Mem为1459.9K，分别减少了87.3%和86.8%。尽管构建成本大幅降低，RecMem在记忆系统方法中取得了最高的总体分数（81.10），超过MemoryOS（67.60）、A-Mem（68.83）和Mem0（62.92）。
Full Context在LoCoMo上略优于RecMem（84.18 vs 81.10），这与LoCoMo相对较短的对话（约16K token）一致，全上下文推理仍然可行。但在更长的场景中，这一优势不再成立。

LongMemEval-S上的结果

使用GPT-4.1-mini时，RecMem将构建token减少了77.5%（相对Mem0）和71.1%（相对A-Mem），同时在所有方法中（包括Full Context和RAG）取得了最高的总体分数（76.80）。
RecMem在时间推理类别上表现出最清晰和最一致的优势。论文认为这是基于重现的巩固的结构性优势：

  • 急切巩固系统在每轮或局部缓冲区提交摘要边界，将同一演变主题的后续提及锚定到不同摘要中，碎片化了线索；
  • RecMem通过潜意识记忆中的相似性聚类跨时间距离聚合共指提及，通过时间戳排序的情景巩固重建每个簇内的时间顺序。
构建成本 vs. 查询成本

RecMem的效率提升来自减少构建时的LLM使用。查询时的token消耗在各记忆系统间保持在可比范围内。在流式部署中，构建时的差异随时间累积，可能主导总LLM使用量。

4.3 消融实验

在LoCoMo上使用GPT-4.1-mini进行消融研究，每次禁用一个组件：

变体 总体分数
移除潜意识记忆 51.88
移除语义记忆 70.58
直接提取（无语义精炼） 74.22
移除情景记忆 79.94
完整RecMem 81.10

关键发现：

  1. 移除潜意识记忆导致最大下降（81.10→51.88），因为未触发巩固的信息仅存在于此层；
  2. 情景记忆和语义记忆的贡献不对称：移除情景记忆仅小幅下降（→79.94），移除语义记忆下降更大（→70.58）。这反映了语义精炼下的分工——情景记忆捕捉高层结构和跨轮链接，语义记忆优先处理细粒度事实细节；
  3. 直接提取变体（不以情景记忆为参考直接从原始对话提取语义事实）分数从79.94降至74.22，证明情景记忆为语义精炼提供了必要的参考信号。

4.4 超参数灵敏度分析

  • $\theta_{\text{sim}}$的影响：在$\theta_{\text{sim}}=0.7$附近有清晰的峰值。过低会将语义无关的交互合并到同一簇中；过高会将相关交互碎片化为多个小簇。
  • $\theta_{\text{count}}$的影响：存在质量-成本的权衡。较低的$\theta_{\text{count}}$触发更早的巩固，每次巩固包含更少的原始交互单元，能更好地保留细粒度细节，但token消耗更高。从$\theta_{\text{count}}=5$增加到6时出现明显的性能下降（81.1→78.9），因为巩固变得过于保守，且累积的簇更大增加了摘要难度。
  • 检索预算：增加检索预算呈递减收益趋势，$k_{\text{sub}}=10$和$k_{\text{epi}}=5$是紧凑且有效的默认值。

五、局限性

  1. 依赖启发式阈值：$\theta_{\text{sim}}$和$\theta_{\text{count}}$目前需要手动指定，部署到交互密度差异显著的领域时可能需要重新校准。开发自适应或可学习的触发机制是未来方向。
  2. 重现作为显著性的代理：设计假设值得长期抽象的信息倾向于重现，但可能忽略罕见但关键的事件（如一次性的安全指令）。潜意识记忆层作为安全网缓解了这一风险——每个交互单元都被逐字保存且可直接检索，但不会受益于情景记忆的跨轮链接或语义记忆的事实级精炼。

六、运行示例

论文通过一个三轮交互的简化示例说明RecMem的工作流程（设$\theta_{\text{count}}=2$）：

  • 第1轮：用户询问订购生日蛋糕的建议。RecMem将此交互存入潜意识记忆，计算嵌入。"蛋糕"主题仅出现一次，$|\mathcal{R}_i| < \theta_{\text{count}}$，不触发巩固。
  • 第2轮：用户转向无关话题（洗深色牛仔裤）。新单元与蛋糕相关单元不相似，$|\mathcal{R}_i| = 1$，不触发巩固。
  • 第3轮：用户回到蛋糕话题。新单元检索到先前的蛋糕相关单元并通过相似度检查，$|\mathcal{R}_i| \geq \theta_{\text{count}}$，触发巩固。产生两个互补产物：
  • 情景记忆：将重现的轮次抽象为连贯的意图级叙述（用户正在为妹妹Mia准备生日蛋糕订单）；
  • 语义精炼：从底层原始轮次中提取原子事实（用户有个妹妹叫Mia；Mia对花生过敏；用户计划在SweetLeaf下单等）。

维度 内容
论文标题 RecMem: Recurrence-based Memory Consolidation for Efficient and Effective Long-Running LLM Agents
作者 Zijie Dai, Shiyuan Deng（通讯作者）, Sheng Guan, Yizhou Tian, Xin Yao, Xiao Yan, James Cheng
发表年份 2026
研究问题 现有LLM记忆系统对每个交互都进行急切的记忆整合（eager memory consolidation），导致大量token消耗，如何在降低记忆构建成本的同时保持甚至提升问答准确率？
研究方法 提出RecMem三层记忆架构：（1）潜意识记忆层使用轻量级嵌入模型缓存原始交互；（2）基于复现的整合机制，仅当语义相似交互达到阈值时才调用LLM提取情景记忆和语义记忆；（3）语义精炼机制从原始交互中恢复被情景摘要遗漏的细粒度事实。在LoCoMo和LongMemEval-S两个基准上与Mem0、A-Mem、MemoryOS等基线进行对比实验。
主要发现 RecMem在LoCoMo基准上将记忆构建token消耗降低最高87%（如从Mem0的1520.8K降至193.2K），同时在整体问答准确率上超越所有基线记忆系统（GPT-4.1-mini下达81.10 vs 次优68.83）。在LongMemEval-S上同样实现最高整体准确率（76.80），且在时序推理任务上表现尤为突出。
创新点 （1）识别了现有记忆系统急切整合的根本低效问题；（2）受认知科学多存储理论启发，提出基于复现的记忆整合策略，仅在语义相似交互反复出现时触发LLM处理；（3）设计语义精炼机制，以情景记忆为参照从原始交互中恢复被摘要压缩的细粒度事实，避免信息丢失。
局限性 （1）依赖静态的相似度阈值和复现计数阈值等启发式超参数，需针对不同交互密度手动调整；（2）以复现作为显著性的代理指标，可能遗漏罕见但关键的一次性事件（如安全指令），尽管潜意识记忆层可作为安全网保留原始交互。

结构化提纲

RecMem: 基于重现的记忆巩固机制——面向高效长期运行LLM智能体的记忆系统

研究背景与目标

  • LLM长期运行智能体面临的核心挑战
  • 上下文窗口有限，无法保留超长交互历史
  • "迷失在中间"效应导致长输入中相关证据利用不足
  • 现有记忆系统的根本低效性
  • 采用"急切记忆巩固"策略，对每一条交互都调用LLM进行提取和合并
  • 导致记忆构建阶段的token消耗极高（如Mem0达1520.8K，A-Mem达1459.9K）
  • 认知科学启发
  • 借鉴多存储理论与互补学习系统框架，以重复经验作为长期巩固的触发信号；这不是一次性事件不能被记住的普遍规律
  • 核心目标
  • 重新思考"何时"进行记忆巩固，大幅降低构建成本
  • 在显著减少token消耗的同时保持甚至提升问答准确率

研究方法

  • 三层记忆架构设计
  • 潜意识记忆层（Subconscious Memory）
    • 以用户-助手对话轮次为原子单元，使用轻量级嵌入模型编码
    • 存入向量数据库，支持高效语义检索，无需调用LLM
  • 情景记忆层（Episodic Memory）
    • 存储跨多轮交互的事件级时序叙事摘要
    • 采用"合并优先"策略，将同主题新内容就地合并到已有情景中，保持叙事紧凑连贯
  • 语义记忆层（Semantic Memory）
    • 存储细粒度原子事实（用户偏好、约束、实体关系等）
    • 弥补情景摘要中被压缩或遗漏的关键细节
  • 基于重现的记忆巩固机制（Recurrence-based Consolidation）
  • 新交互到达时查询潜意识存储，检索语义相似的top-k单元
  • 通过相似度阈值θ_sim过滤出相关集合R_i
  • 仅当相关集合大小达到重现计数阈值θ_count时才触发LLM巩固
  • 触发后对语义簇进行情景摘要提取和语义事实提取
  • 语义精炼机制（Semantic Refinement）
  • 以情景摘要为参照，回溯原始交互文本
  • 执行两个并行任务：细节恢复（识别摘要遗漏的关键实体）和事实维护（去重并更新演变中的用户状态）
  • 确保事实提取质量优于直接从原始对话中提取
  • 查询时检索策略
  • 从三层存储中分别检索固定预算的条目（ksub=10, kepi=5, ksem=10）
  • 将合并上下文与查询一起输入LLM生成答案

关键研究结果

  • LoCoMo基准测试
  • 使用GPT-4.1-mini时，RecMem构建token仅193.2K，相比Mem0降低87.3%，相比A-Mem降低86.8%
  • 整体准确率81.10，在所有记忆系统中最高，超过MemoryOS（67.60）、A-Mem（68.83）和Mem0（62.92）
  • LongMemEval-S基准测试（长上下文，平均115K tokens）
  • 构建token相比Mem0减少77.5%，相比A-Mem减少71.1%
  • 整体准确率76.80，超过所有基线方法（含Full Context的66.20）
  • 在时序推理类任务上表现尤为突出，得益于基于重现的跨时间聚类机制
  • 消融实验结果
  • 移除潜意识记忆导致最大性能下降（81.10→51.88），因其是原始交互的唯一忠实载体
  • 移除语义记忆下降显著（81.10→70.58），移除情景记忆下降较小（81.10→79.94），体现两者互补分工
  • 直接提取（无语义精炼）得分从79.94降至74.22，验证情景记忆对语义精炼的参照信号作用
  • 超参数鲁棒性
  • θ_sim在0.7附近有清晰最优点，θ_count=5在准确率与成本间取得最佳平衡
  • 性能在推荐默认值附近平滑变化，不依赖精确校准

研究结论与意义

  • 核心贡献
  • 揭示了现有记忆系统"急切巩固"范式的根本低效性
  • 提出基于重现的巩固策略，证明高保真长期记忆不需要对每条交互进行穷尽处理
  • 三层架构结合轻量潜意识存储与语义精炼，实现高准确率与低成本的统一
  • 广泛意义
  • 将记忆巩固重新定义为动态的、由重现驱动的过程
  • 呼吁社区将计算成本作为评估记忆系统的一等指标
  • 重现巩固思想具有通用性，可扩展至知识图谱等其他记忆结构
  • 局限性
  • 依赖静态启发式阈值，未来可探索自适应触发机制
  • 以重现作为显著性代理，可能遗漏罕见但关键的一次性事件（潜意识层作为安全网部分缓解）

原文摘要

Memory systems often organize user-agent interactions as retrievable external memory and are crucial for long-running agents by overcoming the limited context windows of LLMs. However, existing memory systems invoke LLMs to process every incoming interaction for memory extraction, and such an eager memory consolidation scheme leads to substantial token consumption. To tackle this problem, we propose RecMem by rethinking when memory consolidation should be conducted. RecMem stores incoming interactions in a subconscious memory layer and encode them using lightweight embedding models for retrieval. LLMs are only invoked to extract episodic and semantic memory when sustained recurrence are observed for semantically similar interactions. Such recurrence-based consolidation works because these interactions correspond to a semantic cluster with rich information and thus are worth extraction and summarization. To improve accuracy, RecMem also incorporates a semantic refinement mechanism that recovers the fine-grained facts omitted by memory extraction. Experiments show that RecMem reduces the memory construction token cost of three SOTA memory systems by up to 87% while exceeding their accuracy.
