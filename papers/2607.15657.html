详细解读

论文核心总结

这篇论文提出了一个名为LUCID的黑盒对抗攻击框架，揭示了多模态AI智能体（agent）持久化长期记忆系统中的一个结构性安全漏洞。核心发现是：攻击者仅通过对用户分享的图像施加人眼不可察觉的微小扰动，无需访问目标模型权重、文本通道、检索编码器或记忆库内部结构，就能系统性地腐蚀智能体的多模态长期记忆。LUCID定义了两种攻击模式——"记忆投毒"（memory poisoning，篡改已有对话中的图像使智能体"错误回忆"真实事件）和"记忆注入"（memory injection，在新对话轮次中植入虚假视觉记忆使智能体"凭空捏造"事件）。在五种架构各异的记忆后端和多个主流大语言模型上的实验表明，LUCID在投毒攻击上达到61.6%的攻击成功率，在注入攻击上达到58.4%的攻击成功率，而现有防御手段均无法完全消除这一威胁。

1. 研究背景与问题动机

1.1 多模态AI智能体的长期记忆

当前的多模态AI智能体（如个人助手、健康监控、机器人等）越来越依赖持久化长期记忆来支撑跨会话的个性化推理。其工作流程大致如下：

  • 用户与智能体进行多轮对话，对话中可能包含文本和图像。
  • 每一轮对话的内容（文本+图像）被编码为向量嵌入（embedding），存储到记忆库中。
  • 当新的查询到来时，系统通过语义相似度检索最相关的历史记忆条目，将其作为上下文提供给下游的多模态大语言模型（MLLM），由MLLM基于这些"记忆"生成回答。
    形式化地，一段对话可以表示为有序的轮次序列 $\mathcal{D} = \big((u_i, a_i, x_i)\big)_{i=1}^N$，其中 $u_i$ 是用户发言，$a_i$ 是智能体回复，$x_i \in \mathbb{R}^{H \times W \times 3}$ 是关联的图像（纯文本轮次 $x_i = \varnothing$）。

记忆编码与存储：每一轮被编码为稠密向量：

$\displaystyle e_i = \text{Encoder}(u_i, a_i, x_i) \in \mathbb{R}^d$

其中 Encoder 是一个多模态编码器（如CLIP视觉编码器+文本嵌入模型），将文本和图像投射到共享嵌入空间。存储后的记忆库为 $\mathcal{M} = \{(e_i, u_i, a_i, x_i)\}_{i=1}^N$。
检索与响应生成：给定新查询 $q$，系统检索最相关的 $k$ 条记忆：

$\displaystyle \mathcal{R}(q, \mathcal{M}, k) = \text{top-k}_i \; \text{sim}(\text{Encoder}_q(q), e_i)$

然后MLLM基于检索到的内容生成回答：

$\displaystyle r = \text{MLLM}\Big(q, \{(u_i, a_i, x_i)\}_{i \in \mathcal{R}(q, \mathcal{M}, k)}\Big)$

1.2 核心安全问题

论文指出了一个关键的结构性假设缺陷：现有记忆管线对视觉内容给予了无条件信任。具体来说：

  • 记忆系统没有内建机制来验证检索到的图像的语义完整性。
  • 检索是基于嵌入相似度而非像素空间内容进行的。
  • 因此，一张经过对抗扰动的图像可以在视觉上与原图几乎不可区分，但其嵌入向量却被推到了完全不同的语义区域。
  • 一旦这样的图像进入记忆库，智能体会以与真实记录相同的置信度检索它，并基于伪造的语义内容生成回答。
  • 这不是一次性的单轮失败，而是持久性的记忆腐蚀：未来每一个触发检索到被污染记录的查询都会继承同样的虚假基础。

2. 威胁模型

2.1 两种攻击目标

In-context Poisoning（上下文内投毒）：攻击者针对对话中已有的一个图像轮次 $(u_j, a_j, x_j)$，该轮次的文本已经建立了具体的上下文（用户描述了一个真实经历的事件）。攻击者将该轮次的图像替换为对抗扰动版本：

$\displaystyle \tilde{x}_j = x_j + \delta_j, \quad \|\delta_j\|_\infty \leq \varepsilon$

所有文本字段保持不变。被腐蚀的条目 $\tilde{e}_j = \text{Encoder}(u_j, a_j, \tilde{x}_j)$ 替代原始的 $e_j$。文本锚点不变，但视觉嵌入被推向目标概念 $c^\*$，在存储条目内部制造了不一致性。攻击成功的条件是：

$\displaystyle j \in \mathcal{R}(q_v, \tilde{\mathcal{M}}, k) \wedge \text{sim}(\text{Encoder}_q(r_{q_v}), \text{Encoder}_q(c^\*)) \geq \tau, \quad \forall q_v \in \mathcal{Q}_v$

效果是智能体错误回忆一个真实事件——它正确地相信事件发生过，但在错误的语义上下文中检索到它。
Out-of-context Injection（上下文外注入）：攻击者针对用户上传的一张新图像，该图像涉及之前未讨论过的话题。由于没有先前的对话建立上下文，记忆系统没有现有证据来验证这张图像。攻击者施加扰动 $\delta^+$，$\|\delta^+\|_\infty \leq \varepsilon$，产生 $\tilde{x}^+ = x^+ + \delta^+$。记忆模块存储：

$\displaystyle \tilde{e}^+ = \text{Encoder}(u^+, a^+, \tilde{x}^+)$

其中 $\tilde{e}^+$ 编码了与轮次内容无关的虚假概念 $c^\*$。这个概念保持休眠状态，直到受害者查询将其检索出来：

$\displaystyle \text{sim}(\text{Encoder}_q(q_v), \tilde{e}^+) \gg \text{sim}(\text{Encoder}_q(q_v), e^+), \quad \forall q_v \in \mathcal{Q}_v$

效果是智能体记住一个捏造的事件，被悄悄植入到一个合法的用户发起的轮次中。由于注入条目的文本在语义上是中性的，记忆系统没有信号将其标记为异常，使得这种模式比上下文内投毒更难检测。

2.2 攻击者能力与约束

  • 攻击者在 $\ell_\infty$ 预算下对用户分享的图像施加不可察觉的扰动
  • 严格黑盒：攻击者不知道目标MLLM、视觉编码器、记忆内容、检索编码器或响应日志
  • 对抗图像在代理模型集合（surrogate ensemble）上生成，然后迁移到目标系统

现实攻击入口包括：被入侵的图像CDN在分享图像中嵌入对抗噪声、恶意SDK在相机和智能体之间拦截图像、包含预扰动图像的网页被智能体原样存储等。

3. LUCID框架设计

LUCID分为三个阶段（见Figure 1）。

3.1 Stage 1：对抗目标设计

目标是从大型候选池中选择一个与原始内容语义矛盾的视觉概念作为攻击目标。
候选池构建：从ShareGPT4V-100K语料库中采样，过滤掉包含AI拒绝或免责声明的条目。对每个候选 $p$ 预计算三种嵌入：

  • CLIP ViT-B/32 图像嵌入 $\phi_p^{\text{img}} \in \mathbb{R}^{512}$
  • CLIP ViT-B/32 文本嵌入 $\phi_p^{\text{txt}} \in \mathbb{R}^{512}$（对其描述文本）
  • OpenAI text-embedding-3-small 嵌入 $\phi_p^{\text{oai}} \in \mathbb{R}^{1536}$

复合评分：对每个受害QA对 $(q, a_{\text{gt}})$，每个候选按三项复合分数评分：

$\displaystyle S(p; q, a_{\text{gt}}) = \alpha \, \Phi_R(p, q) + \beta \, \Phi_{\text{contra}}(p, q) - \gamma \, \Phi_C(p, a_{\text{gt}})$

其中 $\alpha=1.0$，$\beta=2.0$，$\gamma=0.5$。
三个分项的含义：
检索位移分数 $\Phi_R$：估计候选 $p$ 在检索时能多强地取代真实证据。使用CLIP ViT-B/32作为黑盒代理，对图像轮次计算文本-图像融合的检索相关性：

$\displaystyle \Phi_R(p, q) = \max_{r \in \mathcal{C}_{\text{img}}} \frac{1}{2}\Big(\text{sim}(\phi_r^{\text{txt}}, \phi_q^{\text{txt}}) + \text{sim}(\phi_p^{\text{img}}, \phi_q^{\text{txt}})\Big)$

槽位矛盾分数 $\Phi_{\text{contra}}$：奖励与正确答案语义矛盾的候选。通过本地LLM提取每个QA的结构化属性-值对及替代值，然后计算：

$\displaystyle \Phi_{\text{contra}}(p, q) = \max_{s \in \mathcal{A}(q)} \text{sim}(\phi_p^{\text{txt}}, \phi_s^{\text{txt}}) - \text{sim}(\phi_p^{\text{txt}}, \phi_{a_{\text{gt}}}^{\text{txt}})$

其中 $\mathcal{A}(q)$ 是替代槽位值集合。正的 $\Phi_{\text{contra}}$ 表示候选的描述更接近一个错误答案而非正确答案。
GT对齐惩罚 $\Phi_C$：惩罚与正确答案语义重叠的候选，使用双嵌入族增强鲁棒性：

$\displaystyle \Phi_C(p, a_{\text{gt}}) = \max(0, \text{sim}(\phi_p^{\text{txt}}, \phi_{a_{\text{gt}}}^{\text{txt}})) + \text{sim}(\phi_p^{\text{oai}}, \phi_{a_{\text{gt}}}^{\text{oai}})$

此外还有两个硬门控：词汇门控（描述文本必须包含至少一个替代值token，且不包含正确答案token）和主题门控（$\Phi_R$ 必须超过候选池分布的中位数）。最终得分最高的候选成为对抗目标 $(x^\*, c^\*)$。

3.2 Stage 2：对抗载荷构建

In-context Poisoning：标记对话中图像轮次 $j$ 的图像 $x_j$ 进行扰动，目标为 $x^\*$，所有文本字段 $(u_j, a_j)$ 保持不变。源-目标对 $(x_j, x^\*)$ 传递给Stage 3。结果是存储条目保留原始文本锚点，但视觉嵌入被推向 $c^\*$。
Out-of-context Injection：构建一个新的用户分享轮次 $t^+$，放在对话中不与任何现有图像轮次冲突的位置。用户消息使用固定的中性模板（如"这是我最近活动的一张照片，你能简要描述一下你看到的吗？"），源图像 $x^+ \sim \text{Uniform}(\mathcal{P} \setminus \{x^\*\})$ 随机抽取。目标描述 $c^\*$ 不出现在 $t^+$ 的任何文本字段中。源-目标对 $(x^+, x^\*)$ 传递给Stage 3。
两种模式的关键区别在于检测不对称性：投毒在存储条目内部制造了文本-视觉不一致（文本锚定真实事件，视觉嵌入指向别处），理论上可被一致性检查发现；而注入不产生这样的信号——用户文本是中性的，$c^\*$ 不出现在任何文本字段中，虚假概念完全编码在视觉嵌入中，对任何不主动解码存储图像的系统都是不可见的。

3.3 Stage 3：对抗扰动

给定源-目标对 $(x_s, x^\*)$，求解：

$\displaystyle \max_{\delta: \|\delta\|_\infty \leq \varepsilon} \mathcal{L}(x_s + \delta, x^\*, c^\*)$

$\displaystyle \mathcal{L}(\tilde{x}, x^\*, c^\*) = \mathcal{L}_{\text{OT}}(\tilde{x}, x^\*) + \lambda_{\text{txt}} \mathcal{L}_{\text{txt}}(\tilde{x}, c^\*)$

其中 $\tilde{x} = x_s + \delta$。
$\mathcal{L}_{\text{OT}}$ 是FOA-Attack目标函数，结合全局余弦对齐和最优传输（OT）聚类分配，跨代理编码器集合 $\mathcal{F} = \{\text{CLIP-ViT-B/16}, \text{CLIP-ViT-B/32}, \text{LAION-CLIP}\}$：

$\displaystyle \mathcal{L}_{\text{OT}}(\tilde{x}, x^\*) = \sum_m w_m \, \text{sim}(f_m(\tilde{x}), f_m(x^\*)) + \text{OT}(\{f_m(\tilde{x})\}_m, \{f_m(x^\*)\}_m)$

其中 $m$ 索引代理模型，权重 $\{w_m\}$ 在每步动态更新——给扰动进展停滞的模型更多梯度权重。OT项惩罚对抗样本和目标之间的聚类分配分布不匹配，鼓励局部特征结构的对齐。
$\mathcal{L}_{\text{txt}}$ 是论文对FOA-Attack的扩展，动机是部署的记忆后端不仅比较视觉嵌入，还会通过MLLM生成存储图像的文本描述，后续检索和QA操作的是这个描述。因此需要将对抗图像与目标描述在CLIP的联合文本-图像空间中对齐：

$\displaystyle \mathcal{L}_{\text{txt}}(\tilde{x}, c^\*) = \text{sim}(\text{CLIP}_{\text{img}}(\tilde{x}), \text{CLIP}_{\text{txt}}(c^\*))$

优化过程：使用投影I-FGSM进行 $T=1000$ 步迭代，步长 $\alpha=0.5/255$，$\ell_\infty$ 预算 $\varepsilon=16/255$：

$\displaystyle \delta^{(t+1)} = \Pi_\varepsilon\Big(\delta^{(t)} + \alpha \, \text{sign}(\nabla_\delta \mathcal{L}(\delta^{(t)}))\Big)$

最终对抗图像 $\tilde{x} = \text{clamp}(x_s + \delta^{(T)}, 0, 1)$ 替换Stage 2产生的对话中的源图像。

4. 实验设置

4.1 记忆后端

论文评估了五种架构各异的记忆后端：

  1. MuRAG：扁平多模态存储（线性列表），GME编码器，余弦top-k检索
  2. NGMemory：图结构存储，GME编码器，余弦检索+图遍历（深度优先，最大深度3）
  3. AUGUSTUS：概念标签图，GME编码器，CoPe（概念增强邻近度）搜索+图遍历
  4. UniversalRAG：模态路由RAG存储，GME编码器，LLM路由器分类查询后进行检索
  5. Mem0Memory：LLM提取的事实存储（Qdrant向量数据库），视觉信息先通过MLLM转化为文本描述再存储
    这五种后端在编码策略、检索机制、整合逻辑和存储格式上差异显著，代表了设计空间的广泛覆盖。

4.2 评估基准

使用Mem-Gallery基准，包含跨多个真实世界辅助领域的多会话对话。包含68个会话、1071个对话轮次、346个人工标注的QA对，覆盖AI/机器人、科技伦理、育儿、家居维修、房地产等五个主题。

4.3 实验条件

  • Clean：未修改的基线
  • Oracle：使用真实的语义目标图像和描述（攻击效果的上界）
  • Adversarial：完整的LUCID黑盒对抗攻击

4.4 评估指标

  • ASR (VS)（投毒）：智能体回答与攻击者选择的目标视觉相似的探测比例
  • ASR（注入）：智能体回答包含注入的虚假声明的探测比例
  • Cond ASR：限制在检索成功的探测上的ASR，隔离MLLM对注入内容的易感性
  • Ret. Rate：对抗条目在top-k检索结果中的比例
  • Corr Loss：相对于clean基线的正确答案下降
  • 通用QA质量指标：F1、Hit Rate@K、Recall@K、Precision@K、LLM Judge

5. 实验结果

5.1 投毒攻击（Table 2）

跨所有五个记忆后端，对抗条件下平均ASR-VS达到61.6%，接近Oracle的67.9%。关键发现：

  • 对抗图像的检索率紧跟Oracle（如UniversalRAG：89.2% vs 92.5%）
  • 答案正确性下降适中（LLM Judge下降0.12-0.20），因为Mem-Gallery混合了视觉依赖和文本依赖的问题
  • 对于文本密集的轮次，MLLM可以部分从对话文本上下文中恢复答案，这验证了攻击的视觉特异性
  • NGMemory尽管对抗检索率最低（41.9%），但LLM Judge下降最大（0.778→0.571），确认了即使只腐蚀少量记忆也能在视觉关键轮次上降低响应质量

5.2 注入攻击（Table 3）

注入攻击在所有五个后端上有效迁移，平均ASR达到58.4%：

  • NGMemory最易受攻击（adv ASR 81.3%）
  • MuRAG（75.0%）和UniversalRAG（56.3%）次之
  • AUGUSTUS和Mem0Memory表现出适度抵抗（43.8%和37.5%）
  • 一个值得注意的现象：AUGUSTUS的对抗检索率低于Oracle（62.5% vs 75.0%），但条件ASR反而提高（75.0% vs 56.3%）——当注入的记忆被检索到时，其对抗扰动形式比原始目标图像对MLLM更具说服力
  • 注入攻击对通用QA质量的影响极小，因为攻击模拟的是与现有记忆无关的新内容

5.3 跨MLLM迁移（Table 4）

在UniversalRAG后端上测试五种MLLM：

  • GPT-4.1最易受攻击（adv ASR 81.3%），超过Oracle（68.8%）
  • Gemini-2.5-flash（62.5%）也超过Oracle（43.8%）
  • GPT-4o和Claude-Haiku-4.5各56.3%
  • GPT-4o-mini（48.8%）
  • 检索率一致很高（90.0-93.8%）
  • GPT-4.1和Gemini展现出"强于Oracle"效应：扰动图像在生成阶段比未扰动的目标图像更容易让MLLM采纳注入内容
  • GPT-4o-mini展现出相反模式：最高检索率（90.0%）但最低ASR（48.8%），表明生成层面的抵抗力
  • 这揭示了检索-行动差距：检索鲁棒性和生成阶段鲁棒性是可分离的安全维度

5.4 消融研究

检索编码器敏感性（Figure 3）：在CLIP-B/32、CLIP-336、SigLIP和GME四种检索编码器下评估。关键发现是CLIP优化的对抗图像不局限于CLIP嵌入空间——它们能迁移到GME（一种完全不同训练目标和数据的编码器），跨所有后端ASR降低极小。这表明漏洞根植于共享的语义对齐属性，而非编码器特定的伪影，削弱了基于编码器多样化的防御策略。
对话主题泛化（Figure 4）：检索率在所有主题上都很高（85%-94%），注入不降低通用QA质量（$|\Delta F1| \leq 0.03$），使攻击难以通过质量监控检测。ASR与主题相关：AI/Robotics最易受攻击（46%），Technology/Ethics最鲁棒（40%）。
注入图像数量（Table 14）：$N=1$ 已经构成有竞争力的攻击（ASR 36%-45%）。增加 $N$ 不单调提高ASR，效果高度依赖架构。
注入时间距离（Table 15）：NGMemory对时间距离不敏感（图结构显式链接所有会话），而UniversalRAG随时间距离增加反而更易受攻击（ASR从45%增至75%），因为后续轮次引入的多样内容减少了来自近期干净条目的竞争。

5.5 防御评估（Table 5）

评估了五种防御，跨三个干预点：

  1. 图像预处理（高斯模糊、JPEG压缩）：最有效。高斯模糊（r=4）将平均ASR从35.9%降至15.6%，JPEG压缩（q=25）降至18.8%，对F1影响可忽略。原理是在MLLM生成描述前降解高频扰动。
  2. 写入端过滤： - LLM-as-judge：完全无效（ASR不变），因为对抗生成的描述流畅且合理，没有ground-truth图像内容，judge无法区分植入的谎言和真实描述 - 语义漂移过滤（TF-IDF相似度 $\tau=0.20$）：阻止了17/20个注入描述，但依赖架构——中和了UniversalRAG（检索率从93.8%降至18.8%），但对图结构后端无效
  3. 检索时过滤（异常评分 $\tau=0.10$）：完全失败（ASR不变），因为探测查询与注入内容在设计上语义对齐，同时造成F1损失-0.09

结论：有效防御必须在描述生成前的图像层面操作；基于文本的过滤（无论在写入还是检索时）对视觉基础的攻击不够。但测试的图像预处理方法可能无法抵御更隐蔽的对抗攻击。

6. 关键贡献与意义

  1. 揭示了结构性漏洞：多模态记忆管线对视觉内容的无条件信任是一个可被系统性利用的安全缺陷
  2. 严格的威胁模型：LUCID的攻击者能力严格弱于所有先前工作——仅控制图像像素，不接触文本、模型权重或记忆内部
  3. 两种互补的攻击模式：投毒（篡改真实记忆）和注入（植入虚假记忆），分别对应不同的认知角色和检测难度
  4. 广泛的评估：跨五种架构各异的记忆后端、五种主流MLLM、多种对话主题
  5. 防御启示： - 检索鲁棒性和生成阶段鲁棒性是可分离的安全维度 - 编码器多样化不足以防御（对抗扰动跨编码器族迁移） - 文本层面的过滤对视觉攻击无效 - 需要跨模态一致性检查和对抗鲁棒性评估

原文摘要

Multimodal AI agents increasingly rely on persistent long-term memory to ground generation in past visual and textual episodes. We show that unconditional trust in visual data creates a critical vulnerability. We propose Lucid, a black-box adversarial framework that compromises multimodal memory pipelines under a strictly image-bounded threat model, requiring no access to the target MLLM, target retrieval encoder, or the text channel. Lucid crafts imperceptible perturbations to enable two distinct failure modes based on the availability of historical context: (1) Memory poisoning, an in-context attack where the adversarial image replaces a benign one whose content is reinforced by prior textual context, reliably corrupting visual recall and steering the agent toward attacker-chosen narratives; (2) Memory injection, an out-of-context attack where the adversarial image replaces a benign one in a conversation turn devoid of prior textual grounding, causing the agent to generate attacker-influenced responses with no corrective signal from memory. We evaluate Lucid across various conversation domains and five black-box memory architectures, including graph-structured, LLM-summarized, and commercially deployed systems. Lucid achieves 61.6% ASR on poisoning and 58.4% ASR on injection, exposing a structural vulnerability in multimodal memory pipelines.
