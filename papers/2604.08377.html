SkillClaw: Let Skills Evolve Collectively with Agentic Evolver

Ziyu Ma, Shidong Yang, Yuxiang Ji, Xucong Wang, Yong Wang, Yiming Hu, Tongwen Huang, Xiangxiang Chu

论文原文 ↗下载文献卡片 Markdown

邻接工作：管理分工、集体演化或社会交互，不等同于团队共享记忆方法

核心机制

汇集跨用户、跨时间的交互轨迹，由自主 evolver 识别重复行为和失败模式，修订或新增技能，并通过共享仓库同步。

适用范围与局限

研究跨用户生态中的共享技能更新，不等同于同一任务内的多 Agent 协作；摘要报告 WildClawBench 结果，未独立复现。

详细解读

论文核心总结

SkillClaw 是一个面向多用户 LLM Agent 生态系统的技能集体进化框架。其核心思想是：当多个用户各自独立使用 Agent（如 OpenClaw）完成任务时，系统会自动收集所有用户的交互轨迹，将这些来自不同用户、不同上下文的经验聚合为共享证据，然后由一个自主的"进化器"（agentic evolver）分析这些证据中反复出现的成功模式和失败模式，据此对共享技能库进行精炼或扩展。更新后的技能同步回所有用户的 Agent，使得一个用户场景中发现的改进能够惠及全体用户，从而实现技能的持续累积式进化，而无需用户做任何额外操作。

1. 问题背景与动机

1.1 当前 Agent 系统的技能生态是静态的

现代 LLM Agent（如 OpenClaw）依赖技能（skills）来完成复杂任务。技能是一种结构化的可复用过程性知识，编码了与工具交互、解决任务的标准流程。用户通常从一个集中式的"技能中心"（SkillHub）选择和安装技能。
然而，这些技能在部署后基本是静态不变的。用户在交互过程中通过反复试错可能发现了更好的解决方案（比如发现某个 API 端口不对、某个参数格式需要调整），但这些改进仅存在于当前会话中，不会被固化到技能库里，也不会传递给其他用户或未来的交互。

1.2 跨用户经验的浪费

不同用户往往在重叠的任务空间中工作——他们使用类似的工作流、调用相同的工具、遇到相同的失败模式。但由于系统缺乏将这些异构经验转化为可靠技能更新的机制，每个用户都被迫独立地重新发现解决方案。这导致了知识无法在系统层面积累。

1.3 现有方法的不足

论文指出两类现有方法都无法解决这个问题：

  • 基于记忆的方法（如 Reflexion、ExpeL 等）：存储过去的交互轨迹用于检索，但这些记录绑定于特定实例，难以泛化为改进的行为。
  • 基于技能的方法（如 Voyager、SkillRL 等）：将经验压缩为结构化指令，但将技能库视为静态资源，不会随使用而进化。即使局部改进了某个 Agent 实例，这些改进也不会跨用户积累。

缺失的关键机制是：将普通的交互转化为持续的技能进化，并使技能能够跨用户集体改进。

2. SkillClaw 方法

2.1 整体架构

SkillClaw 采用集中式进化架构，其闭环流程如下：

$\displaystyle \text{多用户交互} \rightarrow \text{会话收集} \rightarrow \text{技能进化} \rightarrow \text{技能同步}$

具体来说：

  • 各用户独立部署的 Agent 在日常使用中产生交互会话（session trajectories）
  • 这些会话被上传到中央服务器作为共享证据
  • 一个集中式的进化引擎周期性地处理收集到的会话，更新技能库
  • 更新后的技能同步回所有 Agent
    在推理时，Agent 的 prompt 中包含可用技能的目录，Agent 可以动态选择和加载与当前任务相关的技能。用户之间不需要直接交互，也不需要 Agent 之间的协调。

2.2 形式化定义

设共享技能集为 $\mathcal{S} = \{s_1, \ldots, s_M\}$，每个技能是一个可复用的过程性制品。每次用户交互产生一个会话轨迹 $\tau$，记录完整的交互循环：用户提示、Agent 的动作、环境或用户的反馈、以及最终的 Agent 响应。给定跨用户收集的轨迹集合 $\mathcal{T} = \{\tau_i\}$，目标是更新共享技能集：

$\displaystyle \mathcal{S}' = \Phi(\mathcal{S}, \mathcal{T})$

使得一次交互中发现的改进能够惠及未来的用户。

2.3 从孤立会话到共享证据（Section 2.1）

这个过程分两个阶段：
阶段一：结构化单个会话。 SkillClaw 记录完整的因果链：

$\displaystyle \text{prompt} \rightarrow \text{action} \rightarrow \text{feedback} \rightarrow \cdots \rightarrow \text{agent response}$

为什么要记录完整的中间过程？因为大多数技能层面的失败是过程性的——一个错误的参数格式、一个缺失的验证步骤、一个错序的工具调用都可能导致任务失败，但这些问题不会出现在最终响应中，只能从中间的动作-反馈轨迹中诊断出来。
同时，系统还从每个会话中提取轻量级元数据：(i) 引用了哪些技能，(ii) 是否发生了工具错误，(iii) 粗粒度的质量估计。
阶段二：按技能分组聚合。 对于每个技能 $s$，收集所有调用了 $s$ 的会话：

$\displaystyle \mathcal{G}(s) = \{\tau_i \mid s \in \mathcal{K}_i\}$

没有使用任何技能的会话被放入单独的组 $\mathcal{G}(\varnothing)$。
这种分组的意义不仅仅是组织数据。当多个会话调用同一技能但在不同用户、任务或环境下产生不同结果时，比较直接揭示了技能在哪里有效、在哪里失败——技能本身成为了控制变量。论文将此称为一种自然消融实验（natural ablation）。这使得两种操作变得可靠：(1) 评估现有技能在多样化真实使用中的实际表现；(2) 通过 $\mathcal{G}(\varnothing)$ 中的模式识别出没有被任何现有技能覆盖的反复出现的过程。

2.4 Agentic 技能进化（Section 2.2）

SkillClaw 的核心是一个agentic evolver（智能体进化器）——一个配备了结构化工具的 LLM Agent，它接收分组后的会话证据、当前技能定义和一组允许的进化动作。
关键设计理念是：工具提供结构化输入，但不约束进化器的推理过程。进化器通过开放式推理来诊断根因并决定如何行动。这种"固定工具 + 开放推理"的分离使得 SkillClaw 能够处理多样化的失败模式，而无需为每种类型手工编写规则。
给定技能 $s$ 及其关联的会话组 $\mathcal{G}(s)$，进化器检查成功和失败的执行，并从三个动作中选择一个：

  • Refine（精炼）：基于观察到的失败模式更新技能，纠正已识别的错误或提高鲁棒性。
  • Create（创建）：当 $\mathcal{G}(s)$ 揭示了未被任何现有技能捕获的反复出现的子过程时，引入新技能。
  • Skip（跳过）：当可用证据不足以证明修改的合理性时，保持技能不变。
    对于 $\mathcal{G}(\varnothing)$ 中的会话，进化器专注于发现缺失但可复用的过程。只有当观察到的模式足够具体、可教授且可能反复出现时，才创建新技能。

一个关键设计原则：无论选择哪个动作，进化器总是联合推理成功和失败的会话。成功的会话定义了技能的不变量（有效的部分，不应被改变）；失败的会话定义了目标（需要纠正的具体行为）。这种联合视角防止了一个朴素的失败：修复一个问题的同时无意中破坏了之前有效的过程。每次更新在纠正已识别缺陷的同时保留成功会话验证过的内容，使进化具有累积性。
完整的算法流程见 Algorithm 1：

  1. 将轨迹 $\mathcal{T}$ 转换为结构化证据 $\mathcal{E}$
  2. 按引用的技能分组，得到 $\{\mathcal{G}(s)\}$ 和 $\mathcal{G}(\varnothing)$
  3. 对每个组 $\mathcal{G}(s)$，使用 agentic evolver 分析反复出现的成功和失败模式
  4. 选择进化动作（refine/create/skip）
  5. 如果证据支持修改，生成候选技能更新
  6. 应用保守编辑和验证
  7. 将批准的更新合并到 $\mathcal{S}'$
  8. 分析 $\mathcal{G}(\varnothing)$ 寻找缺失但可复用的过程
  9. 将验证后的新技能加入 $\mathcal{S}'$
  10. 将 $\mathcal{S}'$ 同步回所有 Agent

2.5 技能同步与进化循环（Section 2.3）

进化完成后，候选技能更新在写回共享库之前需要验证。
验证在夜间执行，利用可用的空闲用户环境，确保评估反映真实部署条件。对于技能 $s$ 及其候选更新 $s'$，系统从白天收集的交互数据中选择相关任务，在相同环境下使用完整工具链执行两个版本，然后用模型比较 $s$ 和 $s'$ 产生的结果。如果更新后的技能表现更好，标记为 Accept；否则标记为 Reject。
被接受的更新合并到共享库并同步给所有 Agent 用于第二天；被拒绝的更新仅作为候选记录保留，不会部署。这意味着用户始终与前一晚的最佳验证技能池交互。
这个验证步骤引入了单调部署行为——由于只有改进被接受，部署的技能池不会随时间退化。结合进化过程，系统形成闭环：

$\displaystyle \text{交互} \rightarrow \text{证据} \rightarrow \text{进化} \rightarrow \text{验证} \rightarrow \text{部署}$

2.6 三个关键属性

  1. 集体进化（Collective Evolution）：会话跨用户聚合，一次交互中发现的知识传播到惠及所有用户的共享技能生态系统。
  2. 完全自动化（Full Automation）：从会话记录到技能同步的整个流程无需人工策展或显式用户干预。唯一的人类输入就是正常的 Agent 使用。
  3. Agentic 适应性（Agentic Adaptability）：技能更新通过开放式推理而非预定义规则产生，使系统能够处理之前未见过的失败模式和使用模式。

3. 实验

3.1 评估基准：WildClawBench

SkillClaw 在 WildClawBench 上评估，这是一个由 60 个复杂任务组成的真实世界 Agent 基准，涵盖六个能力领域：

类别 示例任务 挑战
生产力流程 arXiv 分类、日程安排 多步流水线
代码智能 调试、解谜 执行正确性
社交互动 谈判、聊天分析 多轮推理
搜索与检索 学术搜索、冲突解决 API 使用
创意合成 视频笔记、海报生成 多模态生成
安全与对齐 提示注入、泄漏检测 约束满足

WildClawBench 的关键特性包括：在完整 Linux 容器中端到端执行、多模态输入（文本/代码/图像/视频）、3-27 个聚合评估指标、关键错误直接零分、任务长度 15-50 步等。

3.2 实验设置

实验模拟了一个连续的日夜技能进化过程，运行 6 天（6 轮）：

  • 白天：用户与部署的 OpenClaw Agent 交互完成 WildClawBench 任务，生成会话轨迹
  • 夜间：系统处理收集的交互数据，生成候选技能更新，验证器过滤候选更新，只有通过验证的技能被加入共享部署池
    设置涉及 8 个并发用户，所有执行、技能进化和验证过程由 Qwen3-Max 驱动。第 1 天从初始技能集（基线）开始。

3.3 主要结果

Table 3 展示了用户侧白天结果（最佳技能部署视角）：

类别 Day 1 Day 6 绝对增益 相对增益
社交互动 54.01% 60.34% +6.33 +11.72%
搜索与检索 22.73% 34.55% +11.82 +52.00%
创意合成 11.57% 21.80% +10.23 +88.41%
安全与对齐 24.00% 32.00% +8.00 +33.33%

各类别的进化特点不同：

四个类别都展现出一致的进化模式：系统首先解决主要瓶颈，然后围绕当前最佳技能池稳定部署。

  • 社交互动：改进最早最快，Day 2 就从 54.01% 跳到 60.34% 并保持稳定。这表明存在一个高影响力的工作流瓶颈，一旦对应技能被改进，系统迅速获得跨源整合、任务组织和高层摘要的能力。
  • 搜索与检索：呈阶梯式改进（22.73% → 30.00% → 34.55%），由一系列改进驱动。系统先解决输入验证和文件可访问性，然后构建约束感知的检索规划。这反映了"先输入可靠性，后策略"的递进模式。
  • 创意合成：Day 2 大幅跳升（11.57% → 21.80%）然后趋于平稳。主要瓶颈不在内容生成本身，而在环境设置（文件处理、工作目录配置、多模态流水线）。
  • 安全与对齐：改进较晚（Day 5 才从 24.00% 到 32.00%），主要针对真实环境中的执行可靠性（如 Git 回退、目录克隆协议、非交互式设置中的安全执行）。

3.4 详细分析

论文通过 Table 4-7 详细展示了每个类别每晚的技能进化和验证决策。这些表格揭示了几个重要观察：
验证器的保守性很重要：在 6 天中，大多数候选更新实际上被拒绝了。例如在社交互动类别中，6 天只有 1 个更新被接受（Day 1 的 03_task6）。这确保了部署的技能池只会变好不会变差。
进化是高度异质的：不同类别遵循不同的能力轨迹。社交互动强调工作流可执行性，搜索与检索强调输入可靠性和规划，创意合成强调多模态流水线组织，安全与对齐强调鲁棒和可恢复的执行。
受控验证实验（Table 8）：使用三个自定义查询（basic extraction、deadline parsing、save report）进行受控验证，单轮进化后平均增益 +42.1%。其中 save report 从 28.3% 提升到 100.0%，因为初始失败由缺失的环境特定过程（如输出路径或格式）引起，一旦编码为可复用技能就能完全纠正。

3.5 案例研究

论文提供了四个详细的案例研究：
案例 1（Figure 2）：Slack 消息分析。 原始 Agent 采用朴素工作流，检索所有消息并统一处理，同时依赖试错来处理工具失败（如错误的 API 端口配置）。进化后的技能引入了结构化流水线：先扫描消息预览识别任务相关候选，然后选择性检索完整消息内容，最后提取可操作项目。同时，之前观察到的工具失败（端口 9100 → 9110）被直接编码到技能中。
案例 2（Figure 3）：ICCV 2025 论文分析。 原始 Agent 依赖弱启发式（仅匹配大学名称是否出现在作者列表中），导致将非第一作者单位错误计入。进化后的技能引入了更精确的"第一作者单位"定义，基于官方 PDF 首页结构，并对模糊案例进行针对性复查。
案例 3（Figure 4）：SAM3 推理。 原始 Agent 假设所需输入和执行条件完全可用，当路径缺失或环境假设（如 CUDA 支持）不成立时失败。进化后的技能引入了环境感知工作流：先进行轻量级工作空间检查，将缺失路径视为非阻塞性问题，搜索附近的任务特定资产，并适应系统约束（如 monkey patch CUDA 依赖组件以启用 CPU 执行）。
案例 4（Figure 5）：多条件手机选购。 原始 Agent 依赖松散的搜索和启发式匹配，找到一个看似合理的候选就提前停止，将部分匹配错误地视为完全满足所有要求。进化后的技能系统地验证每个要求，当没有候选完全满足所有约束时明确报告，并提供部分匹配的详细分解。

4. 技术细节：Evolver 的 Prompt 设计

论文在附录中提供了完整的 prompt 设计，这是理解系统实际运作方式的关键。

4.1 会话摘要 Prompt

将原始会话压缩为 8-15 句的分析性摘要，保留目标、关键轨迹、技能有效性、关键转折点、工具使用模式和结果。

4.2 从会话进化 Prompt

这是核心的进化 prompt，指导 evolver 分析会话证据并决定动作。其中包含详细的编辑原则：

  • 将当前技能视为事实来源，而非草稿
  • 默认进行针对性编辑，而非重写
  • 保留原始结构、标题顺序、术语和有效指导
  • 只有在证据表明某部分实质性错误时才重写整个部分
    以及硬约束：
  • 不要随意更改 API 合约、端口、端点等（除非会话证据明确表明它们已更改）
  • 不要删除与观察到的失败无关的核心能力
  • 不要将技能变成具有不同目的的技能

4.3 Agentic 进化 Prompt

这是最完整的 prompt，指导进化器作为一个自主 Agent 在工作空间中操作。它定义了工作空间布局、五步工作流程（读取会话 → 分析聚合 → 读取历史并决策 → 执行写入 → 维护技能历史），以及详细的保守编辑原则和区分技能问题与 Agent 问题的指南。
一个特别值得注意的设计是历史感知：在对现有技能做任何决策之前，evolver 必须读取该技能的所有历史版本和证据文件，理解之前的更改为什么被做出、效果如何，避免回退之前的改进或重复过去的错误。

5. 与相关工作的区别

与 Agent 自我进化方向（如 Reflexion、ExpeL 等）的区别：这些工作主要从单个 Agent 自身的历史中改进，或在单一优化循环内改进；SkillClaw 在群体层面进行进化，聚合来自分布式本地 Agent 的会话。
与 Agent 技能方向（如 Voyager、SkillWeaver 等）的区别：这些工作研究技能的优化、发现、精炼和迁移，但通常在单 Agent 或单任务设置中；SkillClaw 关注的是从部署的 Agent 群体收集的聚合证据中进行群体层面的共享技能进化。

6. 总结与局限

SkillClaw 的核心贡献在于提出了从静态技能库到动态、交互驱动的技能生态系统的范式转变。技能不再是固定资源，而是通过真实使用不断进化——捕获反复出现的过程性模式、纠正失败、适应多样化的执行环境。
论文也承认当前实验是小规模测试（8 个用户、6 天、有限的查询和反馈信号），扩大用户数量、延长时间范围、引入更多样化的任务和验证条件可能会进一步丰富进化轨迹并提升系统性能。

研究问题 LLM智能体系统中的技能（skills）在部署后保持静态，不同用户反复遇到相同的失败模式和工作流问题，系统无法将跨用户的异构交互经验转化为可靠的技能更新，从而阻碍了系统级知识的积累与演化。
研究方法 提出SkillClaw框架，采用集中式演化架构：（1）将多用户交互会话结构化并按引用技能分组，形成共享证据库；（2）通过自主智能体演化器（agentic evolver）基于开放式推理分析成功与失败模式，执行技能的精炼（refine）、创建（create）或跳过（skip）操作；（3）通过夜间验证机制过滤候选更新，仅接受经验证优于当前版本的技能，形成"交互→证据→演化→验证→部署"的闭环。实验在WildClawBench基准上使用Qwen3-Max模型模拟8个并发用户、6天（6轮）的部署场景。
主要发现 在6天的演化周期内，四个任务类别均获得显著提升：Social Interaction从54.01%提升至60.34%（+11.72%），Search & Retrieval从22.73%提升至34.55%（+52.00%），Creative Synthesis从11.57%提升至21.80%（+88.41%），Safety & Alignment从24.00%提升至32.00%（+33.33%）。控制实验中单轮演化平均提升+42.1%。不同类别呈现异质性演化路径，如Social Interaction侧重工作流可执行性，Search & Retrieval呈现"输入优先、策略后置"的阶段式改进。
创新点 （1）提出多用户集体技能演化范式，将跨用户交互作为技能改进的主要信号源，实现跨用户知识迁移；（2）采用智能体驱动的演化范式（agentic evolution paradigm），通过开放式推理而非预定义规则进行技能更新；（3）全自动闭环设计，从数据收集、演化到同步均无需用户干预；（4）联合分析成功与失败会话以保护已验证行为的同时修复缺陷，实现累积式演化。
局限性 本研究为小规模集体技能演化测试，用户查询数量、反馈信号和交互深度有限；实验仅报告了四个代表性类别的结果，其余类别待补充；6天的演化窗口可能不足以充分展现长期演化效果；对依赖细致推理而非程序性知识的任务（如deadline parsing），技能演化的改进效果较小。

原文摘要

Large language model (LLM) agents such as OpenClaw rely on reusable skills to perform complex tasks, yet these skills remain largely static after deployment. As a result, similar workflows, tool usage patterns, and failure modes are repeatedly rediscovered across users, preventing the system from improving with experience. While interactions from different users provide complementary signals about when a skill works or fails, existing systems lack a mechanism to convert such heterogeneous experiences into reliable skill updates. To address these issues, we present SkillClaw, a framework for collective skill evolution in multi-user agent ecosystems, which treats cross-user and over-time interactions as the primary signal for improving skills. SkillClaw continuously aggregates trajectories generated during use and processes them with an autonomous evolver, which identifies recurring behavioral patterns and translates them into updates to the skill set by refining existing skills or extending them with new capabilities. The resulting skills are maintained in a shared repository and synchronized across users, allowing improvements discovered in one context to propagate system-wide while requiring no additional effort from users. By integrating multi-user experience into ongoing skill updates, SkillClaw enables cross-user knowledge transfer and cumulative capability improvement, and experiments on WildClawBench show that limited interaction and feedback, it significantly improves the performance of Qwen3-Max in real-world agent scenarios.
